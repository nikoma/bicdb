# BicDB 1.0.17-beta

Release date: 2026-08-03

## Quorum-certified cluster backup cuts

- Adds an expiring `ClusterBackupPlan` issued only by the current committed
  metadata leader against one stable topology generation and exact range
  epochs. Active relocation or mismatched metadata membership fails closed.
- Adds bounded, checksummed `ClusterNodeBackupArtifact` records that bind a
  node archive and its manifest to topology, schema, metadata commit index,
  and fully resolved range-log progress.
- Adds `ClusterBackupCertificate`, requiring a current leader-inclusive voter
  quorum at one identical resolved index for every range. Missing, duplicate,
  stale, unresolved, or divergent observations cannot produce a certificate.
- Canonicalizes artifact and range ordering so certificate validation can
  independently reproduce every selected barrier.
- Atomically persists plans, node artifacts, and certificates, rejects checksum
  damage, and caps control-file, node, range, and observation memory inputs
  explicitly. Certificate hashing streams into SHA-256 instead of allocating a
  second serialized certificate image.

The new module certifies a host-orchestrated range fence; it does not yet
coordinate distributed write fencing or archive transfer itself. Artifact
identity relies on BicDB's authenticated cluster transport. See
`docs/cluster-backup-certificates.md` for the protocol and trust boundary.
