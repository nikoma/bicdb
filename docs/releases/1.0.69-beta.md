# BicDB 1.0.69-beta

This release makes server-paged free-list mutation and reuse fail closed.

## Storage integrity

- Direct free rejects the superblock, the active published root, out-of-range
  page IDs, and pages already marked free before changing page bytes or
  metadata.
- Ordinary allocation rejects reserved `Superblock` and `Free` page types.
- Reuse validates the constant-size free-list metadata envelope, head type,
  successor bounds, advertised count, and immediate two-page cycles before
  consuming a page.
- Free-list structural failures have a dedicated corruption classification
  rather than being treated as an allocation miss.

## Bounded vacuum publication

- Bulk free-page adoption is capped at 65,536 pages, matching the maximum
  bounded vacuum step.
- The complete new segment, its exact declared length, page types, bounds, and
  tail binding to the prior list are validated before the superblock is
  published.
- Validation is proportional to the newly adopted bounded segment. It does not
  scan or materialize the existing free list.
- Invalid segments leave the old list, counters, file geometry, and allocation
  counters unchanged.

## Verification

Regression tests cover duplicate free across restart, out-of-range and
protected targets, reserved allocation types, pre-existing two-page cycles,
exact bulk-segment validation, normal reuse, vacuum reclamation, and trailing
page truncation.
