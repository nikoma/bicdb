# BicDB 1.0.317-beta

This release completes the callable Phase-2 cryptographic-cell boundary for the
industry-agnostic BicDB Cell runtime. Regulated-data admission remains closed;
this release is security infrastructure, not a compliance claim.

## Attested one-cell key authority

- Phase-2 manifests require a `kms+attested://` authority and refuse the
  development file-key provider.
- The runtime consumes one short-lived signed deterministic-CBOR key lease from
  an inherited Linux pipe. Regular files, terminals, and standard descriptors
  are rejected.
- Leases bind the attestation nonce, cell, manifest/generation, volume,
  lineage, executable, guest image, encryption/security profiles, KEK, key
  epoch, key fingerprint, and external rollback transition.
- Every scope field has a substitution test. Lease streams are one-shot and
  raw key material is zeroized on drop.
- The external rollback chain now names the exact durable predecessor and must
  advance by exactly one; missing or restored older witnesses fail against a
  correctly stateful external authority.
- New volumes accept only a signed generation-1 lineage root. Later manifest
  activations must be the exact linked successor; generation gaps and unsafe
  state/witness filesystem objects fail before key or database access.

## Purpose- and object-bound encryption

- Bound stores derive an independent HKDF-SHA-256 purpose key and then a
  normalized path-specific object key from the cell root.
- Cell identity, profile, key epoch, purpose, final object path, and format
  context enter AEAD authentication.
- Separate purposes cover records, WAL, synchronization/replication, temporary
  spills, blobs, indexes, search structures, audit streams, identity secrets,
  and backup authority.
- Collection/index/policy catalogs, vector indexes, graph projections,
  semantic-index job identities, and model/index catalogs are strict encrypted
  frames in cell-bound databases.
- SQL external-sort runs use an opaque database cipher; large-value chunks
  stream through cell-bound blob encryption and bind to their final path.
- Metadata now rejects empty files, symbolic links, hard-link substitution, and
  identity changes while opening instead of treating unsafe state as a new
  unencrypted database.
- Cell startup performs a bounded no-follow walk of the existing database tree
  before consuming its key lease, rejecting nested symbolic links, multiply
  linked files, and special filesystem objects.
- The unencrypted server-paged engine remains refused before metadata creation.

## Crash-safe key rotation

- `bicdb cell rotate-key` and `bicdb-cell rotate-key` accept an exact signed
  manifest transition plus independent retiring/next attested leases.
- Rotation authenticates every encrypted frame/blob/identity secret under the
  retiring key and builds a complete sibling tree under the next purpose/path
  hierarchy.
- Durable `prepared`, `source_retired`, and `activated` checkpoints make both
  namespace boundaries deterministically resumable.
- No mixed-key tree is published. The old ciphertext tree is retained until an
  external recovery/KMS authority approves key retirement.
- Rotation refuses symlinks, multiply linked objects, stale transient objects,
  unknown attachment formats, plaintext frames/chunks, binding changes, and
  non-monotonic key epochs.

## Validation

- Ciphertext-only whole-tree tests include records, audit/sync/WAL, attachments,
  collection and policy metadata, vector/search structures, graphs, and queued
  semantic-index identities.
- Negative tests cover wrong cell/profile/epoch/path/purpose/key, signature,
  lease lifetime/nonce/scope, rollback predecessor, metadata substitution,
  tamper, truncation, replay, one-shot consumption, and development providers.
- Rotation tests stop after each durable boundary, resume the same operation,
  reopen active and retired trees with their respective keys, and verify
  records, large attachments, vector search, and graph projections.
- Existing unbound vector, graph, semantic-index, encryption, large-value, SQL
  spill, application-host, and CLI behavior remains covered.

## Admission remains closed

`clinical_phi_admitted` remains false. This release does not claim a production
KMS/HSM or attestation deployment, data-commit-level rollback roots, attested
microVM isolation, cell-scoped backup/restore or HA, device replicas,
cross-cell grants, fleet supply-chain governance, independent cryptographic
review, or regulated-workload certification.

See [`cell-runtime-phase2.md`](../cell-runtime-phase2.md) for the exact operator
and security contract.
