# BicDB 1.0.332-beta

This release makes compiler-signed Carrier resource policies native to the
embedded SQL engine and keeps typed resource access aligned with PostgreSQL 18
row-level-security behavior.

## Native resource row security

- Install the compiler-signed `SELECT USING`, `INSERT WITH CHECK`, `UPDATE
  USING`, `UPDATE WITH CHECK`, and `DELETE USING` expressions as forced native
  row-level-security policies.
- Preserve unrelated operator policies and restore the exact prior
  enabled/forced RLS state during package removal, failed activation, and
  receipt rollback.
- Resolve bounded correlated `exists` expressions for typed reads and writes,
  including the referenced resource's own read policy and encrypted fields.
- Carry trusted email and display-name claims into protected session settings,
  while continuing to reject application attempts to mutate trusted settings.
- Reject relation bindings that shadow `auth` or subject fields and reject
  structured policy literals outside the signed scalar contract.

## PostgreSQL compatibility

- Route qualified projections such as `SELECT p.id FROM patients AS p` through
  the alias-aware evaluator. They no longer resolve as metadata paths and
  return `NULL`.
- Enforce cross-tenant candidate checks consistently for inserts, updates, and
  deletes, including declared SQL executed through the application host.
