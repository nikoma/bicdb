# 1.0.538: INSERT defaults, rules, column privileges, binary COPY, partition keys and indexes, predefined roles

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/b2.cases`, `b3.cases`, `b4.cases`,
`h.cases` and `h2.cases`.

## Added

- **Rules**: `CREATE RULE ... DO ALSO` (the default) and `DO INSTEAD` with one
  or more actions or `NOTHING`, on INSERT, UPDATE and DELETE, for tables and
  views. `NEW` and `OLD` are bound per affected row; `NOTIFY` actions are
  delivered at commit; rule recursion stops with 42P17. Conditional rules and
  `UPDATE ... FROM` / `DELETE ... USING` on a relation with rules stay 0A000.
- **Column privileges**: `GRANT`/`REVOKE` SELECT, INSERT, UPDATE and REFERENCES
  on columns, `has_column_privilege`, `has_any_column_privilege` and
  `information_schema.column_privileges`. A statement without the table
  privilege runs only when every column it names is granted.
- **COPY**: `COPY TO` writes the HEADER line, CSV quotes empty strings,
  `HEADER MATCH` checks the column names (22P04), and binary COPY reads and
  writes the PGCOPY format for built-in types.
- **Statistics aggregates**: the stddev/variance family with PostgreSQL's
  numeric scale, `corr`, `covar_*`, `regr_*`; `bit_and`/`bit_or`/`bit_xor` keep
  their input type. `make_date`, `make_time`, `make_timestamp`.
- **Partitioning**:
  - Expression partition keys (`PARTITION BY RANGE ((b + 0))`, `LIST
    (lower(a))`, keys mixing columns and expressions) route rows, check bounds
    and show in `pg_get_partkeydef`; the CREATE-time rules and errors follow
    PostgreSQL.
  - Sub-partitioning (`PARTITION OF ... PARTITION BY`), `pg_partition_tree`,
    `pg_partition_ancestors`, `pg_partition_root`.
  - `CREATE INDEX` on a partitioned table builds an attached index on every
    partition; new and attached partitions get the parent's indexes; attached
    indexes cannot be dropped alone (2BP01). Unnamed indexes get PostgreSQL's
    generated names.
  - CHECK constraints and SET/DROP NOT NULL on a partitioned table reach every
    partition; `ATTACH PARTITION` matches columns by name and reports
    mismatches, bound violations and overlaps with PostgreSQL's errors.
  - An UPDATE that moves a row checks the destination partition's constraints
    first; `RETURNING tableoid` names the partition holding the row.
- **Type USAGE and predefined roles**: `GRANT/REVOKE USAGE ON TYPE|DOMAIN`;
  USAGE is checked for column types, function argument and result types.
  `pg_read_all_data`, `pg_write_all_data` and `pg_maintain` exist and grant
  exactly what PostgreSQL grants (no TRUNCATE, no row-security bypass); they
  cannot log in, be dropped or be altered, and `pg_` role names are reserved.
- **PL/pgSQL exceptions**: `EXCEPTION WHEN` accepts every PostgreSQL condition
  name, SQLSTATE literals and OR lists; category conditions trap their class;
  `OTHERS` never traps query_canceled or assert_failure. `RAISE ... USING`
  sends HINT/COLUMN/CONSTRAINT/DATATYPE/TABLE/SCHEMA; `GET STACKED DIAGNOSTICS`
  returns the handled error's fields; `ASSERT` raises P0004.
- **Foreign keys referencing partitioned tables** find the referenced row in
  its partitions and protect every partition's rows; `pg_constraint` lists the
  per-partition constraints with `conparentid`; ATTACH PARTITION validates the
  attached rows against the parent's keys.
- **Large-object privileges** (`GRANT/REVOKE ... ON LARGE OBJECT`,
  `has_largeobject_privilege`, `pg_largeobject_metadata`), the **MAINTAIN**
  table privilege, and `GRANTED BY` (current role only, as PostgreSQL allows).
  `pg_stats` shows a column's statistics to a role with SELECT on that column.

## Changed

- **INSERT without a column list** fills the leading columns and gives the rest
  their defaults; mismatched counts fail with PostgreSQL's 42601 messages.
- **Unaliased result columns** take PostgreSQL's names (`?column?`, `case`,
  `exists`, `row`, the function name, `int4` for `'1'::int`, ...), also in
  derived tables, CTEs and views. Databases on the non-PostgreSQL SQL profile
  keep naming an unaliased expression by its text.
- **Error messages on the PostgreSQL protocol use PostgreSQL's wording**:
  `relation "t" does not exist` (checked before privileges, also for DML
  targets), `table "t" does not exist` for DROP TABLE, `column "c" does not
  exist`, `function f(integer) does not exist` (42883), `permission denied for
  table|view|materialized view|sequence|type x`, `syntax error at or near "X"`.
  Embedded callers keep BicDB's own error text.
- **UPDATE checks its SET targets** even when no row matches, and UPDATE and
  DELETE need SELECT on the columns they read, as in PostgreSQL.
- **LOCK TABLE** checks the privilege each lock mode needs; TRUNCATE accepts the
  TRUNCATE privilege; ADMIN OPTION holders can grant and revoke a role.
- A self-referencing foreign key is satisfied by rows the same statement writes.
- Result descriptions carry PostgreSQL's types and type modifiers on every
  execution path (casts, math functions, `date_trunc` on a date, VALUES).
- COPY FROM STDIN resolves its table with the session's search path and role
  before entering COPY mode.
