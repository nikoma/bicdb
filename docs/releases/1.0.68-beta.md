# BicDB 1.0.68-beta

This release makes the server-paged memory and recovery envelope explicit and
observable end to end.

## Paged storage configuration

- `DbConfig` now exposes page size, hard buffer-pool bytes, and WAL checkpoint
  trigger bytes through dedicated builders.
- Equivalent `BICDB_PAGED_*` environment settings are available to server
  processes.
- The configured page size reaches the physical store instead of being hidden
  behind adapter defaults.
- Invalid resource envelopes fail before page storage is created.
- Reopening with a different durable page size remains a non-mutating refusal.
- Buffer frame-count conversion is checked on platforms where a configured
  budget cannot fit the address space.

## Stable telemetry

- `PagedStoreSnapshot` is a versioned, strict, serializable contract covering
  file geometry, free space, page I/O, WAL, and buffer-pool pressure.
- `BicDb::paged_storage_snapshot()` is scrape-safe and returns no synthetic
  data for embedded databases.
- Operational metrics and Prometheus expose only fixed-cardinality names.
- `bicdb metrics`, the TUI, `bicdb doctor`, and sanitized doctor bundles now
  include paged memory and storage pressure.
- Doctor identifies admission failures, high dirty-page occupancy, WAL
  pressure, and a safely ignored post-crash physical tail.

## Verification

Tests cover strict JSON, workload counters, configured bounds, restart-stable
gauges, non-mutating page-size mismatch, invalid preflight, embedded-mode
absence, Prometheus cardinality, concurrent read-only scrapes, doctor bundles,
and pressure metric propagation.

See [Server-paged storage configuration and observability](../paged-storage-observability.md).
