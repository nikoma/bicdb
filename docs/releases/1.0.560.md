# 1.0.560: COPY ON_ERROR IGNORE, DEFAULT markers, WHERE and FREEZE

## Added

- **COPY FROM ... (ON_ERROR IGNORE)** skips rows whose values a column type
  rejects (domain checks included), with PostgreSQL's notices: a count of
  skipped rows unless LOG_VERBOSITY is SILENT, and one notice per row under
  VERBOSE. REJECT_LIMIT fails the COPY with 22P02 once passed. Missing or
  extra fields and table constraint violations still abort the COPY.
- **COPY FROM ... (DEFAULT 'marker')**: a field equal to the marker takes the
  column default; a column without one gives 22P04.
- **COPY FROM ... WHERE** filters each row before insert, and the reported
  count is the number of rows inserted. Unknown columns, generated columns,
  subqueries, set-returning functions, aggregates and window functions are
  refused before any data is read.
- **COPY FROM ... (FREEZE)** is accepted only in a transaction block on a table
  created or truncated in the current subtransaction, otherwise 55000 (0A000
  on a partitioned table). There is no separate frozen visibility, so an
  accepted FREEZE has no further effect.

## Fixed

- Rows skipped or filtered by COPY no longer use up sequence values.
- A COPY outside a transaction block no longer drops the notices its rows
  raised.
- COPY FROM errors are reported in input order.
