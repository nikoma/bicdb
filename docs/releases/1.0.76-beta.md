# BicDB 1.0.76-beta

This release makes bounded server-paged checkpoints an automatic production
service rather than an operator-driven API.

## Automatic checkpoint hosting

- Starts one checkpoint driver for each server-paged database hosted by
  `bicdb serve`, including dynamically opened cluster databases.
- Resumes the exact checksummed active schedule before considering a new
  operation.
- Starts work under WAL pressure or the configured periodic cadence and
  advances only one due bounded supervisor step per poll.
- Preserves operator and automatic pauses without replacement.
- Rate-limits new generations when a completed checkpoint safely retains WAL,
  preventing an unfrozen transaction watermark from causing a hot loop.
- Stops cooperatively with server shutdown.
- Leaves embedded-memory databases untouched and creates no paged maintenance
  state for them.

## Shared resource governance

- Gives the node one resource governor shared by checkpoint and range-repair
  workers across every hosted database, preventing either task type or database
  count from multiplying the complete background allowance.
- Adds non-mutating hard-demand validation to the governor.
- Rejects new checkpoint configuration that cannot fit the compaction lane
  before server startup.
- Revalidates a restored schedule against current hard limits before page
  access; impossible work remains durably intact and fails closed instead of
  retrying as transient saturation forever.
- Bounds host polling, new-operation cadence, error logging, and exponential
  error backoff.

## Verification

Tests cover periodic and WAL-pressure starts, process-restart continuation with
the same operation ID, exact durable completion, operator-pause preservation,
impossible restored demand, invalid startup configuration, embedded-mode
inactivity, node-wide multi-database governance, real server-worker execution,
cooperative shutdown, WAL truncation, and committed-row readability after
reopen.
