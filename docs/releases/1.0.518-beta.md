# 1.0.518-beta source candidate: commit visibility completion

The first integrated ec4 candidate failed normal all-target compilation with
eight test-worker lifetime errors. See the
[source-pinned failure and separate correction](../design/visibility-ec4-compile-failure.md).
The correction remains uncompiled at this checkpoint. The preparation matrix
below is historical, not a later CI pass.

The independent ec4 SQL job subsequently passed: 2,682 tests passed, zero
failed and four were ignored. Its new real generic post-commit Sync dimension
error control executed successfully, preserving committed SQL DDL/rows/GUC and
the original error. The linked result retains the full original log hashes and
scope. It does not establish timed-Unknown, PGwire, native or physical behavior,
and does not repair the separate ec4 compilation failures.

The remaining-workspace job also failed at runtime: its schedule test reached
the original row/identity assertions, then `disable("notes")` refused
nonquiescent application admission. The target reported 158 passed, one failed
and one ignored. A separate test-only correction drains the actual background
supervisors before the unchanged disable assertion. It does not relax product
admission or timeouts. Both corrections still require new normal CI. Complete
ec4 originals are retained: 11 logs, seven ZIPs and 24 ZIP members; the linked
failure document records the exact errors, checksums and scope.

This candidate changes ordinary commit completion so an exhausted original
five-second visibility wait cannot become a successful ACK. It retains the
actual transaction identity and required post-commit obligations, preserves
committed SQL DDL/settings on a completion error, and keeps native local
materialization separate from an ordinary global-visibility proof.
