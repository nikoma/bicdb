# BicDB 1.0.57-beta

Release date: 2026-08-03

## Fail-closed background-saturation certification

- Advances the immutable cluster certification plan, collector state, and
  report formats to version 2.
- Requires a dedicated, atomically checkpointed background-saturation
  observation before a scale evidence bundle can be finalized.
- Binds before, saturated, and after fixed-cardinality governor snapshots for
  every planned node to one continuous certification window.
- Requires anti-entropy, backup/restore, compaction, and index construction to
  be simultaneously active and newly admitted on every node, with a measured
  rejected background admission proving actual saturation.
- Binds each rejection to the node's validated governor configuration, exact
  background lane, and nonzero demand; the demand must fit the lane hard limit
  yet fail admission against the captured live resource envelope.
- Rejects duplicate or missing nodes, missing or duplicate lanes, inconsistent
  aggregate usage, counter regression, non-quiescent boundaries, and snapshots
  outside the measured window.
- Requires at least five minutes of sustained pressure, 10,000 successful
  foreground reads, writes, and range-quorum operations, 1,000 successful
  metadata-quorum checks, and zero unavailable ranges.
- Enforces no more than 25% read or write p99 regression against measured
  baselines during that same saturation window.
- Adds a mandatory `background-saturation` raw artifact and verifies that the
  typed observation references that exact artifact kind.
- Strengthens failure, restore, and expansion observations so they must also
  reference their exact required raw artifact kinds.
- Exposes saturation progress through human-readable and JSON certification
  status output, while retaining atomic restart and failed-finalization retry.

This release freezes the evidence contract; it does not claim that the
production 1 TB, 5 TB, or 20 TB hardware runs have already passed.
