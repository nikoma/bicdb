# 1.0.535: crash, reopen and hang fixes found by PostgreSQL's regression suite

Running PostgreSQL 18.4's own regression suite against BicDB found ways for an
ordinary client to abort the server, two ways to leave a database that would
not open again, and several hangs. All are fixed here; each has a regression
test.

## Fixed

- **A query could abort the server.** `SELECT 1 AS x ORDER BY x` (an ORDER BY
  of a constant through an alias or position) recursed until the stack
  overflowed. It now runs as in PostgreSQL. Deep recursion in queries and
  stored functions continues on additional stack segments up to a bound
  (`BICDB_MAX_STACK_SEGMENTS`, default 8 × 8 MiB) and then fails with 54001
  "stack depth limit exceeded" instead of aborting the process.
- **A database could stop opening:**
  - `DROP TABLE` of a list-partitioned table with partitions failed half-way
    and left a store that never opened again. DROP now removes the partitions
    first, as PostgreSQL does, and opening such an already-damaged store
    restores the missing empty parent (logged; no rows are deleted).
  - A partitioned table with a UNIQUE constraint and at least one partition
    made the database refuse to open, even after a clean stop. The partition's
    inherited constraint copy is now accepted.
- **COPY FROM STDIN** that fails before its data (for example, a missing
  table) no longer leaves the session waiting forever; the error is returned
  before COPY mode starts, and a query sent in the middle of COPY data gets
  08P01 and ReadyForQuery.
- **Overflow panics** in `array_fill`, `date_bin`, window frame offsets,
  day-number conversions and `to_timestamp` now return PostgreSQL's results or
  range errors (22003/22008) instead of a contained internal panic.
- **Runaway queries:** a correlated EXISTS over a table without a single
  numeric primary key is answered from one scan instead of one per outer row
  (authorization is checked as before), and a recursive UNION over a type that
  cannot be hashed is refused with PostgreSQL's 0A000 instead of looping.
