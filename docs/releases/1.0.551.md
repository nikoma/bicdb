# 1.0.551: foreign keys cannot be created over uncommitted parent changes

## Fixed

- **A new foreign key could be marked valid over an orphan row.** ALTER TABLE
  ADD FOREIGN KEY (equality or temporal, PERIOD), CREATE TABLE ... REFERENCES,
  ALTER TABLE VALIDATE CONSTRAINT and ATTACH PARTITION checked the referencing
  rows against committed data only. A transaction that had deleted or changed a
  referenced row but not yet committed could then commit and leave a
  referencing row without a parent, under a constraint that claimed to hold.
  PostgreSQL's lock on the referenced table makes the DDL wait for such
  writers; here the DDL now refuses with a retryable 40001 while another open
  or prepared transaction has uncommitted row changes in the referenced table
  or its partitions. NOT VALID keys skip existing rows, as in PostgreSQL, and
  are not refused. Ordinary DML is unchanged.
