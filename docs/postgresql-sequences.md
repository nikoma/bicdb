# PostgreSQL Sequences

BicDB supports the PostgreSQL sequence primitives needed by common migrations:

```sql
CREATE SEQUENCE invoice_seq;
SELECT nextval('invoice_seq');
SELECT currval('invoice_seq');
SELECT setval('invoice_seq', 100, false);
```

`SERIAL` and `GENERATED BY DEFAULT AS IDENTITY` create table-owned sequence
metadata and fill omitted column values during `INSERT`:

```sql
CREATE TABLE invoices (id SERIAL PRIMARY KEY, label TEXT);
CREATE TABLE events (
  id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name TEXT
);

INSERT INTO invoices (label) VALUES ('first');
INSERT INTO events (name) VALUES ('created');
```

Migration defaults can attach an existing sequence to a column:

```sql
ALTER TABLE invoices ALTER COLUMN id SET DEFAULT nextval('invoice_seq');
UPDATE invoices SET id = nextval('invoice_seq') WHERE id IS NULL;
```

Sequence state is persisted separately from table rows. Like PostgreSQL 18.4,
`nextval` is not rolled back: if a transaction consumes a sequence value and
then rolls back, the next transaction observes the advanced sequence.

Catalog exposure is intentionally practical rather than exhaustive. Sequence
metadata appears in `information_schema.sequences`, `pg_catalog.pg_class` with
`relkind = 'S'`, `pg_catalog.pg_sequence`, and `pg_catalog.pg_sequences`.

Current limits: advanced sequence DDL, full dependency management, permissions,
`ALTER SEQUENCE`, and exhaustive `pg_catalog` parity are not implemented.
