# BicDB 1.0.22-beta

Release date: 2026-08-03

## Resumable cluster restore activation

- Adds trusted per-node restore acknowledgements constructed only after the
  certificate-bound startup gate passes.
- Adds immutable activation plans that require exactly every admitted artifact
  node and bind their canonical acknowledgement-set hash to the metadata
  activation decision.
- Adds a single-owner `ClusterRestoreActivationRun` with explicit release-batch
  limits pinned into the checksummed activation plan and constant-size atomic
  progress checkpoints. Restart cannot silently widen those limits.
- Reconstructs each release from the certificate's exact plan, range epoch,
  resolved cut, quorum, and artifact observations. A crash repeats at most one
  idempotent batch.
- Keeps every write fence installed until the exact activation is committed in
  a newer metadata term and commit index.
- Atomically publishes `ClusterRestoreReadiness` only after all ranges are
  released. Per-node readiness rechecks admission, the current metadata
  decision and watermarks, and requires an empty fence catalog.
- Bounds and no-follow opens all activation control files, uses an OS ownership
  lock, detects state/readiness tampering, and removes unpublished staging
  directories after failed initialization.
