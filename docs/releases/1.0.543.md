# 1.0.543: 63-byte identifiers, DROP TYPE dependents, geometric typing over joins

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/g.cases` and the PostgreSQL 18.4
regression suite.

## Changed

- **Identifiers longer than 63 bytes are cut to 63 bytes**, as PostgreSQL's
  NAMEDATALEN rule does, with the NOTICE `identifier "..." will be truncated to
  "..."`. String literals, comments and dollar-quoted bodies are untouched;
  statements passed to the embedding API as parsed ASTs keep their names.
  Databases on the non-PostgreSQL SQL profile are unaffected.
- **DROP TYPE of a type that columns use** fails with PostgreSQL's message, a
  DETAIL line per column and the CASCADE HINT; with CASCADE it reports `drop
  cascades to column c of table t`.

## Added

- **Geometric expressions over joins**: `a.p * b.p`, `b.p[1] > 3`, the prefix
  operators `@@`, `@-@`, `#`, `?|`, `?-` (also as WHERE conditions) and casts
  between geometric types (`lseg::point` is `point(lseg)`) evaluate as in
  PostgreSQL. Line input reports `invalid line specification`.
