# BicDB 1.0.365-beta

TPC-C fresh-eyes campaign, Tier 1: allocation and contention cuts on the
per-statement path. Measured on benchmark-primary (16 warehouses, 32 VUs, tuned-durable
lane) against the same base: +8.1% NOPM (139.9k → 151.3k) on top of the
regression fixes shipped in 1.0.364-beta and the follow-up PRs.

- Transactions index their own write log, so read-your-writes overlays are
  one hash probe instead of a scan of every buffered write per point read.
- Embedded statements share the session GUC map behind an `Arc`, and the
  trigger, extension-event, inbound-foreign-key and unique-arbiter catalog
  listings are memoized behind catalog generation counters instead of being
  re-scanned per statement.
- UPDATE takes a before-image only when a unique key can change or a
  trigger, foreign key or event binding will read it, and projects RETURNING
  before moving the updated records into the write.
- Small NUMERIC arithmetic and comparison run on an allocation-free
  `(i128, scale)` fast path with differential tests against the exact
  BigInt path.
- `BICDB_ROW_LOCK_POLICY=wait-die` selects the textbook row-lock loser rule;
  the default is unchanged pending its A/B.
- The campaign plan, findings and the regression table live in
  `docs/tpcc-fresh-eyes-todo.md`.
