# BicDB 1.0.350-beta

This release fixes a PostgreSQL 18.4 type-resolution divergence found while qualifying reviewed medication status changes in the WalkNorth EHR Cell.

## Changes

- Resolve `CASE`, array, and common-type function branches with the available row-column context before falling back to PostgreSQL's all-unknown `text` rule.
- Preserve a timestamp column's `timestamptz` type through nested `COALESCE` expressions when a bound timestamp parameter is `NULL`.
- Match PostgreSQL 18.4 for conditional `UPDATE` assignments whose branches combine null parameters, unqualified timestamp columns, and `NOW()`.
- Add regression coverage for the exact medication-status query shape that exposed the issue.

## Verification

- `cargo fmt --all -- --check`
- `cargo check -p bicdb-sql`
- `cargo test -p bicdb-sql --test sql null_timestamp_parameter_uses_unqualified_column_context_in_nested_case_coalesce`
- Full `bicdb-sql` SQL regression suite
- PostgreSQL 18.4 comparison using an untyped null parameter in the same `CASE`/`COALESCE` branch structure.
