# Native financial comparison and controlled schema evolution

This source batch retains the native ledger and the ordinary conservative
unique-key evolution checks. Building source is separate from qualifying a
deployment; the accounting release manifest identifies the executed gates.

- Compare complete signed Decimal values, including arithmetic results with
  19–28 fractional digits, without rounding or floating-point conversion.
- Validate RAG provider authority using the actual response/streaming method.
- Refuse code rollback that omits active resources or fields or weakens their
  persisted contracts. Release-derived resource version labels alone do not
  prohibit an otherwise compatible code rollback. Retaining tables on disk
  does not establish that older code safely accounts for their facts.
- Add an explicit operator-signed offline tenant/company unique-key transition.
  It audits all affected physical rows and references, retains immutable IDs,
  financial invariants, transitive mutation/worker guards and tenant policies,
  and binds exact signed package/resource/index identities. It admits only
  existing tenant partitions and untransformed string business keys.
- Support an ordinary preparation upgrade that installs the scoped unique
  index while retaining the global index. The offline scope transition can
  then retire only the global index. Its existing scoped index must match the
  old and new signed contracts exactly and remains present during rollback
  and recovery. Caller and worker changes belong to the ordinary preparation
  upgrade, rather than the scope-only transition.

The transition requires a signed `topology: "standalone"` deployment
attestation and an exclusive store lease. Durable HA/distributed or ambiguous
topology markers are refused before open and after the lease. An absent marker
does not prove that an externally configured deployment is standalone. Cluster,
replication and encrypted-store migration are outside this protocol's qualified
contract.

Apply leaves traffic closed. A durable format feature makes older readers
refuse the store, and pending receipts also fence ordinary raw SQL/application
openers. Recovery and admission require the same signed plan. Pretraffic
rollback restores the old catalog and indexes while retaining the newer-reader
format requirement. A complete fenced pretraffic backup is needed to restore an
older binary. After admission, preserve new financial facts and use a qualified
forward-compatible recovery release.

Node qualification commands accept exact artifact paths:

```sh
CARRIER_BINARY=/absolute/carrier BICDB_BINARY=/absolute/bicdb \
  node scripts/qualify-native-decimal-predicates.mjs
CARRIER_BINARY=/absolute/carrier BICDB_BINARY=/absolute/bicdb \
  node scripts/qualify-native-rollback-contracts.mjs
```

The signed migration, crash-window, older-reader and full accounting gates are
separate required evidence. Formatter parsing, compiler preflight and successful
package signatures do not establish runtime qualification.
