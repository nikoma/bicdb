# 1.0.539: select-list set-returning functions, SQL/JSON, user aggregates and casts, DateStyle, jsonpath

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/d2.cases`, `d3.cases`, `d4.cases`
and `d5.cases`.

## Added

- **Set-returning functions in a select list** follow PostgreSQL's ProjectSet:
  user `SETOF` and `RETURNS TABLE` functions, `(f()).col`, whole records and
  functions nested inside expressions, several of them in lockstep with NULL
  padding. PL/pgSQL `RETURN NEXT expression`.
- **SQL cursors**: every FETCH/MOVE direction, `pg_cursors`, `WITH HOLD`,
  `WHERE CURRENT OF`; `ROLLBACK TO SAVEPOINT` closes the cursors declared after
  the savepoint.
- **SQL/JSON**: `JSON_VALUE`, `JSON_QUERY`, `JSON_EXISTS` (PASSING, RETURNING,
  wrapper, quotes, ON EMPTY / ON ERROR) and `JSON_TABLE` (FOR ORDINALITY, PATH,
  EXISTS PATH, NESTED PATH, PASSING, table-level ON ERROR).
- **CREATE/DROP AGGREGATE** with SQL or PL/pgSQL transition and final functions
  (GROUP BY, DISTINCT, ORDER BY, FILTER and window frames), listed in
  `pg_aggregate`; `array_agg` as a window aggregate.
- **CREATE/DROP CAST**, catalogued in `pg_cast`, used by explicit casts,
  implicit function arguments and INSERT assignments.
- **`pg_export_snapshot()` and `SET TRANSACTION SNAPSHOT`** for repeatable-read
  transactions.
- `ORDER BY ... USING <` / `>`; `ALTER/DROP ROUTINE`; `ALTER FUNCTION/PROCEDURE`
  RENAME and characteristics; `CREATE/ALTER/DROP STATISTICS`; REINDEX target
  validation (otherwise a no-op); operator names the tokenizer used to split
  (`===`, `~~~`, `@@@`); postfix `ISNULL`/`NOTNULL`; composite-field and jsonb
  subscript assignment.
- **Date/time**: `OVERLAPS`, infinite intervals with timestamp arithmetic,
  `isfinite`, `make_timestamptz`, `timestamptz(date, time)`, three-argument
  `date_trunc`, `to_timestamp`/`to_date` with PostgreSQL's template parser, and
  more `to_char` fields (CC, AD/BC, FF1-FF6, ISO week, RM, TZ/TZH/TZM/OF).
- **jsonpath** values print as PostgreSQL prints them; the scanner, item-method
  errors and `jsonb_path_*` named arguments follow PostgreSQL.

## Changed

- **DateStyle and IntervalStyle** now shape date, timestamp, timestamptz and
  interval output (ISO, Postgres, SQL, German; MDY/DMY/YMD). DateStyle,
  TimeZone and IntervalStyle given at connection start apply, and RESET returns
  to them.
- **Date and timestamp input** is decoded as PostgreSQL decodes it (field order
  by DateStyle, two-digit years, Julian days, BC, AM/PM, zone abbreviations with
  DST, `now`/`today`/`tomorrow`/`yesterday`). Numeric `SET TIME ZONE` values are
  hours east of UTC.
- A subscript that leaves part of a multi-dimensional array returns NULL when the
  array type is known, as in PostgreSQL.
- `ROWS FROM (...)` keeps the single implementation already on main; the cases
  of both slices pass through it.
