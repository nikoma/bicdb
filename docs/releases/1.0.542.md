# 1.0.542: nested recursive LIMIT, faster correlated LATERAL joins, PostgreSQL regression-suite harness

Checked with the PostgreSQL 18.4 regression suite and the probe cases in
`fixtures/postgres-compat/pgsql-parity/`.

## Changed

- **A LIMIT over a recursive CTE now reaches recursions nested inside it**: the
  rows still missing are passed into the recursive term, non-recursive CTE
  bodies and parenthesized UNION ALL branches, so a nested `WITH RECURSIVE`
  stops once enough rows exist and returns PostgreSQL's rows instead of hitting
  the materialization bound.
- **`LEFT/INNER JOIN LATERAL (SELECT <exprs over outer and inner> FROM t ...) ss
  ON outer_col = ss.inner_col`** reads its inner side once and matches by the
  integer join key, instead of re-running the subquery for every outer row.
  The inner rows are read as the statement's user; any other shape keeps the
  per-row execution.

## Added

- `scripts/pg18-regress/`: a harness that runs PostgreSQL 18.4's regression
  suite (`parallel_schedule`, through psql 18.4 as pg_regress does) against a
  server, compares with every alternative expected file and clusters failures by
  root cause. Concurrent runs on one host are isolated by run label and port.
  `docs/postgresql-regression-suite.md` describes it and records the baseline.
