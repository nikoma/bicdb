# 1.0.550: COPY CSV records across lines, PostgreSQL's errors for bad COPY rows

Checked against stock PostgreSQL 18.4 with the cases in
`fixtures/postgres-compat/pgsql-parity/q.cases`; the new ones match it
including their CONTEXT lines.

## Fixed

- **CSV quoted fields that contain line breaks**: COPY FROM in CSV mode ended
  a record at every newline, so such a field failed with "unterminated quoted
  CSV field". A record now ends at a newline outside quotes, from STDIN (also
  when a record is split across messages), files and programs. An unclosed
  quote at the end of the input is PostgreSQL's 22P04 "unterminated CSV quoted
  field".
- **Errors for bad COPY rows**, as PostgreSQL reports them:
  - a value its column's type refuses fails with that type's own error
    (22P02, 22003, ...) and `CONTEXT: COPY t, line N, column c: "value"`,
    instead of "column ... of relation ... expects type ...";
  - too few or too many fields fail with 22P04 `missing data for column "c"`
    or `extra data after last expected column` and
    `CONTEXT: COPY t, line N: "<line>"`;
  - values and lines in CONTEXT are cut at 100 bytes, and lines are counted
    as PostgreSQL counts them (the header line counts, and so do line breaks
    inside quoted CSV fields once the input's line-end style is known).

Constraint failures (NOT NULL, CHECK, ...) during COPY still carry no CONTEXT
line.
