# 1.0.517-beta: remote-image fifth-member handoff runs end to end

1.0.515-beta and 1.0.516-beta are reserved by parallel candidates and are not
used here.

This carries the remote route of the four-to-five member range handoff (the
fifth member receives its data as an image from a surviving source, then
becomes a writer) from "never ran past the open phase" to running end to end
in the multi-member test fixtures. It contains the route's receivers and test
drivers, the custody-retaining driver changes, and the fixes below.

## Product fixes

- **A newly joined member could never open.** The joint activation catalogue
  write demanded an installed writer host, although its own pre-checks accept
  a live registered owner for the exact range. A joined member is not a writer
  until release. The write is now gated by the same joint identity proof,
  before and after the write.
- **Old-closure custody could never be retired after open.** Retirement
  re-proved the retained observation against the exact predecessor
  configuration, which a member no longer reports once its bridge for the
  decision is published. Retirement now accepts the untouched predecessor or
  exactly this plan's own published successor; every other proof is unchanged.
- **A surviving leader could not commit after a handoff.** The commit
  preflight compared against the writer's original range configuration. It now
  uses the verified Serving configuration when one is published.
- **A surviving leader's new epoch was never recovered.** Only the joined
  target recovered leadership. The original data owner can now run the same
  recovery (`recover_initial_data_leadership`).
- **A surviving leader's commit callback refused its own command.** Its
  Serving audit reads the range lineage, which refuses any pending command,
  including the one the callback is completing. That one caller now proves
  the pending record is exactly its own command extending the lineage; every
  other caller, and any other pending record, is still refused.
- **An interrupted activation write could not be retried by a registered
  member.** The re-fsync paths proved identity with the store's uncertain
  marker in force, which a registered owner's proof refuses; they now set
  aside only that activation's own marker, as the first write does.
- **A publisher was refused by its own in-progress marker** when re-reading
  its catalogue after publication.
- **Validation cost.** The standalone lineage read repeated its full contract
  a third time with no lock change in between; two redundant full sweeps
  around the read-pin release are replaced by liveness checks.

## Test infrastructure

- The one-at-a-time multi-member test jobs build workspace crates at
  opt-level 1. Phase budgets are wall-clock bounds; unoptimized record
  validation exceeded them on slower runners (member check 480 ms to 57 ms).
- Focused Core runs execute multi-member fixtures one at a time.

## Validation

- Shared build host, lightly optimized test build, final product code: all 30
  `hot_policy_tests`, the 3 `custody_retry` tests and the 6
  `native_fifth_data_path_*` tests pass in one serial run (39 passed, 0
  failed).
- An independent read of the product changes found no way to admit a stale
  or foreign owner, lose an acknowledged write, or treat a stale pending
  command as complete. The re-fsync and second-handoff retirement paths it
  flagged as wrongly refusing are fixed here but are not covered by a test.
- Full suite: the checks of the merged pull request.

## Limits

- `recover_initial_data_leadership` has no product caller, and returns zero
  silently if called before the new topology is installed.

- There is still no operator command or controller that moves a range, and no
  remote backend for the production driver. The production driver always
  retires the leader, so the surviving-leader path is reached only by tests.
- The checked custody retirement and the first-policy steps of the remote
  route have test callers only.
- A stop is refused while a first policy has an unknown outcome; reconciling
  that state after a local term change is not implemented.
- No physical multi-host scale-out run has been repeated.
