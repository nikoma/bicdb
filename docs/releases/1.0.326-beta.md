# BicDB 1.0.326-beta

This release enables regulated-data admission through the complete Phase-8
evidence boundary. Admission is derived from verified evidence; it is not a
command-line switch or an ambient environment capability.

## Regulated-data admission

- Enable the release-level regulated-admission capability after the full
  twelve-gate bundle, deployment attestation, transparency checkpoint, and
  short-lived activation authorization verify for the exact Cell, manifest,
  binary, guest image, application/schema set, security profile, isolation
  profile, and deployment tier.
- Derive `CellAdmissionReport.regulated_data_admitted` from the verified
  evidence retained by `CellRuntime`, and report `ADMITTED` from both Cell CLI
  entry points only for that state.
- Permit `regulated` and `regulated_local` application/component contracts
  only for the coherent Phase-8 profile after its exact evidence has verified;
  earlier profiles and unverified bundles still reject them before database
  open.
- Keep Phase 1 through Phase 7, missing/incomplete evidence, stale evidence,
  wrong roles or keys, cross-build/Cell substitutions, and untrusted
  deployment attestations fail closed.
- Permit the BicDB owner/operator to run the admission ceremony. The existing
  minimum two-key thresholds, disjoint key domains, role-separated signatures,
  exact evidence, and short validity windows remain mandatory. Concentrated
  organizational key custody must be disclosed as a governance risk.

## Validation

- The admission verifier's positive test now proves that a complete exact
  bundle enables regulated admission.
- The same test proves that clearing evidence completeness still denies
  admission in an admission-enabled release.
- Existing adversarial coverage continues to reject missing or duplicate
  gates, role substitution, build substitution, stale evidence, tampering,
  non-canonical documents, and untrusted deployment attestation.

Synthetic fixtures validate the mechanism; operators remain responsible for
attaching truthful test, review, deployment, and operational evidence to any
production authorization.
