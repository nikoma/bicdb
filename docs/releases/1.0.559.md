# 1.0.559: temporary views and sequences, and catalogs that stay readable

## Fixed

- **A view over a temporary table could break catalog reads for every
  session.** `CREATE VIEW pg_temp.v ...` was stored under a schema that never
  existed, and a view over a temporary table was created as a permanent view
  that was orphaned when its session ended. Either way, every later read of
  pg_class or information_schema, and CREATE TABLE, failed with "relation ...
  has no matching namespace". Views over temporary relations are now
  temporary, with PostgreSQL's NOTICE (42P16 in an explicit permanent schema;
  0A000 for a materialized view). When a database opens, views left without
  a schema by earlier builds, and rules of relations that no longer exist, are
  removed; no table or sequence is touched.
- **CREATE TEMP SEQUENCE created a permanent sequence.** It is now temporary,
  and nextval, currval and setval look in the session's temporary schema
  first.
- **DDL did not find temporary tables.** LIKE, INHERITS, COMMENT ON,
  has_table_privilege, rule actions and regclass output now resolve them. A
  permanent table cannot inherit from (42809) or reference (42P16) a
  temporary one. CREATE TEMP TABLE ... PARTITION OF works.
- **UPDATE or DELETE through an inheritance parent failed** when the children
  were outside `public`, and unique-violation errors on such tables named the
  internal storage name instead of the constraint.

## Added

- CREATE TEMP VIEW, CREATE OR REPLACE TEMP VIEW and CREATE VIEW pg_temp.v.
