# BicDB 1.0.74-beta

This release adds bounded, governed background writeback for the server-paged
buffer pool.

## Bounded writeback

- Maintains an ordered dirty-page index with at most one entry per dirty
  resident frame, bounded by the configured buffer pool.
- Adds strict inclusive cursor, limit, report, and stop-reason contracts.
- Caps one step by candidate count, logical WAL-plus-page I/O, and cooperative
  duration.
- Returns the exact first unexamined candidate and reports pinned pages without
  forcing, blocking on, or forgetting them.
- Syncs once per nonempty bounded batch rather than once per page.

## Durability and governance

- Runs the writeback barrier before any page write that still owes a WAL image,
  reuses already-durable committed images, and clears pending-log state only
  after the page write succeeds.
- Leaves barrier or page-write failures dirty and retryable.
- Admits the public BicDB operation through the compaction resource lane only
  after its memory and complete logical-I/O demand has been validated.
- Rejects resource saturation and underdeclared demand before examining a page.
- Embedded-memory mode rejects the operation explicitly.

## Observability

- Advances the strict paged-storage snapshot contract to format version 3.
- Adds fixed-cardinality counters for writeback steps, background pages,
  candidate/I/O/duration stops, and pinned skips.
- Documents online sweep semantics and the requirement that completion plus
  zero remaining dirty pages constitutes a drained pool.

## Verification

Tests cover exact multi-step resume, candidate and I/O boundaries, cooperative
duration stopping, strict serialization and report validation, pinned-page
retry, barrier failure and retry, durable bytes, resource-demand preflight,
lane saturation before work, telemetry, public API forwarding, and embedded
rejection.
