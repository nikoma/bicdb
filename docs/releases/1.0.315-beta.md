# BicDB 1.0.315-beta

This maintenance release makes the full GitHub Actions test matrix reliable on
hosted runners without reducing its coverage.

## CI resource bounds

- Compile/link fan-out is capped at one job and Rust test fan-out at four
  threads. CI also disables incremental artifacts and debug symbols, keeping
  the complete matrix below hosted-runner memory and disk ceilings.
- The `bicdb-core` matrix job builds the one out-of-process helper required by
  its projection chaos test. Other jobs no longer build every example in the
  workspace before their own test suite.
- This fixes the `SIGBUS` linker crashes and disk exhaustion observed while
  validating 1.0.314-beta without skipping any test suite.
- The SQL suite preserves its unit, documentation, and every integration-test
  target while linking them one at a time and deleting only each completed
  test executable. Shared dependency artifacts remain cached.

## Metadata failover race

- Metadata consensus now starts an election only if the complete state and
  leader-contact observation that made it appear due are still current.
- A granted vote or leader append racing the supervisor therefore cancels the
  stale local election instead of causing surviving voters to repeatedly
  disrupt one another after a leader failure.
- Leader-contact observations advance monotonically even when back-to-back
  RPCs land within one millisecond, and a focused regression test preserves the
  compare-and-start boundary.
- A newly elected leader now broadcasts its leadership barrier in the same
  scheduling slice as the successful vote. A loaded host cannot deschedule the
  supervisor between election and first append long enough to trigger an
  avoidable higher-term election storm.
- Replication now honors a follower's bounded conflict index. A failover
  survivor that has already compacted a commit the new leader still carries in
  its log can converge at that retained boundary instead of rejecting the same
  stale snapshot predecessor forever.

## Crash-consistent record audit events

- Record audit events now travel in the same transaction WAL decision as their
  row mutations and are published to the event stream only after that WAL is
  durable.
- Startup replays committed audit outbox entries idempotently before projection
  consumers open. A process crash can therefore no longer leave a projection
  event without its row commit, or a committed row without its audit event.
- Event publication writes a durable transaction-log acknowledgement. Recovery
  therefore does not resurrect acknowledged history after audit retention has
  intentionally removed it.
- A focused recovery test exercises the exact crash window between durable
  transaction commit and event-stream publication.

## Online extent migration allocation fence

- A concurrent allocator now establishes sparse backing bytes before advancing
  the page-count horizon observed by the live extent-migration copier.
- The copier can no longer select a newly allocated page before that page is
  readable from the monolithic source, eliminating the hosted-runner short-read
  race without weakening the migration stress test.

The clinical-cell implementation introduced in 1.0.314-beta is unchanged. Its
current admission report remains fail-closed for clinical PHI until the serving,
encryption, key-management, and operational gates documented in
`docs/cell-runtime-phase1.md` are closed.
