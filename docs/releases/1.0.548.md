# 1.0.548: temporal foreign keys complete, exclusion constraint parity

Checked against stock PostgreSQL 18.4 with the `without_overlaps`,
`foreign_key`, `updatable_views`, `inet` and `window` regression tests.
Differing statements in `without_overlaps` fell from 195 to 105.

## Added

- **Temporal foreign keys in the catalogs**: `pg_constraint` lists
  `FOREIGN KEY (a, PERIOD p) REFERENCES t (b, PERIOD q)` with `contype` `f` and
  `conperiod` true; temporal primary keys and unique constraints set `conperiod`
  too. `pg_get_constraintdef` prints the PERIOD form, and
  `information_schema.table_constraints` and `key_column_usage` list the keys.
- **Deferrable temporal foreign keys**: `DEFERRABLE` and `INITIALLY DEFERRED`,
  `SET CONSTRAINTS` and `ALTER CONSTRAINT` timing. A deferred check reserves the
  referenced key at once and checks the row's final state at commit.
- **Temporal foreign keys on partitioned tables**, on either side. Rows of every
  partition are checked, whichever name a write uses; `ATTACH PARTITION`
  validates the attached rows; `TRUNCATE`, `DROP` and `DETACH PARTITION` of a
  referenced partition are refused while rows reference it; a detached
  referencing partition keeps the key. `pg_constraint` shows the partitions'
  copies and one `<name>_<n>` row per referenced partition, as PostgreSQL does.
- **`ON CONFLICT DO NOTHING` with exclusion constraints and temporal keys**:
  without a target, conflicting rows are skipped. `ON CONFLICT ON CONSTRAINT`
  naming one arbitrates it when no other unique or exclusion constraint
  applies.

## Changed

- DETAIL lines of exclusion and temporal key conflicts: `Key (...)=(...)
  conflicts with existing key (...)=(...).`, columns in declared order. Adding a
  constraint over conflicting rows reports `could not create exclusion
  constraint` with `Key (...)=(...) conflicts with key (...)=(...).`. Temporal
  foreign key violations show `is not present in table` and `is still
  referenced from table` with the key.
- `ON CONFLICT ... DO UPDATE` against an exclusion constraint or temporal key
  fails with 42809, `ON CONFLICT DO UPDATE not supported with exclusion
  constraints`.
- `pg_get_constraintdef` of a NOT NULL constraint is `NOT NULL id`, and of an
  exclusion constraint lists its elements in declared order.
- A `CREATE TABLE` column named `exclude` is a column again, not the start of
  an inline exclusion constraint.

## Not supported

- `ON CONFLICT ON CONSTRAINT <exclusion> DO NOTHING` on a table with other unique
  or exclusion constraints, or on a partitioned table, is refused with 0A000.
- Temporal foreign key actions other than `NO ACTION` stay refused with 0A000.
