# BicDB 1.0.75-beta

This release adds bounded, restartable, resource-governed checkpoint
maintenance for server-paged storage.

## Checkpoint state machine

- Replaces threshold-triggered all-buffer flushing with one bounded checkpoint
  phase per commit.
- Adds inclusive `drain`, `freeze`, `finalize`, and terminal cursors.
- Bounds dirty candidates, logical writeback I/O, duration, transaction-status
  freezing, and tail reclamation independently.
- Tracks active XIDs separately so oldest-snapshot lookup is allocation-free and
  does not scan retained transaction history.
- Finalizes only under the writer fence after a zero-dirty proof and a durable
  meta-page write.
- Serializes abort records with checkpoint WAL publication and reset.
- Leaves WAL intact when committed status cannot yet be represented by the
  durable freeze watermark.

## Durable supervisor

- Persists the exact phase cursor, immutable page size and resource envelope,
  cumulative totals, retry state, and last strict report in checksummed,
  size-bounded state.
- Uses atomic publication, symlink-safe bounded reads, immutable store and
  operation IDs, stale-worker fencing, monotonic timing, saturation deferral,
  capped exponential backoff, and durable pause/resume.
- Admits every page step through the background compaction lane before work.
- Exposes fixed-cardinality phase, progress, failure, and resource-deferral
  metrics.

## Verification

Tests cover one-page drain limits, one-transaction freeze limits, strict report
validation, process-restart resume, checkpoint-publication replay, concurrent
commits, pinned/revisited dirty pages, WAL truncation fencing, threshold latency
bounds, resource saturation before page work, corrupt state, active-operation
replacement, stale workers, pause/resume, embedded-mode rejection, recovery,
and Prometheus output.
