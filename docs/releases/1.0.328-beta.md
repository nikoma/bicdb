# BicDB 1.0.328-beta

This release makes paged-store crash recovery independent of database size.
It fixes a WalkNorth production startup regression where replaying any WAL page
was followed by a complete scan of a 924 GiB page file.

## Bounded crash recovery

- Remove the post-WAL full-store page-header scan. On the production shape it
  read roughly 119 million 8 KiB pages and delayed service readiness by 76–77
  minutes.
- Before the first committed page image is replayed, atomically detach the
  persisted intrusive free list in constant time. This prevents a replayed live
  page from remaining allocator-reachable without inspecting every data page.
- Preserve the free list on clean opens and on recovery passes that have no
  committed page image to replay.
- Report the number of allocator entries detached as
  `RecoveryReport::free_pages_detached`.

## Recovery trade-off

Detaching the allocator list can temporarily orphan reusable pages after an
unclean shutdown. This is deliberately fail-safe: it may defer space reuse but
cannot make live data reusable. BicDB's existing bounded, resumable orphan
reclamation pass can recover that space after the database is online. There is
no storage-format change and no index rebuild is required.

## Validation

- Added a 4,096-page WAL-recovery regression proving page reads remain below
  one eighth of the database page count while committed data survives.
- Added a clean-reopen regression proving a checkpointed free list remains
  intact when WAL replay is unnecessary.
- Passed all 287 `bicdb-page` library tests and the crash-matrix,
  kill-recovery, page-reclamation, and segmented-WAL integration suites.
