# BicDB 1.0.80-beta

This release closes the initial fixed-cardinality WAL, checkpoint, and startup
recovery pressure contract without scanning the log during a scrape or
discarding an in-progress maintenance operation during upgrade.

## WAL sync evidence

- Counts successful physical syncs, failed syncs, total WAL records newly
  covered, and the last and maximum successful record batch.
- Measures every successful WAL `sync_data` with the fixed cumulative latency
  boundaries already used by page I/O. Explicit no-fsync test mode measures its
  `flush` call instead and remains distinguishable through effective storage
  configuration.
- Excludes append and file-lock wait, does not manufacture observations for
  redundant already-durable requests, and keeps failed operations out of the
  successful latency distribution.
- Computes checkpoint age from a monotonic process clock while retaining wall
  completion time for correlation. Zero explicitly means no checkpoint has
  completed in the current process.

## Recovery and checkpoint accounting

- Retains one strict, bounded startup recovery report in the open paged store:
  logical WAL input bytes, complete startup-recovery duration, scanned records,
  committed transactions, replayed pages, skipped uncommitted images,
  truncated tail bytes, and redo/end LSNs.
- Covers torn-tail validation and transaction-outcome reconstruction in the
  retained duration rather than timing only the final replay pass.
- Adds durable checkpoint totals for admitted engine-step time and logical WAL
  bytes present at terminal checkpoint publication.
- Exposes both active checkpoint time and schedule wall time so resource
  starvation and operator pauses are not misreported as storage-engine work.

## Upgrade and operational contract

- Advances the strict paged-storage snapshot to format version 7 and the
  checksummed checkpoint-maintenance schedule to format version 2.
- Reads a format-v1 maintenance schedule through its exact legacy schema,
  verifies its original SHA-256, preserves its operation identity, cursor,
  progress, retry, and pause state, and atomically publishes v2 on the next
  transition.
- Initializes newly introduced totals to zero for pre-upgrade work rather than
  inventing unavailable historical measurements.
- Exports all fields through the typed snapshot, operational metrics,
  Prometheus, doctor, and diagnostic bundles using fixed names without path,
  page, database, collection, tenant, query, or plugin labels.

## Verification

Tests cover exact multi-record sync batches, redundant-sync suppression,
concurrent group commit, cumulative latency shape, monotonic checkpoint
freshness, retained recovery evidence, strict nested serialization,
fixed-cardinality exporters and doctor bundles, active versus deferred
checkpoint time, terminal WAL-byte accounting, valid v1 migration, and
checksum rejection before migration.
