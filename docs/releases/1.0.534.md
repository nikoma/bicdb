# 1.0.534: no implicit key on `id`, window EXCLUDE, ROWS FROM, collations, custom ranges

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/c2.cases` and `c3.cases`
(32 cases, identical output).

## Fixed

- **A table without a primary key has none.** A column named `id` was made
  the primary key (unique and NOT NULL) when no key was declared, so valid
  duplicate rows were refused. New tables now use the hidden row identity, as
  tables without an `id` column already did. Tables created before this keep
  their stored schema. Related: `REFERENCES t` without a column list names
  t's primary key (42704 when it has none), and `ON CONFLICT (cols)` without a
  matching unique constraint fails with 42P10 instead of succeeding silently.
- Range functions: `upper(r)` on a user range returned the text-uppercased
  range; `r && '[1,2]'` with an untyped literal failed.

## Added

- **Window frame `EXCLUDE CURRENT ROW | GROUP | TIES | NO OTHERS`.**
- **`ROWS FROM (f(), g()) [WITH ORDINALITY]`** for single-column set-returning
  functions.
- **`CREATE / ALTER / DROP COLLATION`** (ICU locales, C/POSIX, `FROM`,
  `deterministic`), `COLLATE` in expressions and columns, and `pg_collation`.
  ORDER BY now honours a column's declared collation on every sort path.
  Nondeterministic collations apply to comparisons and ORDER BY; other uses
  (GROUP BY, DISTINCT, joins, indexes) return 0A000 for now.
- **Range types over `int2`, `float4`, `float8`, `text`, `time`, `timetz` and
  `interval`**, with multiranges, operators and GiST.
