# BicDB Performance Campaign Ledger

> Publication note: infrastructure identifiers and machine-local paths are
> anonymized examples. See [source distribution notes](source-distribution.md).

Append-only decision record for the three-lane campaign. Curated manifests,
summaries, trial metadata, and results live under `reports/performance/`. Bulky
runtime logs and scratch state are retained outside Git when needed.

## Status vocabulary

- `baseline`: measuring stick, not a candidate.
- `keeper`: correctness passed and the configured performance/resource gate won.
- `mandatory keeper`: correctness fix retained even if performance is neutral or negative.
- `reject`: correctness/resource failure or reproduced regression.
- `inconclusive`: valid evidence but insufficient separation; requires more runs.
- `blocked`: infrastructure prerequisite is unavailable; no performance decision.
