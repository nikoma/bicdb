# BicDB 1.0.70-beta

This release bounds opportunistic server-paged tail reclamation during
checkpoint.

## Bounded checkpoint work

- One attempt may perform at most 8,192 page visits and 64 MiB of logical page
  I/O.
- Preflight discovers the exact physical Free suffix and validates the
  intrusive list before mutating storage.
- Work that cannot fit is deferred with no page, superblock, file-length, or
  free-list change.
- Reclamation keeps one bounded chain vector. It no longer duplicates the
  complete list into a tree set and a survivor vector.
- Free pages leaked before list publication can be recovered when they form the
  physical suffix.

## Interruption safety

- The old free list is atomically detached before survivor links are rewritten.
- A process failure or write failure during that window can leak reusable
  pages, but reopening sees a valid empty list and cannot allocate one physical
  page twice.
- The shorter logical page count is published before physical truncation. A
  failure in the final window leaves an ignored tail that remains visible to
  doctor and can be retried.

## Observability

- Page telemetry now includes tail-reclamation attempts, deferrals, and pages
  truncated.
- The strict paged-storage snapshot contract advances to format version 2.
- Doctor recommends resumable file/extent rewrite maintenance after a bounded
  checkpoint deferral.

## Remaining work

Deferred large lists are not rewritten by checkpoint. A separately supervised,
durable, pause/resume file or extent rewrite remains on the storage roadmap.

## Verification

Tests cover exact envelope accounting, no-mutation deferral, successful
interior-hole preservation, leaked-tail recovery, interrupted survivor-link
rewrite and safe reopen, checkpoint integration, fixed-cardinality telemetry,
and the existing crash/reclamation matrix.
