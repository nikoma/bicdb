# 1.0.554: stores with nested partition trees reopen, and prepared transactions never block an open

## Fixed

- **A store holding a partition tree more than one level deep with a PRIMARY
  KEY or UNIQUE constraint refused to open.** The startup check that matches
  constraint indexes accepted a partition's inherited index only from its
  direct parent. It now walks the whole ancestor chain. A constraint index
  that still cannot be verified at open no longer closes the store: that
  table and its partitions open with writes refused until repaired, and the
  problem is logged. Storage and durability errors still stop the open.
- **Prepared transactions can no longer stop a store from opening.** Each one
  is restored on its own. One that cannot be restored releases its locks and
  is durably marked unrestorable, so no later open can revive it and commit
  it over writes made in between; COMMIT PREPARED on it returns 55000, and a
  superuser can discard it with ROLLBACK PREPARED. If the records cannot be
  listed at all, a durable marker keeps all of them uncommittable and
  PREPARE disabled until none remain.
- **DROP TABLE of a partition tree with triggers failed** with "cannot drop
  an inherited partition trigger directly". The partitions' inherited
  triggers are now removed with the tables, also for DROP SCHEMA CASCADE.
- **FOR SHARE on a row locked by a prepared transaction waited forever.** It
  now fails at once with 0A000, since only COMMIT or ROLLBACK PREPARED can
  release that lock. FOR UPDATE still waits.
