# 1.0.516-beta: independent experiment ledger tooling

This source candidate depends on native recovery candidate515/PR203. It adds
functional qualification tooling and source-audit documentation; it does not
change the production SDK's routing, authorization, retries, quorum or deadlines.
The source version identifies the candidate, not a published binary or release.

The stock SDK probe records original logical attempts, actual RPC frames,
acknowledgments, errors and uncertainty. Its optional pinned-mTLS sink requires
separate collector file/receipt fsync before continuing. Exact receipt schemas
distinguish a mandatory first-row null from a missing field and refuse forbidden
null extras, duplicate fields and invalid counters. The collector uses the same
verified directory descriptor for file creation and directory fsync; kernel
mount observations are not proof of physical flush behavior.

The native SDK is a trusted member API. The proposed isolated arrangement keeps
the member key on its existing test member and uses distinct instrumentation
identities for the external collector/controller. It adds no database principal
or extra voter and does not establish ordinary PostgreSQL application access.

Offline verification and read-only cross-run reconciliation retain every known
or possible success and every attempted/uncertain write. A missing wrapper ACK
cannot exclude an SDK success. Evidence completeness is distinct from correct
database results; every tooling report remains unqualified. See the
[collector design](../design/native-colocated-probe-external-durable-sink.md) and
[tooling overview](../../scripts/platform/native-sdk-ledger/README.md).

The [source audit](../ha-current-source-audit-2026-11-14.md#source-only-operational-follow-up-candidate1fc)
separates historical replica-floor status from per-request Strong admission.
It records missing automatic/cold continuations and the ALL-OLD remote
certificate's inability to replace a permanently unavailable original member.
These are explicit limits, not capabilities supplied by this tooling.

At source freeze, 61 focused Python controls passed, including local files and
loopback TLS. Their bytes match source9c9d2ddcf; those results do not execute a
BicDB SDK or cluster. The Rust producer and seven parser controls still need
compilation/execution in normal CI; no passing Rust result is claimed here.
Original failures and historical evidence remain unchanged.

No new VM, verified optimized binary, deployment, physical RPO/RTO, sustained
throughput gain, successful scale-out or production qualification is produced.
