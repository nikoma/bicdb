# BicDB 1.0.340-beta

This release restores PostgreSQL-compatible bound-parameter evaluation in
standalone `CASE` predicates used by signed Carrier SQL.

## PostgreSQL-compatible SQL behavior

- Resolve `$1..$n` parameters inside `IN` and `NOT IN` predicates evaluated by
  standalone scalar expressions.
- Apply the same bound-parameter semantics to `BETWEEN` and `NOT BETWEEN`.
- Preserve PostgreSQL three-valued `NULL` behavior for both predicate forms.

## Validation

- Reproduced the issue with the WalkNorth EHR clinic-queue transition guard,
  which uses `SELECT CASE ... $2 IN (...)` before completing triage.
- Added a regression using the exact checked-in-to-ready decision shape.
- Confirmed the EHR transition statement now returns `true` instead of
  rejecting `$2` as an unsupported literal.
