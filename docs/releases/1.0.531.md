# 1.0.531: CREATE TABLE AS, writable views, materialized view refresh

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/ctas-views.cases` (83 cases,
identical output).

## Added

- **CREATE TABLE AS and SELECT ... INTO**, with PostgreSQL column names and
  types (typmods kept), `IF NOT EXISTS`, `TEMP`, a column-name list,
  `WITH [NO] DATA` and `AS TABLE` / `AS VALUES`. The query runs with the
  creator's privileges and row-level security. Before this, `SELECT ... INTO`
  returned rows and created nothing.
- **INSERT, UPDATE and DELETE through automatically updatable views**, with
  RETURNING and nested views, and **WITH [CASCADED | LOCAL] CHECK OPTION**
  (error 44000). Privileges follow PostgreSQL: the view owner's on the base
  table, or the caller's for `security_invoker` views. Base-table row-level
  security still applies.
- **REFRESH MATERIALIZED VIEW** with `CONCURRENTLY` and `WITH [NO] DATA`.
  Materialized views now store their rows instead of re-running their query on
  every read; see `docs/postgresql-views.md` for size and type limits.
- **INSTEAD OF row triggers on views.**
