# BicDB 1.0.341-beta

This release restores PostgreSQL contextual timestamp typing for signed SQL
queue transitions and other `CASE` updates.

## PostgreSQL-compatible SQL behavior

- Describe `now()`, `current_timestamp()`, `transaction_timestamp()`, and
  `clock_timestamp()` as `timestamptz` expressions.
- Allow an unknown bound timestamp parameter in `COALESCE(column, $n, now())`
  to inherit the PostgreSQL timestamp context.
- Preserve timestamp typing when that `COALESCE` expression is a `CASE` branch
  in an `UPDATE` assignment.

## Validation

- Reproduced the issue with the WalkNorth EHR clinic queue's complete-triage
  update using its `checked_in` to `ready` timestamp shape.
- Added an end-to-end SQL regression that updates the status and `ready_at`
  columns through the parameterized `CASE` expression.
- Confirmed the bound ISO timestamp is stored instead of producing SQLSTATE
  `42804` (`CASE types timestamptz and text cannot be matched`).
