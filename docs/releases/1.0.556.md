# 1.0.556: ORDER BY keeps NULL placement on ordered index reads

## Fixed

- **Ordered index reads returned rows in the wrong order when the ordering
  column contained NULLs.** Index keys sort NULL below every value, so
  reading a B-tree gives NULLS FIRST ascending and NULLS LAST descending, the
  opposite of ORDER BY's defaults. `WHERE k = v ORDER BY j [DESC] LIMIT n` and
  `ORDER BY j [DESC] LIMIT n` trusted the index order and returned NULLs on the
  wrong side; for example `ORDER BY j DESC LIMIT 7` returned the largest values
  where NULLs belong first. Every ordered-index route now checks NULL
  placement. NOT NULL columns, and statements whose explicit NULLS FIRST /
  NULLS LAST matches the index order, keep the fast path. Other cases read the
  NULL-keyed and non-NULL ranges of the index separately, each bounded by the
  limit, and place them as ORDER BY asks, on resident and paged indexes alike.
