# Remote ALL-Open original-owner retirement

This source batch is a distinct remote ownership transition, based on
`467325de68372cba764ea1d9c64636a4cab1f706` and the frozen metadata/transport
interface `ff5660c5e1f717e251bf836b14530ede45040c2d`. It has not been compiled
or executed. It does not produce native Open, a local release quorum, a
released Frozen permit, a DATA policy, or Strong-read permission.

`NativeRemoteAllOpenRound` accepts only the opaque observations minted by the
actual pinned Serving exchange. A complete proof contains every final NEW
member, including its leader, under one exact MF/phase/decision and one actual
observer. Each member must report the protected preparation, native bridge,
and catalogue activation produced by that member's actual retained owner.
The bounded round rejects duplicate members, other operations and mixed
observers. Its original caller and each exchange's original request remain
live; collection does not renew them. The existing 128-member/8MiB compact
fact bound includes one manifest, rather than a manifest per member.

`NativeRemoteAllOpenRetirementAdmission` pairs that real complete collection
with a different, post-collection actual HostMQ and its attached current
native MStore point, at or above every reply's metadata anchors. It validates
exact AwaitingActivation, current activation range, original configurations,
R/H0/H/session/nonce and decision. Physical checks bind the point to the actual
local DB and Store outside the short publication guard. The final guard does
only request/process/open/slot/version/identity checks and memory moves. The
local version guard is not a distributed metadata lease. The real member
Open/epochs and later fresh release/read protocols remain necessary.

There are separate retirement effects:

* An OLD survivor drains its obsolete host OLD observation and constraint
  observation, plus the original participant's OLD reference. The same host
  table retains runtime, participant, decision and status custody. A sealed
  borrow points at the actual participant slot; the host cannot accept a
  caller-built replacement Option. All gates and latches are acquired before
  the final checks. The actual Frozen-current guard spans the memory moves.
* An original OLD member outside NEW (which may differ from the selected
  image donor) retains its CLOSED host runtime, OLD observation
  and constraint ownership for a future authorized cleanup. Only the obsolete
  participant reference retires; it never becomes Serving or releases Frozen.
* A Registered target drops only the extra freeze held by its original remote
  participant. The actual host/prepared release owner must already retain the
  original lease. Its private successful native receipt and original
  KnownCommitted attempt must match the local opaque frame, including native
  XID, record and remote provenance. Unknown bytes cannot satisfy this check.
* The original donor separately replaces its retained remote OLD certificate
  with identity-only `RetiredJoint`, after completed export retirement and
  exact original source/cut association. It keeps source identity/status and
  CLOSED storage. This RAM-only action uses genuine fresh donor HostMQ/current
  MStore plus ALL-Open, without inventing a final-voter mutation Role.

All removed owners are destroyed after the metadata guard, Frozen-current
guard and host/source latch. A monotone terminal flag distinguishes retired
original-phase APIs from an unstarted operation. Generic original NEW,
DECISION and catalogue requests refuse after retirement; the actual host
lifetime and independent Serving queue remain retained. The ordinary local
`NativeJointReleasePhaseQuorum` and its minters are unchanged.

The recipient native preparation/Open producers, authenticated ingress,
phase-specific current protected reads, actual one-way adoption by the new
phase owner and final release/policy consumers are owned by the separate
finite-Serving batch. They must use these real owners and opaque frames;
serializable point fields are correlation DATA. An all-Open response flag is
never enough to construct an observation. The current interface checkpoint
has no completed native recipient Serving path, so no positive or adversarial
remote retirement test has run in this batch.
