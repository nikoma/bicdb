# 1.0.507-beta: abort and resume for the fifth-member data path

The handoff of one range to a registered fifth member is now driven by a
product driver (`NativeJoinedDataHandoff`) instead of being sequenced by the
test, and a failure no longer leaves the range stuck in the common cases.

- **Abort, before any old voter has recorded a handoff promise:** the original
  range descriptor is committed again through metadata consensus and the
  original members accept writes. It is refused once a source round has
  started or any old voter's durable range log is past the expected epoch.
- **Resume, after a promise exists:** running the same driver again continues
  from the committed metadata stage, closes the source again under fresh
  roles, takes a new capture and replaces the target's partial install.
- A repeat call after completion is a no-op.

The abort returns the range to its earlier epoch. A later handoff that mints
the next epoch again always differs in relocation id, replica id, session and
nonce, and every handoff operation is checked against those; tests replay a
delayed request and retained state from an aborted attempt and assert refusal.

Limits:

- the range is unwritable from the learner allocation until completion or
  abort;
- resume needs the same driver in the same process; a lost driver process or
  a restarted participant is not covered;
- two in-process windows (decision preparation after the finalized image is
  handed over, and handing the decision to serving preparation) still leave
  the range safe but stuck;
- the source round and the abort require every old voter to answer;
- one driver per range is assumed; a second driver racing the abort can strand
  a promise that needs repair;
- the driver has no production caller, and only a handoff back onto the same
  spare member is exercised after an abort.

See `docs/design/native-fifth-data-path.md`.
