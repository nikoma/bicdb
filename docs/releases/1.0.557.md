# 1.0.557: COPY handles generated columns and refuses bad statements before reading data

## Fixed

- **COPY into a table with generated columns failed** with "missing data for
  column". The default COPY column list now leaves out stored and virtual
  generated columns: COPY FROM computes them and COPY TO omits them. Naming a
  generated column is refused with 42P10 before any data is read.
- **COPY entered copy mode for statements that must be refused**, so a client
  streamed the rest of its script as data. A missing or repeated column in the
  column list (42703 / 42701) and generated-column errors are now raised
  before copy mode starts, and the session stays usable.
- **`COPY ... FROM ... WHERE` silently ignored its condition** and loaded every
  row. It is now refused before copy mode; `COPY ... TO ... WHERE` gives
  42601.
- **COPY could not find temporary tables** and failed with "relation does not
  exist".
