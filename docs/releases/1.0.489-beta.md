# BicDB 1.0.489-beta: native read and recovery foundation candidate

This source candidate composes the verified 1.0.488-beta runtime revision
`d8fc122db55300fd019fffe95321403c30ef45be` (superseding the earlier
`34ba460941ddd011534b74d6054d59839bc9c84d` base after its workspace export failure) with the separate native read/recovery
foundation. Main merge, final regression results, binary publication and
verified deployment are separate states. No released binary or deployment is
established by these notes.

The foundation binds native point-read authority to actual metadata quorums,
protected range history and applied local visibility; it fences stale writer,
open and image-install identities and adds scoped same-voter recovery/image
components. The confirmed missing-catalog regression is repaired by refusing
unsafe reconstruction and requiring genuinely fresh durable bootstrap custody
before writer enrollment. Original failing evidence remains immutable.

The larger Abort/joint handoff prototype, public native data-serving lifecycle,
remote native relocation and post-joint recovery are deliberately separate
unmerged work. This source does not add transparent cross-range PostgreSQL SQL,
general multi-range atomic transactions, physical scale-out qualification or
critical-workload admission. The original Azure experiment remains failed.

See [revision-scoped maturity and blockers](../ha-milestone1-status-2026-11-12.md),
[read foundation selection](../design/native-read-foundation-delivery.md) and
[the actual missing-catalog witness](../evidence/native-read-catalogue-loss-2026-11-12/README.md).

SQL/Oracle, PostgreSQL-wire, remaining workspace and stock Rails regression
checks on the versioned candidate, then merge/push and remote-main verification.
Earlier passing cohorts remain tied to their exact source revisions.
