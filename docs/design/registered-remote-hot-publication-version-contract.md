# Registered remote hot publication: source contract and unexecuted gates

This isolated prototype extends source `e6b429aebb94fa2e784121c54891e4ea22bb6c8a`,
including ownership checkpoints `a81c353a07dfcd588030f08c38db98a6e429f0cb` and
`035989946eefb62a62c4627d882dc3fb9f585adf`. It is a source implementation awaiting
its first compile check. No new hot end-to-end case has executed. It is not a
production, cold recovery, controller convergence, SQL or physical scale claim.
The original Azure run remains a failed scale-out qualification.

The original Registered receiver retains its actual A, native/profile-2 final
image and catalogue materialization. It never becomes a legacy local image,
local OLD quorum or initial writer. Original host custody precedes fallible
continuation. Native DECISION attempts retain the complete body, candidate
bytes and actual native xid before first put. Successful native commit, actual
abort and unknown effects remain distinct. A post-write metadata refusal can
reconcile only the same known committed record under a fresh genuine proof;
visible bytes alone do not resolve an unknown native outcome.

The local metadata version is not a distributed lease. Fresh authenticated
Role/OWN quorum evidence, native epoch/dual-quorum promises and ordinary
request-specific Strong barriers remain necessary. The actual MStore
invalidates its version before an authority mutation. Mutation completion may
publish a ready version only after actual successful persistence. A running
failed/dirty version stays poisoned through harmless persistence, nested
failure or no-op heartbeat. Positive metadata read/HostMQ producers refuse it.
Only original actual-open initialization can complete its own initialization.

Phase points are captured from the original attached native metadata Store
outside service/engine locks. Protected native initialization version 1 refuses
a missing point. Explicit legacy initialization version 0 does not acquire a
native-metadata qualification. Identity-only DB/base/catalogue observations
remain separate from current MStore authority.

DECISION, preparation, native bridge, Open, release and first DATA policy use
actual point checks and final short local version gates. Physical readbacks
and original hook/admission/native journal/A scopes precede and remain lexical
through their relevant gate. Final cache/hook/arm operations are concrete memory
operations; native reads, hashes, serialization, callbacks, filesystem work and
retired owner destruction happen outside that gate. The first policy's sealed
candidate borrows its actual native readback/journal and original registration;
a caller cannot substitute a Weak<State> or decoded policy. Its service/cache
and routing slots are borrowed before publication. Same-State survivor Serving
policy remains selected-range scoped. The new target has exactly one local
voter range; other populated range descriptors must remain unchanged and their
native state must remain unknown at this target.

## Same-owner retry lifetime and actual abort health

The Registered FIRST installer retains the actual original host/receiver/DB/slot
lifetime, separately from every finite Role/OWN/policy call. Expiring a first
request does not create a new request or refresh its evidence; a later distinct
call still needs independently fresh proof and the exact already-retained
native candidate/xid/coordinator/guard. Legacy first-policy callers retain their
original finite-caller contract. Process stop, original receiver revocation,
DB replacement or Store-slot replacement still refuses continuation.

A native `abort()` returning success is retained as actual Aborted, separately
from retry permission. Core, actual page-store and actual page-WAL health must
all be healthy before marking that abort retryable, and must be checked again
before a replacement begin. Aborted-on-fenced-storage is neither Committed nor
Unknown, but cannot allocate another native transaction. All outcomes and the
original write/health errors stay in the retained attempt. Actual expiry and
poisoned-storage fixture controls remain unexecuted.

The internal `Legacy` first-policy sum arm denotes the existing protected
Registered-to-local-image policy origin; it does **not** denote metadata-init0.
That origin also retains an actual owned native metadata member and now uses
its immutable native point and actual version gate at WAL/hook boundaries.
Its original finite-caller contract is unchanged. Only explicitly init0 lower
joint fixtures elsewhere retain their separate non-owned-metadata contract.

## Joined custody and unchanged event client successor (source only)

A distinct original-Registered Joined adapter adopts the exact FIRST attempt,
installed guard, coordinator, original A/receiver owner and existing cleanup
worker after the actual Closed socket drains. It does not re-enroll a policy
or cast remote evidence into INITIAL or local OLD authority. Fallible bind or
publication leaves that owner retained and application ingress closed. The
selected range is explicit; another populated descriptor does not obtain a
target native floor or writer grant.

Dispatcher publication holds actual DB/admission/hook/journal, protected
native/catalogue Open and released-generation scopes, and the actual attached
runtime dispatcher and binding slots before the short local metadata version
guard. Its final operation only replaces the binding and marks ingress
published; retired binding destruction follows guard release. Actual fresh
quorum metadata and native epoch/quorum fencing remain necessary. A local
version guard is not a distributed metadata lease.

Readiness status separates observed copy/applied watermarks, observed leader
prefix recovery, and the requirement for a new request-specific Strong barrier.
A follower can bind DATA without pretending to have leader readiness. No status
bit grants a later read; inability to prove Strong must remain unavailable,
never a successful false absence.

Four new `native_registered_fifth_remote_hot_data_` selectors are written for
ordinary unchanged pre-join event-client append/full Strong, lost committed
DECISION reply, real original FIRST caller expiry then fresh same-xid
continuation, and follower DATA binding without fake leader recovery. Each
application intent and returned/uncertain result is retained before assertion.
A failed append is reconciled by a bounded Strong call before its failure is
asserted; subsequent visibility does not retroactively acknowledge it. Internal
SDK wire retries are explicitly unmeasured. The original fixture cases and
per-call budgets remain unchanged. All these new selectors are **uncompiled
and unexecuted** at this source freeze; source inspection and formatting do
not establish a passed behavioral guarantee.

The earlier four through-policy selectors remain separate component gates.
Actual selected-metadata term/config changes at pre/post-WAL and FIRST hook
publication, and a partition/new-leader stale APP/Strong control still require
