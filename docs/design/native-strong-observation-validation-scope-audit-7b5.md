## Smallest proposed scope

Introduce a **new private enforced-native observation scope**, distinct from `NativeReadyObserverReadScope`: Strong observations concern current Serving state and a read stamp, not Prepared/Frozen recovery materialization. Do not cast a read role into `RecoveryRoleAdmission`, acquire a recovery freeze/pin, or reuse a CurrentJointRecovery mutation capability. Incoming requests remain untrusted scope DATA, checked through the existing authenticated sender/request binding and actual kernel state.

The scope would own one actual `NativeImageJournalGuard` and one validated `SourceRangeImageLineage`, borrow the exact DB/Store/service request and original cancellation, and retain the real mutation-gate stamp plus actual service-slot guard and actual writer object captured from that service. It would be !Send, non-Clone/non-Serde, constructor-private, and invoked through a nonescaping/HRTB closure. No scope reference, reusable checked flag, native-currentness token or raw-parts constructor may escape. Only the existing request-bound owned observation could be returned after successful exit validation, retaining its original lifetime/stamp semantics.

For the first implementation, require actual from-birth enforced writer admission. Keep born-v1 component observations on their existing full path; no legacy-to-Strong upgrade or broader recovery qualification follows. The existing Strong consumer must still require all enrolled current voter births/enforcement and its exact installed coordinator/host guard. A freshly fetched replacement writer is not a substitute for the original operation's host guard.

The lock domain is narrowly **actual service mutex → checked DB try-read → short mutation-stamp check → native journal try-lock**, matching existing nonwaiting acquisition behavior. The service borrow protects the raw Store object/mirror; obtain `RangeWriteServiceSlotGuard` from that actual slot, not a cached Store UUID. The journal protects native pending/base/prefix/history/serving/joint/abort records read during the action. The actual `&BicDb` and journal identity must match; retaining only an original directory Weak is insufficient.

No metadata/network wait, catalogue persistence, native page-WAL, row mutation, source freeze or read reservation acquisition belongs inside this scope. Do not hold hook/cache/metadata guards while waiting for the journal. The original Strong coordinator reservation and capacity Operation remain in their current places; a scope must not create another strong Operation owner.

### Mutable entry/exit boundaries

Before and after the action, independently check the **original** request/caller/proof deadlines and cancellation; actual DB open/root/directory and durability health; schema generation/fingerprint; original writer/registration/hook identity and current registry audit matching; actual Store-slot generation/open; and mutation-gate stamp/current readable state. A writer that starts and fails, a freeze/restore, hook reinstall, schema mutation or Store replace/restore must not ABA back into the old read observation.

Use the original captured writer and exact hook/coordinator where required by the existing Strong operation, not only equality among newly fetched phase writers. The scope's native state must still match actual entry/exit R/H/B/native UID and all current/archive/pending/history obligations.
