## Native data integrity

- Compare admitted Decimal operands exactly in native invariant predicates.
- Accumulate native Decimal invariant SUM values without rounding intermediate
  results to the scalar Decimal representation. Scalar arithmetic, Float,
  integer/count operations and individual value admission retain their contracts.
- Repair affected predicate index generations under exclusive database ownership,
  with durable bounded progress, verified publication and recovery. Refuse dirty
  unique generations instead of deleting acknowledged rows. Older readers refuse
  stores requiring the new comparison contract.
- Preserve signed application contracts through explicit closed-store scoped-key
  transitions, retained compatible indexes and fenced package rollback.
- Retain the complete active native invariant semantics during code rollback,
  including predicate, transition and dependency contracts. Matching table fields
  alone do not establish a safe historical code target.
- Authorize the actual RAG resource operation rather than substituting a generic
  operation for its method.

These are generic engine and signed-application capabilities. Product ledgers,
posting schemas and application business rules remain in their owning repositories.

## Validation boundary

The constituent fixes have native Node-driven numeric, generation, old-reader,
atomicity and recovery evidence on their pinned prototype revisions. The composed
1.0.488-beta head requires its own product binary, repeated native Node controls,
and all mandatory repository CI before merge. Earlier passing runs are not a
qualification of this new head. No HA or distributed read qualification is implied.
