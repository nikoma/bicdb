# 1.0.530: full MERGE, grouping sets, FETCH WITH TIES

Part of the PostgreSQL SQL-parity work. Each item is checked against stock
PostgreSQL 18.4 with `fixtures/postgres-compat/pgsql-parity/merge-grouping.cases`
(30 cases, identical output).

## Added

- **MERGE** as in PostgreSQL 18: several `WHEN` clauses with `AND`
  conditions; `MATCHED` UPDATE / DELETE / DO NOTHING; `NOT MATCHED [BY TARGET]`
  INSERT (column list, VALUES with DEFAULT, DEFAULT VALUES) / DO NOTHING;
  `NOT MATCHED BY SOURCE` UPDATE / DELETE / DO NOTHING; table, subquery or
  VALUES sources; `RETURNING` with `merge_action()`, `old` and `new`; error
  21000 when one target row would be changed twice. Writes use the ordinary
  UPDATE, DELETE and INSERT paths, so privileges, constraints, foreign keys,
  defaults and row triggers apply as for those statements. Views, partitioned
  tables, row-security tables and updating a primary-key column through MERGE
  still return 0A000. See `docs/postgresql-merge.md`.
- **GROUPING SETS, ROLLUP, CUBE** and `GROUPING()`, including mixes with plain
  grouping columns and the empty set. See `docs/postgresql-grouping-sets.md`.
- **FETCH FIRST n ROWS WITH TIES** (with OFFSET).
- **Hypothetical-set aggregates** `rank`, `dense_rank`, `percent_rank` and
  `cume_dist` with `WITHIN GROUP (ORDER BY ...)` (one ordering key).
