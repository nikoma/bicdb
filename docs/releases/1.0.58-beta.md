# BicDB 1.0.58-beta

Release date: 2026-08-03

## Destructive node-loss certification evidence

- Advances immutable cluster certification plan, collector state, and report
  formats to version 3.
- Replaces boolean-only failure claims with typed destructive evidence for
  process kill, host power cut, hypervisor crash, and network blackhole tests.
- Requires every snapshot, catch-up, promotion, cleanup, split, merge, backup,
  and index-rebuild trial to bind its active maintenance operation and distinct
  pre-failure and post-recovery checkpoint SHA-256 values.
- Enforces ordered in-window timestamps for failure injection, loss detection,
  old-identity fencing, repair start, policy convergence, and final recovery.
- Validates same-incarnation restart versus strictly higher-incarnation rejoin
  semantics and rejects mismatched recovery identities.
- Requires temporary under-replication to prove the node loss affected real
  ranges, followed by repair and digest verification of every affected range,
  zero final under-replication, and zero range unavailability.
- Requires at least 1,000 successful quorum operations during every outage and
  complete rejection of old-identity write probes.
- Requires a fixed commit watermark, nonzero records, and at least one fifth of
  the selected logical corpus to have identical pre-failure and post-recovery
  SHA-256 digests.
- Requires each failure trial to reference both its exact verified failure
  timeline and checksum artifacts.
- Adds adversarial coverage for forged recovery identity/incarnation,
  unchanged maintenance checkpoints, reordered timestamps, missing repair,
  checksum drift, quorum failure, stale-authority acceptance, and substituted
  artifacts.

This release freezes the destructive evidence contract; it does not claim the
eight production hardware node-loss trials have already passed.
