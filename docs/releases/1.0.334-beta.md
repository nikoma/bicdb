# BicDB 1.0.334-beta

This release makes Carrier application HTTP routing deterministic and keeps
literal endpoint paths from being consumed by typed parameter routes.

## PostgreSQL-compatible application behavior

- Prefer the most specific matching HTTP route, independent of signed manifest
  declaration order. A literal endpoint such as `/patients/search` now wins
  over `/patients/{id}` instead of coercing `search` as a UUID.
- Preserve declaration order when two matching route templates have identical
  specificity.
- Apply the same selected-route semantics when deciding whether a response uses
  the live streaming path, preventing a less-specific streaming declaration
  from changing a literal route's transport behavior.

## Validation

- Added an application-runtime regression covering both literal patient search
  and UUID patient lookup with the parameter route declared first.
- BicDB application-runtime tests: 113 passed, 1 release-only benchmark
  ignored.
