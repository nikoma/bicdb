# BicDB 1.0.338-beta

This release makes Carrier `sql.exec` observe PostgreSQL affected-row results
for CTE-backed mutations and keeps SQL-created UUID resources addressable by
their PostgreSQL-visible UUID.

## PostgreSQL-compatible application behavior

- Return the affected-row count for successful `WITH ... INSERT ... SELECT`
  statements even though the signed statement also contains a `SELECT` action.
- Use BicDB's actual mutation command tag to distinguish command results from
  row-producing CTE queries.
- Store single-column UUID primary keys under their canonical UUID text so a
  Carrier resource read can address a row created through signed SQL in the
  same transaction.
- Transparently decrypt versioned `enc:v2` field envelopes produced by explicit
  Carrier `encrypt(...)` calls while retaining `enc:v1` resource compatibility.
- Fix the WalkNorth EHR prescription workflow's Carrier audit-log write.

## Validation

- Added an application-runtime regression proving a signed statement with both
  `SELECT` and `INSERT` actions returns `HostValue::U64(1)` to `sql.exec`.
- Added a tenant-policy regression covering signed SQL insert, savepoint
  release, and resource read-your-writes for a UUID primary key.
- Extended encrypted-resource coverage across both legacy `enc:v1` storage and
  versioned `enc:v2` Carrier field envelopes.
- Reproduced the complete prescription request against PostgreSQL 18.4 (HTTP
  200) and BicDB 1.0.337-beta (HTTP 400) before the fix.
