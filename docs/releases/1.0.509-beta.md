# 1.0.509-beta: two intermittent test failures fixed at their cause

Test and CI changes only; no product behaviour changes.

- **Fail-closed durability matrix.** A fault named by call count
  (`page_log.sync:60`) was sometimes never reached: with transaction-log
  commit durability only the materializer and checkpoint timers sync the page
  log, so quick writers finished first and the case reported a healthy
  database. The child process now keeps its background threads running until
  the fault fences the database (bounded at 60 s), then requires a late commit
  to be refused as a durability failure. A regression test with two commits
  per writer fails without the change.
- **Cold-reopened promoted voter.** The test read the leader from the first
  ready status, which can precede the retained leader's first heartbeat (a
  strict cold reopen clears the volatile leader label). It now waits up to
  15 s for the reopened process's own status to name a leader, and still
  requires that leader to be `n0`.
- **Workflow.** `core_target` runs one Core integration-test target, with
  `core_target_repeat` (1-50) repeating it and reporting a pass count.

The third intermittent failure examined (`ha_failover_cli`, "no new primary
after the kill") was a fixture port collision; its fixture was reworked in
1.0.506-beta and is not changed here.
