# BicDB 1.0.321-beta

Phase 4 ships the industry-neutral App Root and fleet lifecycle boundary.

## Added

- New `bicdb-fleet` crate with no database, SQL, application-runtime, Cell, or
  key-provider dependency.
- Immutable content-addressed artifact registry with no-overwrite publication,
  bounded reads, symlink refusal, digest verification, and fsync.
- Distinct publisher, security, builder, transparency, and rollout trust
  domains; one public key cannot fill multiple roles.
- Publisher/security/two-builder release threshold and per-application
  reproducible-build witnesses bound to source, recipe, and package output.
- Hash-chain transparency inclusion proofs ending at a security- and
  transparency-approved checkpoint.
- Explicit bounded rollout cohorts, observation gates, concurrency limits, and
  per-Cell tickets bound to the exact manifest transition.
- Runtime/schema/record-format compatibility and minimum-safe release policy.
- Signed predecessor requirement for non-initial Phase-4 transitions.
- Cell-local fsynced convergence receipts with an anchored hash-chain head.
- `--fleet-trust-policy`, `--fleet-activation-bundle`, and
  `--previous-manifest`, plus equivalent `BICDB_CELL_*` environment paths.

## Security ordering

`CellRuntime::open` verifies fleet authorization after immutable Cell/volume
identity and running-binary checks, but before requesting a Cell key, opening
storage, or evaluating application artifacts. Migrations still execute once per
Cell through the Cell-local application runtime; fleet orchestration has no
database handle.

## Verification

- Threshold/common-mode signer tests.
- Wrong-Cell/wrong-manifest activation refusal.
- Immutable registry and symlink tests.
- Transparency, compatibility, cohort, ticket, and dormant-policy checks.
- Convergence receipt chain/tamper tests.
- Cell boundary proof that an invalid fleet bundle is rejected before a key
  provider can be invoked or a database path can be created.

Regulated-data production admission remains explicitly denied.
