# Opt-in local namespace lineage foundation

This source change adds durable **physical-local** namespace identities. It does not activate Strong reads, certify a range image, repair the relocation handoff witness, or qualify HA. Default stores and ordinary create/open retain `local_namespace_id: None`, omitted from serialized metadata.

`BicDb::activate_local_namespace_identity_v1` explicitly fsyncs the sticky `local_namespace_identity_v1` reader/writer fence before assigning missing UUIDs and persisting the catalog. Retrying migration preserves every existing identity. A flag-only interrupted activation stays readable, but missing IDs remain untrusted until explicit migration completes. Active catalogs and subsequent format replacements force fsync independently of the row-fsync configuration.

Rename and same-backing metadata restoration preserve identity. Actual hard drop and backing recreation create a fresh identity, including logical DDL compensation. A source replica's UUID is never adopted: missing target namespaces receive their own local UUID; existing targets preserve their current one. IDs are excluded from portable schema fingerprints, bundle checksums, range snapshot chain hashing and outbound metadata. Strict local metadata equality still includes identity.

The separate sticky `range_image_install_v1` primitive and validated activation query are provided for the image-install owner. Neither flag is enabled by default or implies image readiness. Future image receipts must separately bind the local ID, actual image and certified range prefix; DDL invalidation, authority acquisition and freshness remain independent requirements. Local flags must remain excluded from replicated reader capability lists when integrating with later sources.

All format metadata read/merge/write paths share the canonical-root in-process feature lock. This prevents concurrent capability installation, routine flush, initialization and migration from overwriting a newly durable flag. This lock is not a substitute for the database's exclusive writer/process ownership contract.

The baseline is source `226d9fd80ecd9dbf249fd4fee5984b61311fed47` (1.0.466-beta). Validation results and exact commands are recorded in `validation.json`. The old-reader check uses the immutable source-463 CLI SHA-256 `840f0124f27a1a7695c4b2b0c72b05a262456802af65e063cff12242559e2f7d`: an unactivated store opens, each new flag is independently refused, and all database bytes are unchanged after refused opens. This artifact-dependent case is ignored in the default unit suite and was explicitly executed with `--ignored`; it is not a claim of CI coverage.

Tests exercise both storage modes, interrupted flag-only migration, rename/reopen/recreation and logical metadata restoration, actual snapshot and commit-frame import into missing/existing targets, portable-versus-local equality, invalid identity rejection, concurrent flag/flush publication and the downstream atomic-writer fsync argument. These are local implementation tests and source-level ordering checks, not a VM power-loss or physical durability campaign.

Compiler/test stdout and stderr are retained as deterministic gzip streams under `checks/`; decompression reproduces the original bytes, including ordinary compiler warnings. Existing warnings were retained rather than suppressed. The guard log records every sample; final focused compile/test retained at least 19.44 GiB available RAM with no pause or termination. The reusable shared dependency target remained about 11 GiB and was left available for the next coordinated build.
