# BicDB 1.0.16-beta

Release date: 2026-08-03

## Bounded point-in-time replay

- Replaces PITR's whole-database `DbSnapshot` plus full-collection vectors with
  ordered, bounded audit-event and delete batches.
- Adds `BackupPitrReplayLimits` and CLI controls for record count, event count,
  and serialized event bytes per batch. Invalid zero or excessive limits fail
  before restore begins.
- Counts serialized audit events through a rejecting writer before cloning their
  record values, so an oversized event cannot bypass the byte ceiling.
- Clears only collections represented by the durable record-audit stream. A
  collection with changes after the target is still cleared, while unrelated
  unaudited catalogs are not destroyed.
- Applies trusted restore mutations through offline transactions that bypass
  client policy and distributed write admission without weakening either path
  for a running database.
- Covers embedded and `server_paged` restores, including one-record/two-event
  test batches that prove progress and exact removal of post-target rows.

The durable event catalog is still resident when a database opens. This release
bounds PITR's additional replay working set; paging the event catalog itself is
tracked separately before claiming bounded PB-scale recovery end to end.
