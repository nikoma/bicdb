# 1.0.499-beta: native HA candidate composed onto main

The native high-availability work that had lived on separate branches is now
part of `main`: the native multi-node host, metadata-owned ingress, remote
target image transfer, hot one-peer-loss recovery and the fifth-receiver
fences and custody controls.

Fixed while composing:

- hot one-peer-loss recovery and repeat recovery: a routing read-guard
  self-deadlock, a permanent veto from a lagging follower, majority starvation
  during cooldown, and writes that became unknown outcomes behind a silent voter;
- a node whose incoming listener had stopped can no longer hold metadata
  leadership;
- two tests that asserted more than the product guarantees (anchor resolve
  after caller-budget expiry, four-process registration with a quorum of three).

CI now runs the native multi-node tests in their own serial job; the parallel
core job skips exactly those tests, so every test still runs.

Not qualified by this version: a registered fifth node still receives no data
(the transfer path is not built), and the physical four-to-five node scale-out
experiment remains failed and has not been rerun. See
`docs/ha-milestone1-status-2026-11-12.md`.
