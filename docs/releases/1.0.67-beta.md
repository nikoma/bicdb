# BicDB 1.0.67-beta

Release date: 2026-08-04

## Durable, governed server-paged vacuum supervision

- Adds a tick-driven `PagedVacuumSchedule` with immutable store and operation
  identities, a strict format version, canonical SHA-256, a hard state-file
  bound, and exact inclusive cursor persistence.
- Publishes schedule transitions atomically with configured fsync and a parent
  directory sync. A crash after page mutation but before publication repeats
  the page safely rather than skipping it.
- Serializes local supervisor transitions and fences every tick, pause, and
  resume with the active operation UUID.
- Admits each page step through the node governor's `Compaction` lane using an
  explicit memory, in-flight-I/O, CPU, and rate-charge declaration.
- Persists monotonic due times, saturation deferrals, bounded exponential
  failure backoff, failure ceilings, operator pause/resume, completion, last
  report, and cumulative published progress.
- Rejects unsafe, empty, oversized, symlinked, checksum-mismatched,
  unknown-field, clock-regressed, stale-operation, and foreign-store state
  before page work.
- Detects an immutable byte envelope that cannot advance its current page and
  pauses instead of spinning indefinitely.
- Exposes start, status, one-step tick, pause, and resume through `BicDb`.
  Embedded-memory databases reject these APIs without creating state.
- Replaces core index-maintenance uses that treated `vacuum(usize::MAX)` as an
  unbounded completion guarantee. Foreground maintenance now loops over
  explicit bounded steps and detects a non-advancing cursor.
- Adds adversarial tests for lost cursor publication, inclusive replay,
  process reopen after every page, resource saturation with zero page calls,
  retry/pause/resume, operation fencing, clock regression, corrupt and unsafe
  state, store mismatch, and completion over 600 deleted wide records.

The remaining roadmap work is to migrate whole-file/extent rewrite and the few
remaining legacy cleanup operations behind durable supervisors, then certify
the complete maintenance envelope on the physical 1 TB, 5 TB, and 20 TB
campaigns.
