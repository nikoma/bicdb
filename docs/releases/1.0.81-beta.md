# BicDB 1.0.81-beta

This release removes complete-WAL materialization from server-paged startup and
makes page-image recovery memory independent of WAL length.

## Streaming recovery

- Replaces separate whole-log tail validation, transaction-outcome extraction,
  and replay materialization with exactly two ordered streaming passes.
- Reuses one record body bounded by the durable database page size plus the
  fixed 16-byte WAL prefix. The global `MAX_WAL_RECORD_BYTES` ceiling is one
  1 MiB maximum page plus the 40-byte header/prefix overhead.
- Validates record magic, reserved bytes, kind, bounded length, checksum, and
  contiguous LSN ordering before exposing a record to recovery.
- Checks a claimed body length before allocation, so a forged multi-gigabyte
  length becomes a rejected suffix rather than an attempted allocation.
- Holds the WAL lock from tail validation through truncation, closing the race
  in which an append could previously land between `read_all` and `set_len`.

## Replay and MVCC integration

- Discovers final commit/abort outcomes and the redo point during pass one,
  then applies only committed page images at or after that point during pass
  two.
- Lends the scanner's mutable payload directly to the page writer, avoiding a
  second page-sized allocation during replay.
- Moves the ordered final outcome map directly into the recent MVCC status
  table rather than copying it through an intermediate vector.
- Fails closed if the valid record count or final LSN changes between passes.
- Classifies page or transaction identifiers that would overflow runtime state
  as WAL corruption instead of wrapping or panicking.
- Preserves idempotent replay, torn-tail recovery, uncommitted-row invisibility,
  and contiguous append resumption.

## Operational contract

- Advances the strict paged-storage snapshot to format version 8.
- Adds recovery scan-pass count, peak validated record bytes, and final outcome
  cardinality to the retained report and fixed-cardinality operational,
  Prometheus, doctor, and diagnostic-bundle surfaces.
- Keeps `Wal::read_all` as an explicitly materializing compatibility/diagnostic
  API while removing it completely from database open and recovery.

## Verification

Tests cover the complete WAL and crash-recovery suite, exact two-pass reports,
direct committed replay, uncommitted and aborted skipping, repeated idempotent
replay, redo suffixes, checksums and LSN ordering, torn-tail append resumption,
and a forged `u32::MAX` record length rejected before allocation. A 20,000-page,
10+ MiB suffix retains a reported 552-byte peak record at a 512-byte page size,
more than a 10,000:1 WAL-to-record ratio.
