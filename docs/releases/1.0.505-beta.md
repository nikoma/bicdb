# BicDB 1.0.505-beta

`ClusterEventClient` append and typed Get retain the actual routed-operation
error when later topology discovery fails. An earlier typed
`CommitOutcomeUnknown` keeps its sequence, transaction identity, incarnation
and detail across later operation refusals, discovery errors and deadlines;
a later refusal does not prove rollback. Discovery without a preceding
operation retains its no-member error. Retry counts, backoffs, request budgets,
routing policy, stable event keys and successful read checks are unchanged.
Existing optional RPC evidence retains the secondary discovery exchanges.

The [source-pinned SDK evidence](../evidence/event-client-error-preservation-8352-2026-11-13/README.md)
records all twelve selected tests passing at runtime commit `8352e3d6b`, source
1.0.500-beta: six new error-preservation regressions and six existing retry
tests, with all-target and workflow-consumer compilation. The new tests cover
actual loopback TCP with mock responses plus direct typed-error retention;
they do not commit application data or qualify HA. The integrated 505 head's
validation is separate from that historical result.

This is an SDK diagnostic/correctness fix with synchronized source-version
metadata. It does not establish the cause of earlier failed first-ACK runs,
automatic recovery, physical scale-out, a release binary or a deployment.
