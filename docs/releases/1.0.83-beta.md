# BicDB 1.0.83-beta

## Attributable WAL-recovery certification

- Extends `bicdb bench paged-recovery` evidence with the exact executable byte
  size and SHA-256, BicDB/source identity, OS and architecture, kernel, CPU,
  logical CPU count, host memory, filesystem source/type/mount/options/device,
  database path, and explicit cache preparation.
- Hashes the executable with a fixed 1 MiB buffer and bounds procfs input,
  operator strings, and offline report size.
- Adds `--require-release-evidence`, which fails before fixture creation unless
  fsync, a full source revision, controlled cache state, cache preparation, and
  the required host/storage attribution are present.
- Adds a canonical whole-report SHA-256 and
  `bicdb bench paged-recovery-verify`. Verification rejects symlinks, oversized
  or malformed reports, unknown fields, inconsistent run bindings, edited gate
  outcomes that disagree with their measurements, and checksum mismatches.
- Keeps the physical production-hardware matrix explicitly open. This release
  makes its evidence reproducible and tamper-evident; it does not manufacture
  production measurements.
