# 1.0.537: DETAIL, HINT and NOTICE lines, geometric columns, grouping-set aliases

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/c4.cases` and `g.cases`.

## Added

- **DETAIL, HINT and NOTICE lines as in PostgreSQL:**
  - Constraint violations carry PostgreSQL's DETAIL: `Key (a, b)=(1, x) already
    exists.`, `Key (a)=(1) is not present in table "t".`, `Key (a)=(1) is still
    referenced from table "c".`, exclusion conflicts and `Failing row contains
    (...).`. Row values are included only when the role may read them
    (superuser, or SELECT on the relation with no row-level security applying);
    otherwise the DETAIL is omitted or value-free.
  - NOTICEs for `... does not exist, skipping`, `... already exists, skipping`,
    `drop cascades to ...` and `truncate cascades to ...`; WARNING severity for
    COMMIT/ROLLBACK outside a transaction and BEGIN inside one; RAISE severities
    as in PostgreSQL.
  - A RAISE NOTICE in a trigger during COPY FROM STDIN or in a deferred trigger at
    COMMIT is delivered instead of failing the statement.
- **Geometric column types**: `point`, `line`, `lseg`, `box`, `path`, `polygon`
  and `circle` work as columns in both storage modes, with PostgreSQL's input
  grammar, subscripts and typed untyped literals.
- **Grouping sets over aliases, positions and constants**, including FROM-less
  queries (`SELECT 1 AS one GROUP BY ROLLUP(one)` returns PostgreSQL's two rows).

## Changed

- **`DROP TABLE` / `DROP VIEW` with dependent views** refuses with 2BP01, a
  DETAIL per dependent and PostgreSQL's HINT, unless `CASCADE` is given, which
  drops the views. Before, the table was dropped and its views were left
  broken. Databases using the Oracle profile keep the previous behaviour.
- `ALTER TABLE IF EXISTS` on a missing table skips with a NOTICE instead of
  failing; TRUNCATE's foreign-key refusal uses PostgreSQL's 0A000 with DETAIL
  and HINT.
