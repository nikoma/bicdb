# BicDB 1.0.324-beta

Phase 7 ships the industry-neutral cross-Cell object-grant boundary. Regulated
production-data admission remains closed.

## Shipped

- Added `bicdb-cell-grant`, a bounded deterministic-CBOR protocol with mutual
  Cell trust pins and four disjoint threshold authority roles.
- Added exact object, purpose, application, schema, lifetime, count, byte,
  predecessor, epoch, and redisclosure constraints with no wildcard query
  language or executable import type.
- Added independent random object DEKs, XChaCha20-Poly1305 payload encryption,
  and RFC 9180 X25519/HKDF-SHA256/ChaCha20-Poly1305 recipient envelopes.
- Added source export signatures, package chains, replay protection,
  threshold revocation, content-review evidence, and honest non-erasure
  semantics.
- Added serialized, crash-safe source and recipient ledgers inside the
  encrypted Cell database. Recipient bytes and immutable provenance commit in
  the same transaction.
- Integrated Phase 7 into the signed `CellManifest`, pre-key startup ceremony,
  active-primary runtime, reduced CLI, and `BICDB_RUNTIME_MODE=cell`
  environment launcher. No remote database handle was added.
- Added adversarial tests for wrong recipients, tampering, policy substitution,
  replay, role confusion, ambiguous encodings, revocation, ciphertext-at-rest,
  and concurrent durable transition races.

## Deliberate limits

The software recipient key is a reference backend. Production HSM/attestation,
opaque transport/relay evidence, complete protocol fuzzing, independent HPKE
and security review, attested isolation, and every applicable Phase-8 gate
remain mandatory. `regulated_data_admitted` is therefore still `false`.

See [the Phase 7 operator contract](../cell-runtime-phase7.md).
