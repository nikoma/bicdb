# 1.0.549: server-side COPY to and from files and programs

Checked against stock PostgreSQL 18.4 with 28 probe cases
(`fixtures/postgres-compat/pgsql-parity/q.cases`), all with the same output.

## Added

- **Server-side COPY**: `COPY t [(cols)] FROM 'file'`, `COPY t|(query) TO
  'file'` and `COPY ... FROM/TO PROGRAM 'command'`, with every format and
  option COPY STDIN/STDOUT takes (text, csv, binary, HEADER, HEADER MATCH).
  PostgreSQL's privilege checks: the effective role needs the privileges of
  `pg_read_server_files`, `pg_write_server_files` or
  `pg_execute_server_program` (a superuser has all three), with PostgreSQL's
  messages. PostgreSQL's file and program errors: 42602 for a relative COPY TO
  path, 58P01 for a missing file, 42809 for a directory, 38000 `program "..."
  failed` with the exit status.
- **Operator controls, off by default**: `bicdb serve --copy-server-files-dir
  DIR` (repeatable) enables file COPY below DIR; `--allow-copy-program`
  separately enables COPY PROGRAM. Neither is a SQL setting. Without them COPY
  fails with 0A000 ("... is not allowed in this environment"). Files must be
  absolute, contain no `..`, lie below an allowed directory and are opened
  component by component with `O_NOFOLLOW`; the file must be a regular file
  with one hard link. Programs run through `/bin/sh -c` in their own process
  group with an empty environment apart from `PATH`; cancellation and the
  query timeout kill the group. COPY in a routine is still refused. See
  [server-side COPY](../server-side-copy.md).
- `COPY BINARY table`, the old spelling of binary COPY.

## Fixed

- Binary COPY FROM of a float4 or float8 column failed with 22P02.
- In a multi-statement query, the statements after a COPY were read as COPY
  options and never ran.
- A table named `binary` was copied in binary format.
