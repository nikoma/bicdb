# BicDB 1.0.1-beta

Release date: 2026-07-31

BicDB 1.0.1-beta introduces the first production Carrier application-runtime
profile. A signed ABI-v2 package can install resource contracts, run trusted
resource operations and sandboxed business logic against the same in-process
BicDB, expose host-owned HTTP routes, supervise durable work, and atomically
upgrade or roll back as one coherent snapshot.

## Highlights

- Adds the versioned, capability-mediated ABI v2 while retaining ABI v1.
- Adds immutable actor contexts and unforgeable invocation-scoped transaction,
  savepoint, mutation, secret, blob, delivery, and stream handles.
- Enforces native `MutationGrant` policy below Rust, SQL, and pgwire mutation
  entry points, including tenant/workspace/version/column/row budgets,
  append-only policy, commit validators, audit evidence, and durable outbox
  publication.
- Adds signed application packages with exact dependency locks, artifact
  hashes, provenance, SBOMs, durable staging, atomic activation, coherent
  rollback, and readiness checks.
- Adds host-brokered database, service, broker, clock/random, secret/crypto,
  policy-controlled HTTP egress, streaming blob, realtime, and bounded
  observability capabilities. WASM receives no WASI, socket, filesystem,
  environment, or raw database authority.
- Adds host-owned HTTP v2 routing, JWT/OIDC authentication, TLS, trusted proxy
  policy, CORS/CSRF, bounded bodies and headers, SSE/response streams, rate and
  admission controls, cancellation deadlines, OpenAPI aggregation, workers,
  schedules, and graceful draining.
- Adds signed resource contracts and one generic Carrier resource interpreter
  for CRUD, UPSERT, filtering, JSON paths, search, sorting, pagination, soft
  delete/restore, optimistic concurrency, idempotency, policy checks, field
  redaction, audit, and events.
- Adds native multi-field raw-text FTS projection. Resource contracts index
  their declared source fields directly; no duplicate application
  `search_text` column or external tokenizer is required.
- Adds `bicdb app` install, stage, validate, activate, upgrade, rollback,
  disable, remove, inspect, graph, route/service/worker/schedule inspection,
  doctor, diagnostics, and combined pgwire/HTTP serving commands.
- Reuses precompiled modules and engine/linker state, bounds per-plugin and
  per-route concurrency, keeps stores isolated, moves synchronous Wasmtime
  execution off the Tokio reactor, and records bounded operation timings.

## Compatibility profile

The accepted profile is `bicdb-application-v2`. Unsupported Carrier features
fail package validation rather than degrading silently. In this release,
repeatable-read/serializable isolation, arbitrary SQL, unrestricted
PostgreSQL-specific extensions, inbound request streams, WebSocket callbacks,
and online row rewrites are rejected. The exact supported surface and security
contract are normative in
[`application-runtime-abi-v2.md`](../application-runtime-abi-v2.md).

## Evidence

The embedded vertical slice covers a tenant- and workspace-scoped resource,
JWT actor construction, CRUD/UPSERT/search/filter/sort/page, role/scope checks,
RLS, redaction, optimistic versions, idempotency, native grants, OpenAPI,
audit/outbox events, consumer metadata propagation, package activation,
upgrade, rollback, and process reopen. Dedicated tests cover forged handles,
undeclared authority, dependency cycles and privilege intersection, deadlines,
oversized FTS tokens, savepoint truncation, outbox recovery/deduplication, and
SQL/pgwire write bypass attempts.
