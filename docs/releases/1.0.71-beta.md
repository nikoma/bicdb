# BicDB 1.0.71-beta

This release makes server-paged MVCC-chain integrity verification bounded and
restartable.

## Bounded verification

- Adds an inclusive serialized key cursor and explicit per-step ceilings for
  keys, total versions, versions per chain, fixed-header bytes, cooperative
  duration, fault-sample count and bytes, and cursor-key bytes.
- Releases the structural read lock between keys while re-resolving each
  current chain head under the lock.
- Returns exact stop reasons, progress counters, completion, and a cursor that
  can be checkpointed and resumed after reopening the database.
- Rejects invalid envelopes, unknown serialized fields, and cursor keys above
  the configured and hard limits.

## Wide-row safety

- MVCC inspection now reads only each stored version's 30-byte header prefix.
- Overflow-backed row payloads are no longer materialized merely to follow a
  version chain.
- Fault samples have independent hard count and aggregate serialized-byte
  limits; excess samples are counted rather than retained.

## Public integration

- `PagedStore`, `PagedRecords`, and `BicDb` expose the same bounded step
  contract.
- Embedded-memory mode rejects the paged-only operation explicitly.
- The exhaustive structural verifier remains available for offline use and is
  not represented as PB-safe by this release.

## Verification

Tests cover multi-step exact coverage, strict serialization, invalid bounds,
oversized cursors, restart resumption, pathological per-chain limits,
overflow-backed 256 KiB versions, bounded page reads, public API forwarding,
and embedded-mode rejection.
