# Root-local bootstrap fence and per-name association: implementation contract

This is a refinement of [the deferred-final-tail design](bootstrap-deferred-final-tail-7c.md), pinned to its source-only commit `b77f1dad3900e36fa89b7e3e94efdf986db85df2` and runtime baseline `7c77418656a41ec6e25c7601319e061c328f48e1`. It specifies lock/record ordering before the implementation is wired. No new protocol behavior, compilation, runtime or crash qualification has passed. Source work in the isolated implementation branch is incomplete and is not made authoritative by this note.

## Two actual exclusion domains

Use a root-local namespace kernel SH/EX file and persistent local physical identity, plus per-name parent slots. These have different purposes; neither is metadata/native authority.

The root-local domain follows a physical root through a rename. It is enrolled under the actual CLOSED root/Page claims and physical EX; its identity/kernel inode is stable, existing-only for an enrolled profile. It supplies the common SH retained by existing Core and raw Page child IO. Root-local control state is not portable backup payload. Verified restore ownership strips source physical identities and creates the candidate's new root identity and local kernel domain before copied enrolled FORMAT can be used. It never copies the source's lock inode or assigns the source physical identity to a target.

A per-name parent slot survives root absence and binds exact parent/name, install generation, original/candidate physical IDs and immutable Stage/Final digests. Only creation, Stage and Final need to create or mutate it. Normal existing-root opens can read a known parent association without new parent writes. A writable existing root in a read-only parent must not be forced to create parent metadata merely to open. Use independent sibling slot directories keyed by target component, with exact component checks; avoid one parent-wide lock held across data IO or archive restore. A private fully initialized allocation can be atomically no-replace published as a new slot; a malformed existing slot is not a fresh allocation.

Root-local identity includes an immutable physical allocation ID and enrollment-domain ID. A current-name slot is a separate association: an installed candidate can retain its physical allocation/enrollment identity after it moves from its staging name. It does not become the original target identity. Current root/name association must be checked from the journal; equality of a copied source identity is never permission.

## Admission before effects, including the no-slot race

[Core currently runs Finish before FORMAT and root creation](https://github.com/nikoma/bicdb/blob/7c77418656a41ec6e25c7601319e061c328f48e1/crates/bicdb-core/src/db.rs#L10823). Its new entry must check a known parent association and root-local pending state before effects, then repeat the matching intent/identity check under its SAME actual DirectoryLock before gate initialization/recovery writes. A missing root-local marker is not proof there is no parent FI. An originally absent target requires actual per-name reservation BEFORE mkdir; a present but different normal root is a conflict, not an old target discovered later.

Normal existing-root startup can take the actual root claim first when it must enroll a legacy root, but it must recheck the parent intent before creating control/gate files. Final cannot publish an armed FI while another real Core root claim remains. A normal opener that passed an earlier absent-parent-slot preflight must see the later FI under the root-local SH/post-claim recheck or fail the actual closed claim before effects. A new parent slot created after preflight is not ignored.

[PageStore::open currently creates parents before its physical gate](https://github.com/nikoma/bicdb/blob/7c77418656a41ec6e25c7601319e061c328f48e1/crates/bicdb-page/src/manager.rs#L858). The new shared layer must run before that mkdir/gate write, including the actual PagedStore constructor and maintenance/conversion entry points which can create paths earlier. It must resolve existing aliases to actual ancestry and inspect controlled ancestors, not only `db/paged` or a new standalone child's own slot. An enrolled Core root's local namespace SH must be retained through descendant data IO. Candidate/predecessor reservations also deny ordinary IO at those names. Creating a deeper slot cannot hide an ancestor FI. Dangling aliases, replaced parents and changed enrolled inodes refuse; no `None == None` birth or lossy component-key equality.

Normal data IO uses SH, so same-root readers/writers remain compatible; an exclusive DirectoryLock per IO would introduce false contention. Final uses EX, without upgrading its own SH. In a race where a name association can appear after the initial probe but before the data kernel lock, recheck after actual acquisition before IO. Do not block acquiring namespace SH while holding data SH if a finalizer can hold namespace EX while waiting for data EX: use the established lock order, a nonblocking refusal/restart inside the SAME original acquisition window, or the always-present enrolled root-local SH. No request deadline or kernel wait budget is restarted.

## Actual custody and lexical reentrance

The order is parent/name admission in a deterministic component order; actual closed root and conventional Page DirectoryLocks plus backup owner; root-local namespace EX; actual physical EX. Release SH before EX acquisition. Any variant needed by existing lock orders must be checked for cycles before wiring; no mutex/DB/version guard can be carried into a new wait on a lower-order owner.

The namespace EX control-file owner alone cannot admit data IO. Its explicit lexical borrow also requires the SAME actual DirectoryLock at the expected physical root and its current identity. Keep a separate non-mintable borrow lifetime, not only a UUID/pointer or `exclusive` flag. A nested SH may retain the actual EX descriptor but must retain only weak authorization to that closed-root borrow; dropping the original borrow must deny fresh nested IO even if an older read/kernel scope still owns a descriptor. The borrow is thread-bound. It cannot be manufactured from JSON or moved into a cold request. The actual physical EX uses its existing explicit lexical borrow too; a new SH underneath one's own EX is prohibited.

All guards borrowed from startup's actual root claim must end before the owner is moved, or borrow an original local Arc of the SAME DirectoryLock while only a clone goes into Core's existing field. No strong BicDb Arc, callback retaining its own DB, or claim inside a returned Stage observation may keep the old process open across its own restart. The actual source [`restart`](https://github.com/nikoma/bicdb/blob/7c77418656a41ec6e25c7601319e061c328f48e1/crates/bicdb-pgwire/src/high_availability.rs#L70) only requests shutdown; Final still needs actual closure.

Before directory moves, drop lexical path-bound IO borrows. Keep SAME root/Page claims and parent namespace EX through the moves; retain the actual kernel EX only for the effects it legally protects. Drop old named bindings before acquiring new-name bindings, revalidate SAME moved root identity/claims, then resume IO under a fresh actual local domain at that name. Opening the newly installed name while an old binding still occupies its process registry path can otherwise falsely bind the candidate to the predecessor inode. No unprotected normal IO gap is allowed: parent reservations and durable root-local pending markers remain active through the binding handoff.

## Immutable records and arming order

Stage still permits the SAME live original target's existing activity. Its immutable verified SOURCE bytes are saved before tail synthesis; SI binds the original allocation, candidate and selected archive. It does not preserve a staging-time OLD HA head as final authority. Both restore codecs must keep their actual verified owners through candidate identity/source descriptor publication; a copied metadata flag is not that producer.

After actual original/candidate/predecessor matching and CLOSED claims plus both EX domains, derive FI from latest OLD head and immutable SOURCE. Native replacement still refuses without the missing actual required-ACK-prefix/accepted-lineage minter. The arming sequence is:

1. Write immutable FI plus exact SOURCE/OLD/post-tail/preimage descriptors under the actual parent-slot owner. Fsync the file, slot directory and required parent entry. Keep actual IO returns. A visible file after failed sync is not old success.
2. Publish and durably sync root-local `FinalPending` on the original FIRST (if present), then candidate. Each marker binds exact FI hash, install/generation, parent-slot identity and actual physical root identity. All affected existing roots' pending markers must be known durable before any tail or rename. Originally absent target has no original local marker; its durable parent reservation protects the missing name.
3. Publish/sync the parent slot's armed `FinalPending` pointer to that SAME immutable FI. A Stage pointer, FI file by itself, or a queue response is not an armed install.
4. Only after both root-local pending state and parent armed state are durably established may the exact candidate tail/rename journal enter effects. Retain actual owners through final checks. A failed sync cannot be inferred successful from equal bytes.

The published state contains DATA only. On restart the new finalizer reacquires actual closed claims and EX, validates the exact records and actual placements, and obtains NEW barriers; it never resurrects the old request or native authority.

| Cut | Safe interpretation / next actual operation |
| --- | --- |
| FI blob visible but its original sync failed; no root markers or armed parent pointer | No tail/move is permitted. Preserve the original error. A new same-owner finalizer can prove new durability only after exact latest-OLD/candidate revalidation. If OLD changed, do not silently reuse the stale FI. |
| Known durable FI blob, no markers yet | Unarmed draft, not install permission. SAME original live activity may have advanced after the call ended. A new finalization must validate latest OLD. Abandoning/superseding an unarmed draft requires proof all roots are unarmed and candidate remains exact SOURCE state; preserve the prior draft/evidence. |
| Original local pending known durable, candidate pending missing or parent pointer still SI | Original ordinary opens refuse. With SAME FI and closed claims, recover the exact marker-before-parent-pointer state and obtain new barriers. No tail was legal yet. Do not remove the original marker as a timeout rollback. |
| Candidate pending durable (and original pending if applicable), parent pointer not armed | Same incomplete arming recovery; ordinary candidate opens are reserved/refused. Marker presence alone never permits mutation. |
| Root-local pending references missing/corrupt/different FI or wrong parent slot | Fail closed and preserve evidence. Do not manufacture a replacement FI or clear the root marker from a path/ID. |
| Parent armed pointer exists but any required root pending marker is missing/different | Fail closed before IO; even if this should be unreachable by the ordering, do not default missing markers to healthy. |
| All exact arming state valid | Same-owner finalizer can perform new barriers and the strict one-way tail/rename protocol. |

An old FI which captured a prior head cannot become a current grant merely because all IDs still match. For a proposed unarmed-draft supersession, the source-side proof must include parent still Stage-only, all exact original/candidate local states unarmed, candidate still SOURCE and no journaled effect. If those facts cannot be proven, refuse. No generic unknown reset or new-attempt replay is authorized.

## Exact tail and move states

Avoid the current [`remove HA then write new HA`](https://github.com/nikoma/bicdb/blob/7c77418656a41ec6e25c7601319e061c328f48e1/crates/bicdb-core/src/db/ha_bootstrap.rs#L121) intermediate. Atomically replace HA directly from its exact verified SOURCE body (or its saved explicit absence) to the exact FI post-tail. Treat removal of the source replication-state file as a separately named exact transition. FI enumerates only these saved file states and exact post state; arbitrary absence/default Standby or a newly synthesized body is not a recovery match. Every temporary file must be task-owned/bound or preserved/refused, not broadly excluded from a digest.

Repeat synthesis from immutable SOURCE and immutable final OLD, never the prior post-tail. If a file/rename/sync returns Unknown, preserve it. A fresh same-owner barrier can establish new durability of the permitted current state; no reader can rewrite the original failed fsync return to Ok. Candidate publication still needs exact final tail, no-replace renames, parent durability and durable Committed. Keep the matching predecessor until the permitted commit/retirement cut; a closed tree at its path is not the predecessor.

After candidate install and known parent Committed, clear the candidate's local pending fence only under actual installed ownership and NEW local durability; never open it first. Keep the original predecessor locally blocked until its matched cleanup. Committed cleanup must not rewrite a later healthy candidate tail or treat ordinary candidate progress as proof a new original install succeeded. If the existing API keeps all cleanup before normal Core open, retain that ordering; any later cleanup lane needs historical committed-install evidence plus exact current physical identity, not stale whole-head replacement authority.

## Remaining implementation/qualification gates

This note does not implement the architecture. The WIP low-level source is not exported/wired and cannot substitute for the complete Core/Page/restore/caller chain. Every parent/root read, allocation, IO entry and kernel acquisition still needs a concrete source inventory and genuine controls before a coherent freeze.

The new protocol cannot claim a durable parent barrier from current Core's [Windows/wasm no-op sync_parent](https://github.com/nikoma/bicdb/blob/7c77418656a41ec6e25c7601319e061c328f48e1/crates/bicdb-core/src/storage.rs#L2347). Preserve existing ordinary behavior while identifying a real supported barrier or an explicit unsupported new-protocol lane; do not silently mark it durable. No Windows/macOS runtime result is claimed. Likewise a new FORMAT flag cannot protect old pre-FORMAT installers; the b77 pinned deletion/old-reader limitations remain.

Required controls include original absent/existing positives; known parent created between preflight and Root/Page admission; ancestor raw Page creation before mkdir/gate; alias/parent substitution; marker-before-parent-pointer and parent-pointer-with-missing-marker; every real process crash at arming/tail/move/cleanup; original live post-Stage vote and ACK; same-name unrelated target/predecessor; actual read-only-parent normal existing open; unrelated-root progress under a stalled finalizer; same-thread nested EX borrow and ended-original-borrow refusal. Original payload, exact error, budget and ordinary API assertions must remain meaningful, not skipped or weakened.

Source architecture identification is **passed** within the stated source inspection. Current cross-call/final association is still **failed** as a source contract. The new producer/open coverage and platform/cold progress are **inconclusive** until implemented/reviewed. All proposed runtime/crash controls are **not tested**. Native prefix authorization, automatic controller/recovery and final GC remain open; no native Serving/zero-ACK-loss grant follows from filesystem identity or this note.
