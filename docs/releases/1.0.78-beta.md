# BicDB 1.0.78-beta

This release completes the initial fixed-cardinality server-paged buffer-pool
pressure contract with contention, dirty-age, and writeback-backlog telemetry.

## Contention visibility

- Uses a nonblocking fast path for every buffer-pool metadata-shard lock and
  page-data latch acquisition.
- Counts only acquisitions that could not proceed immediately and records
  process-lifetime total and maximum wait nanoseconds for each wait class.
- Avoids clock sampling on uncontended access, preserving the ordinary page
  path while making metadata hot spots and read/write latch contention
  distinguishable.
- Saturates cumulative duration arithmetic instead of permitting an uptime- or
  contention-driven counter wrap.

## Dirty age and writeback lag

- Records the earliest instant at which a writable guard could modify a clean
  frame and retains that timestamp across repeated writes.
- Exposes the oldest dirty resident page age and exact pending resident
  writeback backlog in pages and bytes.
- Clears the timestamp and backlog only after successful page writeback.
  WAL-barrier or page-write failures remain dirty, aged, visible, and
  retryable.
- Keeps all state bounded by the preallocated frame count and resets only the
  process-lifetime timing origin on reopen.

## Operational contract

- Advances the strict paged-storage snapshot format to version 5.
- Exports fixed-cardinality operational and Prometheus names without page,
  collection, tenant, query, path, or plugin identities.
- Updates the server-paged observability and writeback documentation and closes
  the roadmap's initial buffer-pool telemetry gate.

## Verification

Tests force metadata-shard and page-latch contention, prove nonzero total and
maximum waits, verify conservative dirty age and backlog bytes, retain age
through an injected WAL-barrier failure, clear it after successful writeback,
validate snapshot/Prometheus integration, run all page-storage unit and crash
integration suites, and compile every workspace target.
