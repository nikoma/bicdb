# BicDB 1.0.86-beta

## Disk-backed transaction-status spill

- A live long-running transaction no longer lets committed outcomes accumulate
  without bound. When the frozen watermark is pinned, each checkpoint persists
  the terminal outcomes above it to chained **status-spill** pages, syncs them,
  evicts them from the resident transaction table, and then truncates the WAL.
- Visibility resolves an evicted outcome with one demand read of its spill
  page through a single reusable page-sized buffer. Resident transaction
  memory is bounded by in-flight transactions plus one checkpoint's worth of
  commits, not by the whole pinned suffix.
- The spill descriptor (head page, chain length, entry count) lives in the
  meta page's trailing fixed region and is written only after the spill pages
  are durable, so a crash never names a page that does not exist. Spill pages
  bypass the buffer pool and the free list, so a demand read can never observe
  a reused page's new identity.
- The open-time freeze is spill-aware: an evicted commit is recognized as
  committed rather than mistaken for a crash-orphan and recorded as an abort
  exception, which had silently inverted its visibility.
- Fixed a spill merge-ordering defect where, when the carried-spill entry was
  larger than the new outcome, the merge emitted the larger entry first and
  produced an unsorted page that the binary-search lookup then missed. Under a
  concurrent checkpoint storm this lost committed rows across restart.

## Observability

- Recovery reports gain `status_spill_entries_at_open` and
  `status_spill_pages_at_open`; store snapshots gain `status_spill_entries`,
  `status_spill_pages`, and `status_spill_lookup_failures`.
- New fixed-cardinality metrics and Prometheus series:
  `paged_status_spill_entries`, `paged_status_spill_pages`,
  `paged_status_spill_lookup_failures_total`, and the recovery spill counters.
- Benchmark evidence format advances to version 5 with the two spill columns;
  the verifier fails artifacts whose spill entries exceed the reported page
  capacity or that retain any spill entry for a fully closed fixture.

## Explicit boundary

This closes the long-running-transaction case named by 1.0.85-beta and makes
resident recovery memory independent of the pinned suffix. Exception-capacity
overflow still degrades freezing to the stop behavior for the excess, now
carried by the spill. The production recovery certification gate remains open
until the documented hardware matrix passes.
