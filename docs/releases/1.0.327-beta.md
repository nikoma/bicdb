# BicDB 1.0.327-beta

This release closes PostgreSQL-compatibility and signed-authority gaps found
while compiling the full WalkNorth EHR as an isolated BicDB Cell application.

## PostgreSQL-compatible signed SQL

- Accept relation-free, routine-free `SELECT` projections as capability-free
  signed SQL while continuing to reject authority-free writes.
- Treat PostgreSQL positional parameters by their highest referenced index, so
  sparse placeholders such as `$1` and `$4` have arity four.
- Resolve positional parameters recursively through casts and `trim(...)`, and
  preserve them in relation-backed aggregate projections. This covers Carrier
  raw SQL such as `lower(trim($1::text))` and parameter columns beside filtered
  aggregates.
- Recognize table-function syntax as routine authority instead of incorrectly
  treating the function name as a relation.
- Enforce role-only resource policies before authored SQL runs. Expression
  policies remain fail-closed because an unrestricted SQL statement cannot
  safely reproduce host-owned row filtering.

## Schema parity

- Extend signed unique targets with an optional validated predicate and install
  that predicate as a real partial unique index. This preserves PostgreSQL
  partial-unique conflict semantics instead of widening the constraint.

## Phase-1 Cell integration testing

- Allow a manifest-pinned `deny_all` egress policy to name explicit
  Phase-1-only development bindings for non-regulated application testing.
- Derive encrypt/decrypt-only application secrets from the Cell key, provide a
  deterministic local tokenizer, and keep all configured HTTP and LLM effects
  explicitly denied. Production-capable Cell profiles reject these bindings.
- Preserve PostgreSQL constraint behavior for protected relations by running
  engine-internal unique, foreign-key, and exclusion checks independently of
  caller row visibility.
- Accept Carrier's compiler-signed transaction-local security-GUC setup as a
  compatibility no-op while keeping the Cell-verified actor as the sole source
  of authorization.
- Decode BicDB typed-storage envelopes before projecting persisted resources
  back into Carrier values, including UUID primary keys during Cell restart and
  schema-evolution validation.
- Keep derived application secrets stable across signed manifest-generation
  rotations for the same Cell, key epoch, and application root, so encrypted
  schema state remains readable after an attested runtime upgrade.

## Validation

- Added focused ABI and bounded-SQL coverage for capability-free projections,
  authority-free write rejection, table functions, and sparse placeholders.
- Added host coverage proving raw SQL requires the signed read, deleted-row,
  and write roles.
- Added SQL-session coverage for nested positional parameters, positional
  aggregate projections, protected-table uniqueness, and signed security-GUC
  authority preservation.
- Compiled and admitted the full WalkNorth EHR BicDB package against the new
  contracts, rotated its running Cell to the new binary digest, and exercised
  all 24 Hub starter pages as the release integration workload.
