# 1.0.527: `cargo install bicdb` compiles on macOS

`cargo install bicdb` 1.0.525 failed on macOS while compiling `bicdb-page`:

```
error[E0308]: mismatched types
   --> bicdb-page-1.0.525/src/lock.rs:292:34
292 |     if i32::from(lock.l_type) == libc::F_UNLCK {
    |                                  ^^^^^^^^^^^^^ expected `i32`, found `i16`
```

The directory-lock probe compared the `flock` lock type with `F_UNLCK`.
Linux declares `F_UNLCK` as `c_int`, but macOS and the BSDs declare it as
`c_short`, so the comparison only compiled on Linux.

## Fixed

- **Directory-lock probe builds on every Unix.** Both sides of the
  comparison are widened to `i32`. Behaviour on Linux is unchanged.

## Release

Internal packages pin each other exactly, so all 27 packages are published
again as 1.0.527. The crate sources are those of 1.0.525 plus this fix; there
is no other code, dependency or behaviour change. 1.0.526 is not used here:
that number belongs to the separate change that brings the 1.0.524/1.0.525
packaging to `main`.

The `macos-release-check` workflow builds `bicdb` on a macOS runner for this
release branch before upload.
