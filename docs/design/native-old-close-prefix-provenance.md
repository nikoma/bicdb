## Two different checksums

`NativeJointOldObservation::materialized_facts` deliberately preserves the
checksum of the complete `NativeJointOldCloseRecord`. That record contains
scope/promise, birth, physical-base checksum, **native-prefix checksum**,
selected R/H0/H, local visibility, schema/namespaces/history generation,
selected catalogue-history checksum, metadata context and actual native xid.
Its outer checksum hashes a different record and is not the contained prefix checksum.

`SourceRangeImageLineage::native_receipt_sha256` returns the actual selected
certified-prefix checksum, or the native physical base checksum at an empty
prefix. That value enters the actual source Manifest, Finished seal and target
base's source receipt. `require_closed_fact_current` already revalidates the
original protected close record against the genuine source's current native
prefix, physical base, R/H0/H and namespace identities.

These are selected-range facts with global birth/schema/namespace/image-generation
bindings, not a hash of every live database row. The catalogue-history commitment
selects only the range's retained log, decisions, fences and native state.

## Genuine producer and authenticated transport

`NativeJointOldCloseRecordData` is serializable historical DATA with private
bytes and no authority constructor. Only the actual retained native close
receipt's snapshot reader produces new bytes locally. It validates the original
native admission, closure, promise/catalogue and current physical lineage, then
reads CURRENT and immutable-history values from one actual paged snapshot.
Both must be byte-identical to the original canonical committed record. It
revalidates after reading. This performs no native write, replay or checkpoint.

A closed OLD reply must carry both its existing materialized fact and that exact
record. A constraint-only/absent closure cannot carry the record. The pinned TLS
client validates the response's original request, actual peer/birth and frame
checksum, then validates bounded canonical record bytes, the embedded record
checksum, original facts, birth/incarnation, scope and promise. The actual OLD
collector retains the authenticated frame and checks the selected source's
record against its genuine original owner. Existing outer closure facts and
complete peer/irreversible constraints are preserved.

The Manifest additionally carries the selected record and physical-base
checksum taken from the actual pinned source lineage. Shape validation proves
record inner prefix = actual Manifest prefix, physical base, source birth,
namespace/history/schema, R/H0/H/local B, session/nonce and intended configuration.
The later Finished seal is checked against the same record. Source capture and
fresh MStore/OWN pre/post validation remain mandatory; a caller's wire assertion
cannot replace the sealed producer or a native source owner.

Registered NEW obtains this actual-source comparison before acquiring target
service/DB guards. It compares exact authenticated original record bytes with
the retained target's original sealed Manifest, including the original OLD
certificate checksum, then checks that record against Manifest and Finished.
The original target/A/freeze, role, independent OWN, current-MStore point,
protected image/base/catalogue, R/H and configuration checks remain required.
The final source-receipt equality compares Finished to the target's source
receipt; the independently verified original record supplies its native-prefix
relationship. No decoded record can produce OLD, NEW, an ordinary writer or a
Serving/readiness grant.

The wire/Manifest additions are mandatory and fail closed if absent. The
prototype's strict old decoders reject the additional fields; mixed-version
compatibility is not established. Native record retention is bounded before
cloning/checksumming wire envelopes. Existing transport and native-get allocation
limits remain separate; this is not a general oversized cursor/allocation fix.
