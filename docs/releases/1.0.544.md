# 1.0.544: EXPLAIN in PostgreSQL's layout, jsonpath datetime items, date/time leftovers

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/k.cases`.

## Added

- **EXPLAIN with options** (`COSTS OFF`, `VERBOSE`, `FORMAT TEXT/JSON/YAML/XML`,
  `ANALYZE`, ...) and EXPLAIN of INSERT, UPDATE, DELETE, CREATE TABLE AS, set
  operations and multi-table joins render PostgreSQL's plan tree vocabulary and
  layout (Seq Scan, Index Scan with Index Cond, Sort, Limit, Aggregate,
  HashAggregate, WindowAgg, Append, Hash Join, Nested Loop, Function/Values/CTE
  Scan, InitPlans/SubPlans, ModifyTable). EXPLAIN requires the explained
  statement's privileges. EXPLAIN ANALYZE in this layout is limited to
  single-scan plans (others fail with 0A000). A bare `EXPLAIN [ANALYZE] SELECT`
  keeps BicDB's native access-path report.
- **jsonpath datetime items**: `.datetime()`, `.date()`, `.time()`, `.time_tz()`,
  `.timestamp()`, `.timestamp_tz()` with PostgreSQL's formats, conversions,
  comparison rules and ISO 8601 output; a precision above 6 is reduced with a
  WARNING.
- `x [NOT] BETWEEN SYMMETRIC a AND b`; POSIX time zone specs with daylight rules
  (`CST7CDT,M4.1.0,M10.5.0`); `SET TIME ZONE DEFAULT/LOCAL`.

## Changed

- A time zone abbreviation the session's zone uses (LMT, MMT) means what it
  means in that zone in timestamptz input and `to_timestamp`; an unknown plain
  zone word is invalid input syntax.
- `date_bin` reports PostgreSQL's range errors and 0A000 cases.
- SIMILAR TO: a `[:class:]` element inside a bracket expression no longer ends
  the bracket.
- `jsonb_path_match` with a non-boolean or empty result behaves as in
  PostgreSQL.
