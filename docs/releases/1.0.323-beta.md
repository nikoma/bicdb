# BicDB 1.0.323-beta

Phase 6 ships the industry-neutral, hardware-bound device-edge boundary.

## Added

- New `bicdb-cell-device` crate with no cluster selector, KMS credential,
  network server, SQL executor, or cross-Cell handle.
- Disjoint threshold Enrollment, Authorization, Resolution, and Retirement
  roles plus separate parent export keys.
- Certified hardware-key descriptors for encryption, user-presence signing,
  platform attestation, and rollback-resistant clocks.
- Device-unique database keys sealed with X25519, HKDF-SHA256, and
  XChaCha20-Poly1305; the parent Cell key is never exported.
- Exact-object working sets with bounded bytes/counts, signed tombstones,
  contiguous package chains, device encryption, and no wildcard filter
  language.
- A real encrypted, identity-bound BicDB device store with hardware-clock
  rollback detection and bounded offline sessions.
- Immutable hardware-signed amendment chains, parent causal-base comparison,
  explicit clean/conflict results, and threshold-certified resolution.
- Parent refusal and cooperative hardware-key destruction for certified
  device retirement, with honest residual-copy semantics.
- Phase-6 Cell manifest profiles, policy digest pinning, CLI flags, and
  `BICDB_CELL_DEVICE_*` environment mappings.
- Parent device ledger inside the encrypted Cell database so state inherits
  commit fencing, replication, backup, and recovery.

## Correctness and security findings closed during integration

- Resolutions can name only amendments that the parent durably admitted and
  has not already resolved.
- Amendments can cite only working-set packages durably recorded by the
  parent; fabricated causal package digests are refused.
- Parent ledger state is persisted before in-memory publication, avoiding a
  split state after an I/O or fenced-commit failure.
- Missing exact objects are signed tombstones, allowing one-id creates without
  granting wildcard create authority.
- Device database paths must be absolute, have existing real-directory
  parents, and cannot be symlinks; creation is restricted and fsynced.
- Private X25519 scalar error paths zeroize before returning.
- Corrupt pending amendment records fail closed instead of being skipped
  during resolution lookup.
- Enrollment binds the exact trust-policy digest, and device plus parent
  ledgers require a strictly advancing hardware counter for each amendment.
- Parent and device transitions reject working-set, resolution, and retirement
  certificates presented before their effective time.
- Phase 6 inherits Phase-4 fleet and Phase-5 HA construction instead of
  relying on new parallel lifecycle paths.
- Phase-5 documentation now describes declared-RPO asynchronous replication
  accurately and does not imply continuous commit-time enforcement.

## Verification

- End-to-end encrypted device database, exact existing object plus tombstone,
  user-presence session, replace/create amendments, clean/conflict outcomes,
  certified resolution, replay refusal, clock rollback refusal, retirement,
  and ciphertext canary scan.
- Role-substitution and resolution-of-unadmitted-amendment negative tests.
- Exact public `CellRuntime::open` path inheriting Phase-3 application,
  Phase-4 fleet activation, Phase-5 commit fencing, and Phase-6 device policy
  construction with pre-key refusal checks.
- Dedicated Cell binary, main CLI, and environment-mode compilation.

Regulated-data production admission remains explicitly denied.
