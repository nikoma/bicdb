# BicDB 1.0.485-beta — metadata Append safety

A metadata receiver could acknowledge an untouched divergent local suffix beyond
the prefix actually matched by the leader's bounded Append request. Counting that
reply could mark a distinct topology committed without replicating it. The
receiver now acknowledges only the matched previous/snapshot/entry prefix and
limits commit advancement to that frontier. An unrelated local suffix supplies
no replication evidence. Persistence and wire formats remain unchanged.

The [reproduction and repair report](../design/metadata-append-frontier-safety-2026-11-12.md)
links exact failing/fixed revisions and CI. The [original retained artifacts](../evidence/metadata-append-frontier-2026-11-12/README.md)
include all pre/post-recovery metadata states, real request/reply traces,
source/compiler identities, checksums and an offline custody verifier. The
baseline reports ACK 3 for matched index 1 and prematurely commits topology 3.
The fixed comparison reports ACK 1, keeps that proposal uncommitted and passes
genuine majority recovery plus strict reopen of all three stores.

Two focused metadata regressions pass at source `6458bf6d0c121e647ae0a1f57fa85a06d16b4163`,
including snapshot-plus-entry, duplicate partial-batch, empty-heartbeat and
commit propagation controls. All-target and isolated consumer checks pass there.
Those runs used working version 1.0.481-beta. Full final-version regression and
Rails checks are required before merging this independent candidate.

This candidate is based directly on public main 1.0.482-beta
`f43583da4c34209e810c5e6a8f5925831b2949a1`. Versions 1.0.483/484 were
assigned to unmerged candidates and are not reused. The independent repair
excludes the queued ERP Decimal/index semantics changes and the larger native
read/recovery feature batch. Existing results for a composed 1.0.484 candidate
remain historical; they are not this candidate's release qualification.

The correction is receiver-side; mixed-version safety remains unqualified.
Physical HA/RPO/RTO, automatic five-node convergence, sustained throughput gain,
general distributed SQL and critical-workload admission remain open. No causal
link to the original Azure failures or business-row loss is established. A source
merge is separate from a built binary, published release and verified deployment.
