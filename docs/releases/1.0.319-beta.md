# BicDB 1.0.319-beta

This hotfix closes an online-backup snapshot race exposed by the exact
post-merge `main` workflow for 1.0.318-beta. It does not change Cell identity,
encryption, application, or admission semantics. Regulated-data admission
remains closed.

## Fixed

- Physical segment and transaction-log writers now hold a shared OS-backed
  database gate for the complete write instead of checking whether a backup
  marker exists and then writing later.
- Streaming base backups hold that same gate exclusively from the consistency
  cut through archive completion. A writer can therefore finish before the
  cut or begin after it, but cannot cross it while a source file is hashed and
  streamed.
- The gate uses a persistent, never-unlinked inode. This prevents a process
  from locking an old inode while another process opens a replacement path and
  bypasses the lock.
- The existing online-backup owner lock remains separate, so a second backup
  still fails immediately instead of silently queueing behind the first.
- Large-value writes participate in the same database gate for their complete
  temporary-write and publish operation.
- Backup archives, encryption rotation, and encrypted-tree digests exclude the
  coordination inode. Existing databases create it before recovery or
  foreground writes begin.

## Root cause

The previous marker protocol had a time-of-check/time-of-use gap: a writer
could observe no `.backup-online.lock`, then a backup could create the marker,
and the writer could append to `transactions.log` while the backup was reading
it. The backup correctly detected that the source changed and aborted, but it
could not guarantee a stable snapshot under that interleaving.

## Validation

- deterministic bidirectional exclusion test proving shared writers block an
  exclusive backup and an exclusive backup blocks new writers;
- the exact concurrent-write backup/restore regression repeated 30 times;
- complete backup integration suite, including restore and PITR;
- WAL-rotation-during-online-backup stress regression;
- encryption and crash-resumable key-rotation integration suite;
- encrypted large-value and backup/restore integration suite;
- complete reduced Cell runtime and CLI suite;
- workspace/all-target compile, formatting, and repository invariants;
- GitHub pull-request and exact-SHA post-merge `main` workflows.

## Admission remains closed

This repair makes backup snapshot coordination deterministic. It is not a
regulated-workload certification and does not complete the remaining Cell
application, fleet, HA, device, grant, orchestration, supply-chain, or
independent-review roadmap gates.
