# BicDB 1.0.333-beta

This release makes signed Carrier application upgrades preserve PostgreSQL 18
schema and tenancy semantics when an existing Cell gains stricter row
partitioning, additive encrypted fields, or a corrected partial unique index.

## Safe Cell application evolution

- Permit a new encryption binding only when it belongs to a newly added field;
  changing an existing plaintext field to encrypted without an explicit
  ciphertext transformation remains rejected.
- Permit `tenant_field` to advance from unset to an already persisted,
  non-nullable field. Removing, changing, or selecting a nullable tenant field
  remains rejected.
- Preserve unique-target identity and columns while allowing a signed predicate
  correction, such as aligning a soft-delete constraint with PostgreSQL's
  `WHERE deleted_at IS NULL` behavior.
- Replace only predicate-compatible native indexes and retain their exact prior
  definitions in the activation receipt so any later failure restores the old
  index before startup returns an error.

## Validation

- BicDB application-runtime tests: 112 passed, 1 release-only benchmark ignored.
- Focused tests cover additive encryption, tenant-partition tightening, signed
  unique-predicate correction, and compensated native-index replacement.
- A real WalkNorth EHR Cell transition from 1.10.2-rc to 1.10.16-rc completed
  the signed generation-3 startup ceremony with migrations, contracts, routes,
  workers, schedules, providers, and schema compatibility ready and no issues.
