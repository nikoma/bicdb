# BicDB 1.0.331-beta

## Seed Block-Max WAND from bounded impact candidates

- Samples at most eight impact-ordered rounds to populate the exact BM25
  winner heap before the document-order Block-Max WAND scan begins.
- Gives broad top-k conjunctions a useful pruning threshold immediately,
  instead of discovering high-scoring candidates only after a large
  document-order scan.
- Keeps final ranking exact: impact candidates only seed the heap; the
  document-order path still proves the complete top-k result using its
  conservative block bounds.
- Falls back to the ordinary document-order path when impact sidecars are
  missing, incompatible, or unreadable.
- Avoids partitioning a seeded query so every candidate is compared against
  one global top-k threshold.

The retained 50,000-document FTS workload completed top-10 conjunctions in
7-34 ms across rare/common through six-common-term shapes with one serving
partition. The complete FTS integration suite and `bicdb-core`/`bicdb-sql`
checks pass.

This release changes query execution only. It does not change the storage
format and does not require rebuilding an existing full-text index.
