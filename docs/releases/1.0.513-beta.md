# 1.0.513-beta: joined handoff stage logic separated from member custody

Refactor only; no behaviour change. 1.0.512-beta is reserved by a parallel
candidate and is not used here.

The in-process driver that hands one range to a registered fifth member
(`NativeJoinedDataHandoff`) is split in two:

- **Stage logic** (`distribution_native_host/joined_data_handoff.rs`): stage
  derivation from committed metadata, the abort boundary, resume rules and the
  metadata commits.
- **Member custody** (`joined_data_handoff/local_backend.rs`): everything that
  touches a member's service or runtime, behind the `JoinedHandoffBackend`
  trait. The existing in-process behaviour is its only implementation.

This is the seam a later remote backend needs so that the abort and resume
rules are not written a second time. A remote backend must never build local
quorum, role or freeze objects from reply data.

Validation: the six `native_fifth_data_path_*` tests pass unchanged, and the
full suite passed on the pre-version head.

Limits: there is still no production caller and no remote backend. The split
of the former `open_and_serve` into `activate` and `serve` changes where a few
reference-counted handles are dropped; this is argued from the code, and
covered only by the existing tests.
