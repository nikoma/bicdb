# BicDB 1.0.484-beta — metadata Append safety

This candidate fixes a metadata-consensus receiver that could acknowledge an
untouched divergent local suffix beyond the prefix matched by the leader's
bounded Append request. A leader could count that index and prematurely commit
a distinct topology. The receiver now acknowledges only the matched prefix and
caps follower commit at that same frontier, including snapshot and empty-payload
requests. No persistence format or wire DTO changes are required.

The [reproduction and repair report](../design/metadata-append-frontier-safety-2026-11-12.md)
links exact failing/fixed revisions and CI runs. The [retained original artifacts](../evidence/metadata-append-frontier-2026-11-12/README.md)
include genuine fsynced store states, pre-recovery copies, real message traces,
compiler/source identities and offline checksum verification. The baseline
returns ACK 3 for matched index 1 and prematurely commits topology 3. The fixed
comparison returns ACK 1, keeps that proposal uncommitted and passes genuine
majority recovery plus strict reopen of all three stores.

Validation before the version bump: the two focused metadata regressions passed
at `6458bf6d0c121e647ae0a1f57fa85a06d16b4163`, together with all-target and
isolated consumer compilation checks. Those checks used working version
1.0.481-beta and do not qualify this composed 1.0.484-beta candidate. Full
regression and Rails checks for the final versioned source are required before
merge. This candidate incorporates the queued 1.0.483-beta source at
`777e82cf829cbee94b881054a29b686a271a75b6`; that change must merge first,
then the next unused source version must be checked again.

The repair is receiver-side; mixed-version safety remains unqualified. This
release note does not assert a binary build, published release or deployment.
Physical HA/RPO/RTO, complete automatic five-node convergence, sustained capacity
gain and general distributed SQL qualification remain open. No causal attribution
to the original Azure failure or business-row loss is established. The larger
native read/recovery and learner-transition work remains a separate candidate.
