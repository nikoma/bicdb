# 1.0.540: table inheritance, hstore, pgcrypto crypt, exclusion constraints, string constants, text search

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/a2.cases`, `a3.cases` and `i.cases`.

## Added

- **Table inheritance**: `CREATE TABLE ... INHERITS (...)` builds the child from
  its parents (merged columns, NOT NULL, defaults, CHECK constraints). Reads of
  a parent include its descendants (`tableoid` names the storing table); UPDATE,
  DELETE and TRUNCATE reach the descendants; ALTER TABLE column changes and ADD
  CONSTRAINT CHECK recurse unless `ONLY` is written. `ONLY` in SELECT, JOIN,
  UPDATE and DELETE; `CHECK ... NO INHERIT` and `NOT NULL NO INHERIT`;
  `ALTER TABLE child [NO] INHERIT parent` (several actions per statement);
  `ALTER CONSTRAINT ... [NO] INHERIT`; `DROP TABLE parent CASCADE`; renaming a
  table in a hierarchy; `pg_inherits` and `relhassubclass`. UPDATE/DELETE
  through a parent with row-level security, and MERGE into a parent with
  children, are refused with 0A000.
- **Exclusion constraints** declared inline (`EXCLUDE USING gist (...)`), now
  checked against the transaction's own rows and reserved until commit, so two
  concurrent transactions can no longer both insert conflicting rows.
  DEFERRABLE exclusion constraints are refused with 0A000.
- **UNLOGGED tables** (`relpersistence` 'u'; rows are still written durably)
  and **VIRTUAL generated columns** (`attgenerated` 'v'). ADD COLUMN with a
  generated expression fills the existing rows.
- **hstore**: the type, its operators, `akeys`, `avals`, `hstore(...)`,
  `hstore_to_json[b]`, `hstore_to_array`, `exist`, `defined`, `delete`,
  `slice`, `each`/`skeys`/`svals`, `populate_record`, with PostgreSQL's
  canonical text form and input errors.
- **pgcrypto** `crypt()` and `gen_salt()` (bf, md5, xdes, des, sha256crypt,
  sha512crypt) producing PostgreSQL 18's hashes; `digest()` sha1 and more
  `hmac()` algorithms. Blowfish/sha-crypt with non-ASCII passwords are 0A000.
- **Text search**: untyped literals next to tsvector/tsquery take that type,
  `<->` on tsquery is the phrase operator, `ts_lexize`, `ts_token_type`,
  `ts_stat`, `default_text_search_config`, text search functions in FROM, and
  `ts_rank_cd` honouring the operand's weights.
- A set-returning SQL or PL/pgSQL function in a select list runs as
  PostgreSQL's ProjectSet, several calls in lockstep; SQL-function SRFs in FROM
  take WITH ORDINALITY; `RETURN NEXT expr` does not set FOUND.
- `x OP ANY/ALL (array)` for non-comparison operators; hstore GIN/GiST
  operator classes; inherited NOT NULL constraints keep PostgreSQL's names.
- PostgreSQL's lexer WARNING (22P06) for nonstandard backslash escapes while
  `standard_conforming_strings` is off.

## Changed

- **String constants are decoded exactly as PostgreSQL's lexer does**, once,
  before any other stage: `E'...'` escapes (octal, hex, `\u`/`\U`), `U&'...'`
  with UESCAPE, continued constants, and PostgreSQL's errors. Before, `E'a\\b'`
  was decoded twice. `standard_conforming_strings = off` is accepted and
  honoured.
- **Float output** follows `extra_float_digits`; float4 values and float4[]
  elements, rows and JSON print at float4 precision; booleans inside
  composite values print as `t`/`f`; a float4 column compares with an untyped
  literal at float4 precision.
- Generation expressions are shown as PostgreSQL deparses them (`(a * 2)`).
- `pg_constraint.connoinherit` is false for inheritable CHECK and NOT NULL
  constraints; an unnamed table CHECK is named after its first column
  (`t_a_check`).
