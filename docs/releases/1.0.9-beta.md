# BicDB 1.0.9-beta

Release date: 2026-08-03

## Durable per-range write quorum

- Adds a checksummed, atomically persisted data command log per range with
  epoch/leader fencing, sequential indexes, deterministic command checksums,
  idempotent retries, bounded applied-history retention, and restart recovery.
- Installs the range authority below BicDB's transaction commit path. A
  distributed server fails closed until the authority is ready, rejects
  cross-range ordinary transactions, and never acknowledges a local-only row
  mutation.
- Prepares each exact mutation command on the current voters and requires a
  majority before recording a decision. It then requires a majority of durable
  commit acknowledgements; minority partitions cannot write.
- Replays a durable committed-not-applied decision on restart, covering a crash
  between quorum commit and local row application. The local applied checkpoint
  is written only after BicDB's ordinary WAL durability boundary.
- Keeps one in-flight decision per range until that local durability boundary,
  preventing later commands from overtaking an ambiguous commit. Supervisor
  shutdown clears the authority fail-closed and releases its database handle,
  so a stopped node can be reopened without a leaked paged-store lock.
- Extends the authenticated, bounded cluster RPC protocol to version 6 with
  range prepare, commit, and abort messages. Followers validate cluster, range,
  epoch, leader, voter placement, mutation ownership, command identity, and
  checksum before touching data.
- Adds regression coverage for missing authority, minority rejection, checksum
  tampering, conflicting duplicates, stale epochs, durable-log reopen,
  decision replay, idempotent commit retries, and an actual loopback TCP
  follower apply.
