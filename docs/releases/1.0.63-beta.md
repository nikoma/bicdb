# BicDB 1.0.63-beta

Release date: 2026-08-04

## Bounded raw certification capture

- Adds `bicdb cluster certify-capture`, which turns an existing command output
  or measurement stream into a valid run-bound certification artifact and
  registers it in one operator workflow.
- Copies payloads through a fixed 1 MiB heap buffer, independent of artifact
  size; no payload or whole artifact is accumulated in memory.
- Builds the envelope from the immutable plan and durable collector state, so
  run ID, profile, BicDB version, source revision, dirty state, artifact kind,
  producer nodes, and observation interval cannot be hand-copied incorrectly.
- Reserves a bounded 64 KiB header line, streams and hashes the payload once,
  writes the final header, and validates that the source did not change during
  capture.
- Publishes a fully written and optionally fsynced artifact with an atomic
  same-filesystem hard link. Existing output is never overwritten.
- Makes the publication-to-registration boundary restart-safe: rerunning the
  exact command verifies and registers an already-published artifact even when
  the original payload is no longer available.
- Rejects output and payload symlinks, path traversal, unsafe parent
  components, empty payloads, zero record counts, invalid or future intervals,
  changed payload files, mismatched resumptions, and opaque preexisting output.
- Moves the verifier and capture copy buffers from worker stacks to bounded
  heap allocations, avoiding stack exhaustion during nested resume checks.
- Adds focused coverage using a payload larger than three buffer windows,
  simulated interruption after publication, source removal before resume,
  no-overwrite behavior, forged intervals, zero records, and path traversal.

This release supplies the safe producer path required to execute the physical
1 TB, 5 TB, and 20 TB certification trials. It does not mark those hardware
trials complete.
