# BicDB 1.0.66-beta

Release date: 2026-08-04

## Bounded, cursor-resumable server-paged vacuum

- Adds `VacuumLimits` with explicit page, logical-byte, and cooperative-time
  envelopes for one maintenance step. A hard 65,536-page ceiling also bounds
  the pending fully-dead-page list to at most 512 KiB; 16 GiB and five-minute
  hard ceilings prevent legacy callers from disabling byte or time bounds.
- Adds a serializable inclusive `VacuumCursor`, a structured stop reason, exact
  next-step position, elapsed time, and bounded-work counters.
- Streams heap page IDs directly from the durable catalog one B+tree leaf at a
  time instead of allocating a vector proportional to the database.
- Reads only the fixed 30-byte MVCC header prefix from an overflow value rather
  than materializing its complete payload.
- Preflights overflow-chain release against the remaining byte envelope. A
  value that does not fit is not partially reclaimed or skipped; the report
  returns its heap page for a later step with a larger approved budget.
- Makes the low-level heap scan cursor database-size-independent as well,
  removing its residual all-page vector.
- Preserves the legacy page-count vacuum entrypoint while routing it through
  the new streaming implementation.
- Adds deterministic page-, byte-, and time-stop tests, large-overflow-value
  coverage, cursor monotonicity checks, and serialize/reopen/resume coverage.

The production maintenance supervisor still needs to atomically checkpoint the
returned cursor and schedule successive governed steps; this release provides
the bounded storage primitive without claiming that broader roadmap gate.
