# BicDB 1.0.60-beta

Release date: 2026-08-04

## Restore and expansion certification

- Advances immutable cluster certification plan, collector state, and report
  formats to version 5.
- Binds whole-node restoration to a named backup and manifest digest, a
  strictly higher node incarnation, and exact timestamps inside the report.
- Requires matching source/restored record counts, logical bytes, and corpus
  digests at one fixed commit watermark.
- Caps restore peak RSS at 32 GiB and requires matching production-sized FTS
  document counts, index-byte counts, and SHA-256 digests.
- Requires 1,000 successful restore FTS probes, 10,000 successful quorum
  operations, 1,000 rejected old-identity writes, and zero unavailable ranges.
- Requires expansion to publish a newer topology generation and digest and to
  identify every new node with complete, capacity-checked hardware evidence.
- Requires bounded peak RSS on every old and new node, substantive movement
  with nonzero source/network/destination counters, and at most 4x relocation
  I/O.
- Requires statistically meaningful foreground and hotspot measurements,
  bounded p99 regression, uninterrupted quorum work, full-corpus and FTS
  equality, successful FTS probes, converged placement, and balanced replica
  bytes after expansion.
- Binds both observations to exact checksummed artifact kinds rather than
  accepting globally registered or substituted evidence.
- Adds adversarial tests covering forged provenance, time and incarnation
  inconsistencies, checksum and FTS mismatches, memory excess, insufficient
  operations, missing hardware, weak topology transitions, unbalanced
  placement, unfinished relocation, and artifact substitution.

This release freezes the restore and expansion evidence contract. It does not
claim the production hardware rehearsals have already passed.
