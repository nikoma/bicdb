# BicDB 1.0.14-beta

Release date: 2026-08-03

## Fail-closed schema compatibility fencing

- Adds a canonical, versioned SHA-256 fingerprint over collection policy,
  mutation policy, executable indexes, and structural SQL catalogs while
  excluding user rows and volatile runtime state.
- Shares a lock-independent schema generation and verified-digest authority
  with range write admission. Schema changes invalidate verification
  synchronously, without recursively acquiring the database lock.
- Publishes each node's live digest in quorum-committed heartbeats under the
  reserved `bicdb.schema.sha256` label and validates its exact lowercase
  SHA-256 shape.
- Rejects schema-incompatible replica placement, relocation, node removal
  planning, and leader transfer targets.
- Fences authenticated snapshot, catch-up, cleanup, repair, and range-write RPC
  execution against both membership advertisement and the live database.
- Extends cluster data protocol v11 with leader-exported, checksummed schema
  bundles bounded to 64 MiB and one million structural records. Empty nodes may
  install the bundle before their first snapshot; nodes containing user rows
  reject automatic replacement and remain quarantined.
- Starts the production pgwire range coordinator in strict mode: leadership
  recovery and writes remain unavailable until the current leader label matches
  a freshly verified local digest.
- Keeps unlabeled legacy topology readable during rolling upgrade, while the
  production host remains write-closed until its own fingerprint is published.
- Adds regression coverage for row-independent fingerprints, index/catalog
  drift, immediate stale-digest write closure, placement rejection, malformed
  labels, and live data-RPC verification.

This release detects and fences schema drift and safely bootstraps genuinely
empty voters. It does not overwrite schemas on nodes containing user data;
those still require coordinated online DDL or explicit operator repair.
