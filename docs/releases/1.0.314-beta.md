# BicDB 1.0.314-beta

## BicDB identity and PostgreSQL compatibility

- Make `SELECT version()` identify the engine truthfully as BicDB by default,
  while preserving independently configurable PostgreSQL wire-version startup
  parameters.
- Add `--postgres-version-banner` to `serve` and `dev` for clients that require
  a PostgreSQL-shaped `version()` response. `bicdb_version()` remains the
  immutable BicDB build identity in either mode.
- Keep the optional PostgreSQL-shaped banner strictly cosmetic: protected
  `carrier.current_*` identity, role, and tenant GUCs remain host-derived and
  client writes remain refused in compatibility mode.
- Synchronize the macOS bundle/package metadata and client-matrix identity to
  1.0.314 so desktop artifacts cannot reintroduce the stale 0.9.36 identity.

## WalkNorth EHR and SQL compatibility

- Correct the WalkNorth EHR migration gate to verify identity-owned sequences
  through `pg_class` while expecting `information_schema.sequences` to remain
  empty, exactly matching the PostgreSQL 18.4 oracle.
- Implement PostgreSQL-compatible scalar `regexp_replace` and set-returning
  `regexp_split_to_table`, including flags, aliases, ordinality, NULL behavior,
  and PostgreSQL's zero-length delimiter behavior.
- Allow data-modifying `INSERT ... RETURNING` CTEs to feed later CTEs and the
  outer query.
- Bind PostgreSQL trigger metadata (`TG_NAME`, `TG_WHEN`, `TG_LEVEL`, `TG_OP`,
  `TG_TABLE_SCHEMA`, `TG_TABLE_NAME`, `TG_RELNAME`, `TG_RELID`, `TG_NARGS`, and
  zero-based `TG_ARGV`) before PL/pgSQL declaration initialization.
- Preserve the declared output columns of SQL `SETOF` functions when their
  result relation is empty.
- Match `GRANT ... ON ALL FUNCTIONS IN SCHEMA` against the routine's stored
  schema rather than its serialized name.
- Infer text parameter types through `TRIM` expressions.
- Preserve schema-qualified partition identities through raw PostgreSQL
  partition DDL and report logical table names through optimized catalog views.
- Honor explicit schema qualification when resolving `regproc` and
  `regprocedure` aliases instead of falling through to a same-named routine.
- Keep canonical/driver DATE decoding limited to a date or lossless UTC
  midnight timestamp while retaining PostgreSQL's broader timestamp-to-date
  truncation for SQL text input.

## Transaction and authorization correctness

- Make security-context reads inside a transaction overlay that transaction's
  pending writes before collection policy and protected-field projection, so
  RLS-enabled sessions retain read-your-own-writes semantics.
- Give READ COMMITTED `UPDATE` and `DELETE` operations a bounded long wait for
  the current row owner, then recheck and serialize, instead of surfacing a
  false serialization failure after the ordinary short conflict budget.
- Prevent multi-record row-lock deadlocks with deterministic wait ordering:
  wait edges can point only from newer transactions to older owners, and the
  opposite encounter loses immediately rather than forming a cycle.
- Allocate PL/pgSQL's implicit `FOUND` variable as a compiled routine slot so
  ordinary assignment loops do not materialize the fallback variable map.

## Cell/Application architecture and Phase-1 runtime

- Add the normative
  [BicDB Cell/Application Architecture](../bicdb-cell-application-architecture.md),
  defining application roots, independently isolated clinical cells, explicit
  application scopes, cell identity/key/replication binding, device replicas,
  encrypted cross-cell grants, and fleet admission gates.
- Record the adversarial finding that cell isolation limits runtime blast
  radius but not common-mode release, frontend, runtime-image, orchestration,
  or KMS compromise. Publication, rollout approval, activation, and decryption
  are separate trust domains.
- Clarify that the current `regulated-phi` general-server profile is not proof
  of readiness for a global clinical-cell fleet.
- Add the separate capability-reduced `bicdb-cell` crate/binary and the same
  typed path under `bicdb cell serve`. The runtime verifies a signed
  deterministic-CBOR manifest, immutable signed volume identity, expected
  cell/volume/lineage, monotonic generation transition, runtime and application
  digests, fixed cell-scoped key request, and encrypted single-database open
  before reporting readiness. Signatures bind the signer identifier as well as
  the payload, and the runtime digest always measures the executable actually
  running rather than a caller-selectable path.
- Document the exact Phase-1 manifest, signing, immutable volume binding,
  startup, and environment contracts in
  [Cell runtime: Phase 1 operator contract](../cell-runtime-phase1.md).
- Make `BICDB_RUNTIME_MODE=cell` select only that construction path and reject
  general BicDB commands. Raw key bytes are never accepted through the flag or
  environment; the Phase-1 file provider reads one mode-0600 file bound to one
  CellId and KEK id.
- Keep the security claim explicit: Phase 1 has no public listener and reports
  `clinical_phi_admitted = false` until attested KMS release, complete storage
  encryption, external anti-rollback, cell-native application execution,
  replication fencing, and independent certification are implemented.
