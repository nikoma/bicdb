# BicDB 1.0.505-beta

`ClusterEventClient` keeps the actual routed-operation error when later topology
discovery fails. An earlier typed `CommitOutcomeUnknown` retains its transaction
identity and dispatch uncertainty across subsequent refusals, discovery errors
and deadlines. A timeout or later refusal does not establish rollback.

An already dispatched request can finish inside the same original caller budget
while another route is examined. Workers inherit the caller's complete nested
query-budget context and shared memory peak; an expired caller is refused before
TCP dispatch. The existing bounded retry plan and connect cap remain in place.
Socket progress never renews the original deadline, and successful replies still
require current cancellation, deadline, identity and response-type checks.

Optional RPC evidence retains its first published actual failure cause before
exposing its fence to concurrent workers. Dispatch uncertainty can increase
without replacing that cause. A sibling cleanup failure cannot be hidden behind
a mock ACK; a real evidence failure is preserved before cancellation can replace
it with a generic timeout. No global callback lock serializes unrelated sinks.
