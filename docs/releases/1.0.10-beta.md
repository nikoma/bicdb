# BicDB 1.0.10-beta

Release date: 2026-08-03

## Bounded range-log repair

- Adds authenticated per-voter range-log progress and resolved-suffix repair
  before a leader prepares the next write.
- Streams only contiguous applied/aborted commands with command and batch
  SHA-256 checksums, exact serialized-byte accounting, epoch/range/leader
  fencing, and idempotent replay.
- Makes repair memory, RPC, and admission work explicit and bounded: 128
  commands, 4 MiB, and eight batches by default, with validated configurable
  limits.
- Broadcasts aborts to all voters after a failed prepare quorum so a durable
  prepare whose response was lost cannot accumulate silently.
- Supports continuous resolved suffixes across monotonic historical epochs,
  while rejecting future/stale-route epochs. A follower behind retained
  history or a voter ahead of the designated leader still requires snapshot or
  leader recovery rather than an unsafe log fast-forward.
- Extends the authenticated cluster data protocol to version 7 and covers both
  in-process automatic catch-up and actual loopback TCP progress/repair/apply.
