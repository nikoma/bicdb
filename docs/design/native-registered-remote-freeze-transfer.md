# Actual Registered remote freeze transfer

This source batch implements ownership/preflight only. It has not been compiled
or executed. It writes no Installing record, image row, native floor or serving
state. Earlier A9 component test results apply to A9, not this changed runtime.

The actual Registered receiver retains a per-range
`NativeRegisteredRemoteInstallAttempt`. Its owned preflight holds the original
receiver admission, the SAME `Arc<NativeRemoteImageFact>`, actual native
admission, UID/schema-generation pins, native safety, exact catalogue/raw
constraints and an opaque prepared `NativeRegisteredRemoteImageIntent`.
The source frame must point to that exact MF owner. The manifest's authenticated
target attempt A must differ from the actual handoff session owner N.

The first actual request acquires a shared view of the runtime's retained N
permit, creates the lexical remote step and actual NoDomain observation, and
captures safety with the already-held native journal. The root intent producer
builds and rechecks its DATA token inside that same real NoDomain scope. These
are immutable constraints, not a native-write grant. The consumed step returns
the SAME role/OWN/member and original cancellation/deadline tokens in an owned
request containing no Frozen reference or Arc. All temporary Frozen borrows and
Arcs end before transfer.

The original host inserts the exact attempt before calling the runtime. The
runtime reserves its real exclusive operation, verifies the original actual
session and demands `Arc::get_mut` on the existing permit. An outstanding
callback Arc produces a bounded refusal. Under nonwaiting actual guards it
rechecks the original receiver, source frame, request, native safety, UID/schema
pins, exact CLOSED raw/catalogue pair, protected MStore point and the root's
prepared intent constraints. A test cut is followed by the same full recheck.
It then rotates that actual permit N→A, moves it out of the original runtime
slot and retains it in a runtime-owned cell with the exact preflight. There is
no fallible production operation after rotation before returning the lease.
The host stores the lease before its outside-engine MStore postcheck.

The runtime and host independently retain that same A custody. Dropping a
finite request or lease cannot return A to N, release the permit or discard the
prepared data. A busy pre-rotation attempt remains retained and a distinct fresh
request may retry it using the SAME MF Arc and intent checksum. An already
transferred attempt refuses duplicate transfer. Original process/slot revocation
still invalidates use of the lease. Physical custody surviving a five-second
call is not renewal of that call's authority.

`NativeImageInstallFreeze::RegisteredRemote` preserves the eventual image/freeze
interface. The ordinary local installer explicitly refuses that variant, and
ordinary joint-image release refuses it before owner consumption. The remote
Installing/history/row/finalization/release producers are separate missing work.
No cold reconstruction or untouched A→N return is provided by this batch.

The source selectors `native_registered_fifth_remote_transfer_` use the actual
original fifth, real target metadata provider, authenticated source frame and
runtime-owned freeze. They require actual unique N→A transfer, actual callback
Arc refusal plus fresh retry, cancellation before rotation and actual original
hook ABA after initial preflight. They assert target native/raw/row/UID bytes
remain unchanged and retain exact outcomes. They have not run. These tests
exercise ownership, not physical movement or fault-safe durable Installing.

The next producer must retain the native attempted xid/bytes before WAL, publish
and read back the exact protected proposal then catalogue Installing refusal,
and reconcile uncertainty without constructing another NoDomain. Every row step
needs actual source/history admission and independently fresh request authority.
A populated Assigned target remains outside this Registered-only lane: first
Serving plus real ACK/full Strong must precede the same target's second-range
acceptance. Nothing here qualifies the original Azure failure modes or sustained
four-to-five-node throughput.
