# BicDB 1.0.511-beta candidate

This source candidate shares full raw relation materializations within one
native invariant-validation pass when the transaction already uses Serializable
isolation and the pass borrows the same database's actual exclusive admission.
All roots, original transaction overlays, tenant/publication checks and
expressions remain evaluated. Read-committed and forced-global RC paths retain
fresh scans; startup catalogue admission is unchanged.

Memo retention uses the smaller of16MiB and the inherited positive memory
budget. Oversized relations or combined retained bodies fall back to complete
uncached scans, preserving original deadlines and memory failures. These are
cooperative estimates, not hard RSS reservations.

Issuing a raw `PagedRecords` writer now permanently disables sharing for that
actual open. The hidden unstable `paged_records_handle` getter uses nonblocking
shared admission and returns `None` while exclusive admission is busy, as well
as for a database without paged storage. It records issuance before any Arc
escapes. This avoids reentrant-hook deadlock and does not revoke existing raw
handles. An escaped lower Store Arc retains its physical writer-directory lock.

Ten source controls cover raw-row/overlay semantics, memory/deadline fallback,
early and concurrent raw capability issuance, actual guard identity, writer
lifetime across reopen, and a bounded child exercising real reentrant admission.
The corrected f32 source executed all ten controls successfully before this
port. That historical component result does not validate the current combined
head: current-main 507 HA changes and source version 509 require their own
required CI and original Node application acceptance. Source review and
formatting do not establish measured speedup.
