# 1.0.546: temporal keys and foreign keys, window row order

Checked against stock PostgreSQL 18.4 with the PostgreSQL regression suite and
the temporal-key and window tests.

## Added

- **Temporal keys**: `PRIMARY KEY` / `UNIQUE (..., p WITHOUT OVERLAPS)` on a range
  or multirange column, in CREATE TABLE and ALTER TABLE ADD CONSTRAINT, enforced
  as PostgreSQL does (equality on the leading columns, `&&` on the period, 23P01),
  with an empty period rejected (23514) and PostgreSQL's definition errors. They
  show in `pg_constraint` and `information_schema` as PRIMARY KEY / UNIQUE.
  Forms the DDL path does not take still fail with 0A000.
- **Temporal foreign keys**: `FOREIGN KEY (..., PERIOD p) REFERENCES t (..., PERIOD q)`:
  the referencing period must be covered by the referenced rows' periods. Child
  and parent writes, ALTER TABLE ADD/DROP CONSTRAINT, DROP TABLE and TRUNCATE
  behave as for other foreign keys. ON UPDATE/DELETE actions other than NO ACTION
  and DEFERRABLE are 0A000. They are not yet listed in `pg_constraint`.

## Changed

- **Window query rows come out in their window's sort order** when every window
  function shares one window, as PostgreSQL's WindowAgg returns them.
