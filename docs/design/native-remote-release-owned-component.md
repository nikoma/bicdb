# Recipient-owned remote release component (source only)

This separate source unit starts at commit
`3b4756b67ac93f6f4e2c6eaf77558d01cb7c0605`. It implements a finite
same-open release/arm continuation after actual remote Open. It does not
implement Serving policy, final metadata publication, an automatic relocation
controller, slot garbage collection, process restart or cold reconstruction.
It has not been compiled or run. Format parsing is not compilation.

## Actual authority and ownership

The actual TLS caller collects opaque `AuthenticatedNativeRemoteServingFrame`
objects from ALL final NEW recipients. Each frame must describe the original
native decision, preparation, bridge and catalogue Open from the same manifest,
phase, member/incarnation and original observer. The existing compact fact and
request lifetime bounds remain in force. A separate post-ALL HostMQ context and
attached current native MStore point precede each local effect. The original
server token, mutation Role and OWN also remain live; the collection does not
renew any of them. Decoded replies never construct a local quorum.

Before any original reference drain, the serialized real host retains
`NativeRemoteReleaseOwner` and registers Weak protected Open/Released routes to
that SAME successor. Successor publication is itself a one-way memory effect.
An error preserves the successor and all remaining original references; it is
not reset into new work. Its private custody transitions are:

1. SAME original completed preparation custody Arc;
2. SAME returned custody/evidence Arc if an actual reader prevents `try_unwrap`;
3. owned original evidence, still holding its actual lease;
4. private consumed lease-free history plus the original Registered release
   state or survivor runtime, each retaining its original activation/lease.

The history consumes the actual producer objects. A preparation vote, digest,
DTO, `None` slot or count alone cannot create it. The redundant preparation
lease is dropped only after the real Registered owner has transferred its
original freeze to existing release state, or the same survivor runtime has
been verified. The existing unique-Frozen checks and actual drop/arm sinks
remain in force. Original local quorum constructors and method signatures
remain available; their authority is separate from the new private remote
admission backing.

Original OLD observations and the donor source certificate retain other
Frozen references. `retire_finite_remote_open_references` is an explicit
production actor step on each actual original host. It obtains its OWN fresh
self-observer HostMQ/MStore after genuine ALL Open and invokes only the exact
existing original-source and participant retirement producers. OLD outside NEW
retains its CLOSED runtime/cleanup owner; it does not acquire a NEW continuation
or native release Role. Readonly RPC handlers perform no retirement effects.
There is no automatic scheduler for this step in this unit.

## Current reads, partial effects and errors

Protected Open and Released observations use the actual retained successor
owner and `NativeJointHistoricalCutScope`, with current private known native
D/CURRENT/archive/provenance/status, original process/DB/Store, healthy current
catalogue and selected activation. This remains usable after original slots
are retired, without reviving their Frozen getters. A dropped but unarmed
owner can be observed as Open DATA; it cannot count as Released.

Full physical/domain validation occurs outside final metadata version guards
and remains borrowed through them. Final guard checks use original process,
request/Role/OWN/MStore memory lifetimes and current catalogue IO generation;
they do not canonicalize paths or hash the domain. Each actual release helper
return is retained before outer postchecks. Outer API returns have separate
bounded attribution (count/hash chain, first original error prefix/full hash).
Those histories do not grant authority or establish successful release.

`ReconcileRelease` is a distinct mutating operation. Only the same retained
actor/operation/manifest/phase/decision and actual successor can reconcile the
original unknown, under a new actual ALL Open and fresh local authority. It
reuses the same partially transferred/drop state and original activation; it
never replays native preparation/bridge/WAL or creates another freeze. Queue
uncertainty is cleared only inside a protected current released/armed
observation, with the original error history retained. Readonly observations
never clear it. A native or catalogue IO Unknown from earlier stages remains
blocked by their unchanged APIs.

## Defined acceptance controls, not executed results

Three normal-host tests use the existing five-host-object same-process TCP/TLS
fixture and actual retained coordinator/host actors:

- `native_first_actual_all_open_retirement_and_unique_release_component`:
  actual ALL preparation/bridge/Open, finite original-host retirement,
  protected Open after drains, actual unique release, ALL protected Released,
  unchanged native XID/LSN/CURRENT/archive and no writer installed.
- `native_first_actual_release_refuses_missing_real_open_before_successor`:
  the real Registered target Open is not called; authenticated release must
  refuse at its protected missing-activation read before successor publication
  or drop uncertainty, with native storage unchanged.
- `native_first_actual_registered_drop_cancel_retains_owner_then_reconciles`:
  the original server token is cancelled by a selected test callback after the
  real Registered Frozen drop and before arm. The control requires positive
  original server/Role/OWN windows, actual retained dropped owner/error/unknown,
  readonly Released refusal, then same-operation fresh reconciliation with no
  new native transaction/freeze. The original error remains attributed.

The existing FIRST test bodies and original windows/assertions are preserved.
The controls explicitly require their real prerequisites; setup refusal is not
a passing skip. RAII requests owner-worker stop before scoped joins on every
failure/panic. Kernel calls and scoped joins are not forcibly preemptible.
No test definition or successful untouched-range tail proves selected-range
SDK ACK/Strong behavior, independent-process/VM operation or physical RPO zero.

## Compatibility and remaining delivery gates

The new wire operation may be refused by older peers. Rolling upgrades are not
qualified. This unit introduces no new persistent record semantics or format
feature flag; the private consumed-history and partial-release state are RAM
owners and cannot be reconstructed by decoding files. Process loss remains a
cold-recovery blocker. Release does not imply Serving.

The next real producer must consume actual ALL Released and the same retained
native owners, then install policy after the original RPC has returned, with
fresh purpose-specific metadata/Role/OWN/MStore and actual listener drain.
Nonleader final voters require the separately scoped legal self-origin path.
Selected-range SDK ACK/full Strong acceptance, final conditional metadata,
automatic controller, permanent OLD loss, target-intent association on cold
bootstrap, cleanup and all supported-platform execution remain outstanding.
The independently documented bootstrap cross-call association risk is not
resolved by this release component.
