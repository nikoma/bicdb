# 1.0.533: PostgreSQL function calls, planner settings, SIMILAR TO

Part of the PostgreSQL SQL-parity work, checked against stock PostgreSQL 18.4
with `fixtures/postgres-compat/pgsql-parity/functions-misc.cases` (60 cases,
identical output).

## Added

- **Function calls as PostgreSQL resolves them**: named arguments (`=>` and
  `:=`), mixed positional and named arguments with defaults, OUT/INOUT
  parameters returning a record (`(f(1)).c`, `SELECT * FROM f(1)`,
  `RETURNS TABLE`), and VARIADIC parameters including `VARIADIC ARRAY[...]`.
- **Planner and resource settings** such as `work_mem`,
  `maintenance_work_mem`, `effective_cache_size`, the cost settings and the
  `enable_*` switches, with PostgreSQL's value normalisation and errors
  (22023). Durability settings such as `synchronous_commit` are still refused.
- **`SIMILAR TO`** (with ESCAPE) and `substring(x SIMILAR p ESCAPE e)`.
- **`pg_notify()`**.

## Fixed

- Multi-dimensional array subscripts and slices have the element or array type
  PostgreSQL gives them, including on the wire.
- `COMMENT ON TABLE/COLUMN` is stored and returned by `obj_description`,
  `col_description` and `pg_description`.
- `has_table_privilege` on catalog relations matches PostgreSQL, and the
  two-argument form answers for `current_user`.
- `ts_headline` resolves all its overloads by argument type.

## Changed

- `NOTIFY` inside a transaction block is delivered at commit and dropped on
  rollback, and identical notifications in one transaction are delivered once,
  as in PostgreSQL. Before, notifications were delivered immediately.
