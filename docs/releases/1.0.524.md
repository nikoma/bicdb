# 1.0.524: first crates.io release

1.0.522-beta is reserved by a parallel candidate and is not used here.

## Install from crates.io

BicDB is prepared for publication on crates.io. Once the crates are uploaded:

```sh
cargo install bicdb --locked
bicdb --version
```

This compiles the default CLI from source. It needs Rust 1.96 or newer and the
native build prerequisites listed in the README (on Ubuntu: `build-essential`,
`pkg-config`, `libssl-dev`, `clang`, `libclang-dev`, `cmake`). `--locked` uses
the dependency versions BicDB was tested with. `cargo install bicdb --locked
--features bench` adds the developer `bench` and `compat` commands, as the
`bench` feature always has.

## Package rename: `bicdb-cli` is now `bicdb`

The package that builds the `bicdb` binary is renamed from `bicdb-cli` to
`bicdb`, so the crates.io name is the program name. The directory stays
`crates/bicdb-cli`; the binary name, its commands and its features (`bench`,
`bench-comparison-engines`) are unchanged.

Replace `-p bicdb-cli` with `-p bicdb` in Cargo commands, for example
`cargo build --locked --release -p bicdb`. `cargo build --bin bicdb` works for
both old and new checkouts. CI, scripts and current documentation are updated;
historical records keep the commands that were actually run.

`bicdb` and the 26 `bicdb-*` crates it needs are published together at the
same version. The internal crates exist so that `cargo install bicdb` works:
they say so in their description, and their APIs carry no compatibility

`bicdb-bench` is published because `bicdb`'s optional `bench` feature depends
on it; it is not built by default. `bicdb-wasm`, `bicdb-app-host` and the
extension examples are marked `publish = false`.

Each published crate carries `description`, `authors`, `repository`,
`homepage` and `license = "Apache-2.0"` from the workspace, and an `include`
list that ships what is needed to build it: `src/`, `build.rs` and `proto/`
(gRPC provider), `assets/` (SQL stopword lists), `Cargo.toml`, `LICENSE`,
`NOTICE` and `THIRD_PARTY_NOTICES.md`, plus `README.md` for `bicdb`. Integration
test suites, fixtures, examples and evidence stay in the repository.
`scripts/validate-licensing.sh` now also fails when a published crate's
`include` list would drop a legal file.

## Version scheme: stable numbers

Versions drop the `-beta` suffix from this release on: `1.0.524`, then
`1.0.525` and so on. `scripts/bump-version.py` accepts the stable form and
treats the `bicdb` package as a release package. Because a stable number is not
a unique string, a bump now refuses to rewrite any manifest value other than a
BicDB package version or a requirement on a BicDB package. The documented
[current limitations](../../README.md#current-limitations) still apply.

## Not changed

No code, dependency or runtime behaviour changes. No crate is published, and
no binary, release or deployment is produced by this source version.
