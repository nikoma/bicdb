# BicDB 1.0.65-beta

Release date: 2026-08-04

## Live-cluster certification preflight

- Replaces topology-only production certification planning with a fail-closed
  live-cluster preflight.
- Requires `server_paged` storage, exactly five live active data/metadata
  voters, five distinct server failure domains, RF3 voting replicas for every
  range, bounded placement skew, and no unavailable or under-replicated range.
- Rejects active, failed, pending, or unplaceable relocation and rebalance
  work before a campaign begins.
- Requires one active schema fingerprint across all five nodes and binds it to
  the immutable plan.
- Requires a stable metadata leader, a nonzero term, a fully committed log,
  no metadata learners, and an exact five-voter set at the topology generation
  being certified.
- Binds the storage mode, distribution-configuration SHA-256, local identity,
  node incarnations, metadata proof, health metrics, replica bytes, and
  pending-work counts into certification format v8.
- Requires the effective-configuration and topology-before raw payload digests
  to match the exact configuration and topology frozen by the preflight; a
  self-consistently rehashed substitute still fails offline verification.
- Rejects future or stale heartbeat state and local configuration/topology
  identity drift.
- Rejects dirty source trees before creating a collector checkpoint rather
  than waiting until final verification.
- Adds adversarial coverage for resident-memory storage, stale nodes,
  under-replication, schema divergence, uncommitted metadata, missing server
  failure-domain placement, forged health metrics, and dirty source state.

The physical 1 TB, 5 TB, and 20 TB five-server campaigns remain required.
