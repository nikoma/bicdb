# Event requests: in-flight replies, caller envelopes and cleanup

This source batch combines PR182's in-flight listening with SDK505's typed error retention. It is an unqualified source candidate: formatting and source preservation checks do not establish that it compiles or that any new regression passes.

An append or scan keeps at most five actual RPC workers. The half-remaining-budget slice still determines when discovery and the next attempt can start, and bounds TCP connect. Once dispatched, a worker may listen only until the original request deadline. That deadline is also capped by the tightest active caller query-scope deadline. The namespace, key/value, range routing policy, retry count and backoff schedule are preserved. Blocking hostname resolution and synchronous user evidence callbacks retain their existing limitations; scoped joining does not make those operations forcibly deadline bounded.

`QueryBudgetContext` carries process-local numeric envelopes and shared peak counters. Each worker installs its own non-Send guard. All nested limits and deadlines remain in force; observations update the original caller's peak as well as the worker's local view. Scope guards never cross threads, and the context conveys no database or distributed authority. This preserves cooperative peak accounting; it is not a new global allocator or memory reservation protocol.

Each worker reports its actual typed result and completion time. The coordinator retains all completed results until sibling cleanup, without copying successful payloads. A response must have the expected operation variant before it can count as an ACK. A typed `CommitOutcomeUnknown` or dispatched `RpcEvidenceFailure` survives later refusal, discovery/fence and deadline errors. Failure selection happens after cleanup so a late sibling's uncertainty is not discarded. A fully validated same-operation ACK may resolve earlier commit uncertainty. Even then, an actual sibling evidence fence refuses the current request, retaining the original fence detail; it cannot be hidden behind the cached ACK. The caller envelope and evidence fence are checked again before returning success. Transport completion time and API-return time are different observations; neither moves the deadline.

Same-sink callback reentry is checked on the caller thread before a new worker can escape the existing thread-local callback guard. Pre-dispatch refusal remains definitely undispatched. A reentry triggered by a post-dispatch parent observation retains that parent's may-have-dispatched status. Different sinks and legitimate parallel callbacks remain allowed. No callback I/O is performed under a new global lock.

The original SDK8352 six error regressions and six retry tests, PR182's two timing/discovery tests, and the identical two caller-query tests are preserved. The paired historical test-only sources remain immutable: PR182 child560d8a failed the expired-caller case by returning success after one TCP APP frame; synchronous505 child8ec100 passed by returning `QueryTimedOut` with zero connections/frames. That evidence does not qualify this changed runtime.

New controls cover inherited nested deadlines and shared peaks, expiry during an actual mock reply, worker-observed memory-limit refusal before I/O, out-of-order typed unknown/refusal results, wrong-operation response rejection, all sibling outcomes through cleanup, an actual observer callback failure after another TCP exchange's ACK, and pre/post-dispatch same-sink reentry plus a different-sink control. The typed channel tests are component tests; the TCP tests use mock replies and callback errors, not native database commits or actual filesystem sync failures. None is physical HA, scale-out, production or deployment evidence. The separate original first-APP68 failure is not causally explained by the older56f occurrence or by this source batch.
