# BicDB 1.0.336-beta

This release makes Carrier scalar SQL preserve PostgreSQL `NULL` results so
Cell applications observe the same behavior as Carrier's PostgreSQL Node
runtime.

## PostgreSQL-compatible application behavior

- Preserve a `NULL` returned by a signed `sql.scalar_as` statement, including
  `NULLIF(...)` and nullable `CASE` expressions.
- Keep strict signed nullability enforcement for structured `sql.one_as` and
  `sql.list_as` result rows.
- Fix the WalkNorth EHR prescription workflow, where omitted optional allergy
  review and prescription notes correctly produce a PostgreSQL `NULL` value.

## Validation

- Added an application-runtime regression proving a synthetic Carrier scalar
  result accepts PostgreSQL `NULL`.
- Added the inverse regression proving structured non-null result contracts
  still reject `NULL`.
- Reproduced the EHR prescription request against PostgreSQL 18.4 (HTTP 200)
  and BicDB 1.0.335-beta (HTTP 400) before the fix.
