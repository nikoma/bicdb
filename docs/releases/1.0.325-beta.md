# BicDB 1.0.325-beta

Phase 8 ships the industry-neutral hardened-fleet admission-evidence boundary.
The Cell/Application software roadmap is now implemented through Phase 8;
regulated production-data admission remains closed.

## Shipped

- Added `bicdb-cell-admission`, a deterministic, bounded, database-free
  verifier for the exact twelve production-admission gates.
- Bound evidence to the exact Cell, manifest, binary, guest image,
  application/schema set, security profile, isolation profile, and deployment
  isolation tier.
- Added disjoint threshold `EvidenceReviewer`, `DeploymentAttestor`,
  `TransparencyWitness`, and `AdmissionAuthority` trust domains, with a minimum
  threshold of two and no key-material reuse between roles.
- Added failure-free and skip-free test summaries, immutable artifact and
  provenance commitments, the exact six independent-review disciplines, and
  strict evidence lifetime bounds.
- Added short-lived deployment attestation covering workload identity, KMS
  scope, capability graph, storage mounts, network policy, crash-dump policy,
  observability policy, verifier identity, and activation nonce.
- Added a signed hash-chain evidence checkpoint and a separate short-lived
  activation authorization that commits the exact canonical evidence set.
- Integrated the manifest-pinned policy and evidence bundle into
  `CellRuntime::open` before Cell-key release, plus the dedicated and general
  Cell CLIs and `BICDB_RUNTIME_MODE=cell` environment launcher.
- Added positive integration coverage and adversarial tests for missing or
  duplicated gates, stale evidence, tampering, role substitution, unilateral
  thresholds, cross-build substitution, untrusted attestation, non-canonical
  documents, and mismatched deployment tiers.

## Deliberate limits

This release provides the verification and enforcement boundary, not invented
external assurance. It contains no claim that penetration testing,
cryptographic/privacy/platform review, production confidential-compute
attestation, or a production admission-root ceremony has occurred.
`REGULATED_ADMISSION_ENABLED` and `regulated_data_admitted` therefore remain
`false` even for a complete bundle.

See [the Phase 8 operator contract](../cell-runtime-phase8.md).
