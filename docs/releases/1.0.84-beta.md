# BicDB 1.0.84-beta

## Compact WAL recovery outcomes

- Replaces recovery's per-transaction `BTreeMap` nodes with a sorted, exactly
  9-byte terminal-outcome encoding.
- Sorts and deduplicates terminal decisions in place, keeps logarithmic lookup
  during the second WAL pass, and transfers the same allocation into live MVCC
  state after recovery.
- Fails closed when one transaction has contradictory commit and abort records.
- Reclaims the compact prefix as the frozen transaction watermark advances.
- Adds terminal-record and peak-outcome-allocation fields to recovery snapshots,
  fixed-cardinality metrics, benchmark v3 JSON/CSV, and human-readable reports.
- Quantizes benchmark evidence durations to microsecond precision before
  checksumming so JSON round trips cannot spuriously invalidate an artifact.
- Adds focused tests for 20,000 reverse-ordered decisions, visibility, compact
  element size, deduplication, conflict detection, and post-recovery freezing.

## Explicit boundary

This is a material memory reduction, not a claim of constant-memory recovery.
A transaction that prevents the frozen watermark from advancing can still
retain a suffix-sized outcome vector. Durable abort exceptions or disk-backed
outcome spill remains follow-up work, and the production recovery certification
gate remains open until the documented hardware matrix passes.
