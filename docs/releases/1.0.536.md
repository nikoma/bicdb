# 1.0.536: bounded recursive CTEs, faster nested EXISTS

## Fixed

- **An infinite `WITH RECURSIVE` could take the server down.** A recursive CTE
  that never terminates grew until the process was killed for running out of
  memory.
  - When the outer query is `SELECT * FROM cte LIMIT n [OFFSET m]`, the
    recursion now stops once it has n + m rows, as PostgreSQL's incremental
    work table does.
  - Every recursive CTE is charged to the statement's memory budget and capped
    by `BICDB_MAX_CTE_MATERIALIZED_BYTES` (default 512 MiB, `0` disables).
    Past the cap the statement fails with 53200 "out of memory" and a DETAIL
    naming the CTE; the server keeps running.
- **Nested EXISTS with outer-only conditions ran for minutes.** A condition
  inside EXISTS that uses no column of the inner relation and calls no
  function is now evaluated once per outer row, as PostgreSQL does, instead of
  once per inner row. Subqueries with an aggregate projection are unchanged.
