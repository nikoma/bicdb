# Closed handoff image admission: source audit

Read-only audit of `c68da3231e050911f6a12d21fa61a9e796df3169` (full prototype, source `1.0.489-beta`). No implementation, build, engine open, or new executed result accompanies this document. The executed no-reinstall baseline fails at the image writer check before the global joint decision; the design below is a missing producer contract, not an existing capability or a recovery qualification.

## Exact current boundary

`distribution_range_image_install.rs::clear_step` and `install_step` construct `NativeHistoryTargetContext`, call `BicDb::native_image_row_scope`, then acquire Controlled mutation. In `db/range_image_native/history_stage.rs:1820`, the row-scope constructor validates the actual staged proof and then calls `require_installed_native_writer_database_for_range(context.fence.range())`. The fence range is the committed PendingE2 capture descriptor. `NativeImageTransactionGrant::require_current` repeats that installed-writer check at the actual transaction boundary (`history_stage.rs:1779`). Changing only the first check cannot make a correct transaction succeed.

`HostWriterPolicyFacts::require_range` (`distribution_native_writer.rs:247`) compares its recorded canonical range exactly. Its canonicalization already filters learners and ignores approximate metrics; it **retains epoch**, so PendingE2 still differs from original C1. `NativeWriterHostState::require_database` also checks actual hook/coordinator/open/birth/schema/registry/health. The ordinary predicate must remain unchanged. Generic imports on born2 remain refused; the existing image-only grant reaches `certified_prefix.rs::require_native_transaction_mutation_scope` through `require_enforced_transaction_preflight`'s bypass branch, never by claiming ordinary native Prepare/Commit authority.

There is an existing exact predecessor proof: `NativeJointHandoffPlan::require_old_native_configuration` (`joint/plan.rs:103`) removes only the committed target learner, subtracts the one allocation epoch, and compares **actual old native lineage**, full voter credentials, cluster/bootstrap/schema/restore. This is not permission to decrement any caller's epoch or to accept a metadata declaration as native history.

The native safety digest shown above does not explicitly commit the protected abort-slot inventory. Admission may check inventory integrity; that is different from proving each existing command/promise/outcome compatible with the chosen source spine. A new image admission must include actual protected slot/promise coverage and preserve their domains, or explicitly refuse unsupported nonempty cases. Do not assert that raw CQ/Pending coverage proves all NoData obligations. `abort_history/slot_journal.rs::native_abort_slot_inventory` is an actual record reader, not an adoption/compatibility authority.

## Smallest closed-purpose contract

Add a private image-only eligibility producer consumed by the existing row scope and its transaction grant. This is **proposed**, not a named existing API. It must admit only the actual `CommittedHandoff` source/role pair, matching the same original OLD cut, exact current Pending plan/target and staged source history, without requiring the future global joint decision. Requiring that later decision would recreate the image-before-decision cycle.

Two distinct eligibility cases are necessary:

- **Existing C1 writer:** retain and recheck the actual original writer object/registration/coordinator/Store/root/open. Validate its full policy against the exact actual OLD predecessor proved above, while the separate fresh CommittedHandoff role validates PendingE2. This authorizes only closed image rows under the real target intent/Frozen; it neither refreshes nor reinstalls policy and cannot satisfy ordinary PendingE2 APP/Strong checks. A real hook replacement must invalidate the saved operation.
- **New Registered receiver:** consume actual same-open Registered metadata ownership, current bound birth/incarnation/pins/schema/restore/namespaces and StoreUUID, together with fresh own current metadata and the actual target CommittedHandoff role/OLD cut. Require the exact planned learner, actual born-enforced/native-catalogue custody, complete target obligations and absence of an unauthorized ordinary-writer installation. A missing hook or empty counters alone is not a receiver capability. Never adopt an arbitrary existing catalogue, recreate genesis, initialize a blank voter, or overwrite a prior policy.

The second producer is **missing**. The lower owned-metadata observation exists, but `NativeUnassignedLearnerFactory::require_owned_metadata_member`, `registered_context` and the fresh factory context deliberately reject **any data assignment**. Registered continuation additionally checks the original no-business state. They must stay strict. A separate retained receiver lifecycle/context must accept only the genuine committed learner assignment and preserve the same service, DB, native-catalogue owner and protected MStore UUID. It cannot reuse `NativeInitialDataHost`: that path requires planned INITIAL ranges/genesis, while a fresh fifth factory has `initial_ranges=[]`. After one legitimate image changes local B, subsequent range images need this retained receiver context; rechecking blank/unwritten factory state or making another genesis would be wrong.

At row-scope construction, keep the full existing target/fence/staged-proof/source checks before acquiring Controlled mutation. Bind the eligibility to exact actual source/session/nonce/attempt/intent/marker, target DB/Store/birth/schema/namespace IDs, original role/parent cancellation and real Frozen ownership. At transaction authorization/commit, keep actual transaction ID, complete mutation hash, authorized range and live mutation claim; recheck the retained writer-or-receiver identity and original cancellation/deadline. A caller-supplied bool, purpose DTO, current MQ alone or unchecked override is insufficient.

Account for the installer's **own** native-image invalidations: `NativeHistoryTargetContext` intentionally rechecks immutable base/prefix/Pending lower bounds separately from its own changing generations. The new boundary must bind the exact actual Installing marker and expected stage, not demand an obsolete source-ready grant after clear and not ignore a foreign schema/hook/namespace change. On commit ambiguity retain intent/stage/freeze custody; an error is not rollback. Cursor advancement remains after successful existing validation. Global decision, NEW QQ, native activation, finalization, writer publication and serving-generation release remain distinct later producers.

## Local, cold and wire gaps

The current APIs are local: installer `begin` takes an actual DB Arc, mutable `RangeWriteStore`, native admission, borrowed source authorization, real install role and owned freeze. `RangeImageCapture`, `CompletedNativeRangeImageSource` and actual OLD observations own local DB/service/pin objects. `ClusterDataRequest` has generic snapshot/catch-up operations, but no equivalent authenticated native capture/session/history-stage/clear/finalize kernel protocol. Generic snapshot DTOs or the serializable native steps/seal cannot recreate those opaque inputs. Remote image work needs a separate bounded authenticated source-session/kernel producer binding the original caller/pins/request/deadline and actual target identity, with retained ownership and retry semantics; sending a local Arc or promoting a decoded seal is not an implementation.

Cold reopen cannot reuse DB-open-bound row grants or staged proofs. The existing protected-proposal/Installing resume machinery is purpose-specific to CurrentVoterRepair; it must not be relabeled CommittedHandoff. Protected local old-close records and persisted intent/header hashes are historical facts, not a fresh OLD quorum/source session. All-owner CommittedHandoff reissue, original-source death/replacement, changed leader/membership and cross-process session recovery remain unqualified until their real producers and crash-cut tests exist. No old-root capability retrofit or old-reader compatibility is implied.

## First actual tests, without fixture writer reinstall

1. Extend the retained-original-policy baseline through real clear/copy/audit/finalization using actual OLD closure and fresh Pending role. Assert original writer object/registration/protected policy bytes unchanged and ordinary APP/Strong still unavailable while closed. The first closed-image pass is not a full handoff pass; retain any later actual missing producer instead of reinstalling policy to reach ACK.
2. Real four-host metadata/RF3 plus a genuinely registered fifth factory: real birth RPC/enrollment, same-owned MStore catch-up and committed data-learner assignment; then actual OLD QQ/image under the separate receiver producer, with **no INITIAL writer**. No manufactured receiver proof or fresh factory after assignment. A second range image must preserve the first range's actual rows/history/UIDs and retain the same owners/StoreUUID.
3. Genuine negatives: fresh Normal/wrong committed plan/session/nonce, expired original caller, actual foreign birth/open/StoreUUID, live original-writer replacement, recreated namespace, source owner/pin loss, higher or conflicting CQ/Pending/certificate/sparse obligation, and unsupported protected slot/promise/outcome. Require refusal before clear/WAL where applicable and preserve all irreversible maps. Exercise cancellation and publication uncertainty at actual mutation boundaries, not DTO shape tests.

The required endpoint remains the real fifth target's complete native image/NEW quorum/decision, proof-authorized writer/open transition, next native-coordinator ACK and full Strong value on every new data voter, then multi-range and crash/failover recovery. Closed image admission alone does not satisfy that objective or qualify remote/operator HA.
