# BicDB 1.0.85-beta

## Durable abort exceptions

- The frozen-transaction watermark no longer stops forever at an aborted
  transaction. Freezing records aborted — and crash-orphaned, terminal-
  record-less — transactions as durable abort exceptions in a bounded
  meta-page region and advances past them.
- Aborted transactions keep reading as aborted after the watermark passes
  them, so their rows never become retroactively visible once their abort
  records are truncated with the WAL.
- Checkpoint truncation is no longer pinned by a single abort: the exception
  region is flushed with the meta page before the checkpoint record that
  permits WAL reset, and the open path restores exceptions before installing
  recovered outcomes.
- Recovery now runs an open-time freeze: nothing is in flight at open, so
  every representable outcome collapses into the watermark immediately. A
  retained suffix left by a since-ended blocker no longer stays wholly
  resident.
- Corrupt or out-of-sequence exception regions fail the open as classified
  meta corruption instead of being guessed at.

## Observability

- Recovery reports gain `frozen_outcomes_at_open` and
  `abort_exceptions_at_open`; store snapshots gain the frozen/next
  watermarks, resident transaction entries, abort-exception count, and
  meta-page exception capacity; checkpoint step reports gain
  `abort_exceptions_recorded` and `freeze_exception_capacity_full`.
- New fixed-cardinality metrics and Prometheus series:
  `paged_transaction_frozen_xid`, `paged_transaction_next_xid`,
  `paged_transaction_resident_entries`, `paged_abort_exceptions`,
  `paged_abort_exception_capacity`,
  `paged_recovery_frozen_outcomes_at_open`,
  `paged_recovery_abort_exceptions_at_open`, and the cumulative
  `paged_checkpoint_abort_exceptions_recorded_total`.
- Benchmark evidence format advances to version 4 with the two new recovery
  columns; the verifier fails artifacts whose retained exceptions exceed the
  page size's durable capacity or whose open-time freeze left any of a fully
  closed fixture's outcomes unabsorbed. The CLI evidence test now binds the
  format version to the exported constant instead of a hardcoded value.

## Explicit boundary

This closes the checkpoint-blocking-abort case named by 1.0.84-beta and makes
recovery memory independent of suffix length in every case the meta-page
exception region can represent. It is still not a constant-memory claim: a
live long-running transaction pins the watermark until it ends, outcomes above
it remain suffix-sized, and exception capacity overflow degrades freezing to
the pre-1.0.85-beta stop behavior (reported, not hidden). A disk-backed
transaction-status spill remains the follow-up for that residual case, and the
production recovery certification gate remains open until the documented
hardware matrix passes.
