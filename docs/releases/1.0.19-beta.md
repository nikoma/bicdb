# BicDB 1.0.19-beta

Release date: 2026-08-03

## Resumable cluster-backup lifecycle

- Adds `ClusterBackupRun`, a durable state machine covering range fencing,
  selected-node capture, certification, release, completion, and abort.
- Records progress as bounded, length-authenticated SHA-256 journal frames.
  Recovery truncates only an incomplete final frame and rejects damage to any
  complete frame.
- Retains compact ordered-range and journal-offset arrays rather than every
  decoded quorum, with explicit batch, event-memory, and journal-disk limits.
- Atomically publishes a newly initialized run directory and uses an exclusive
  OS lock to prevent concurrent coordinators from advancing one run.
- Checkpoints each range immediately, derives archive nodes from the exact
  durable leader-inclusive quorums, and validates every certificate barrier
  against its original write fence.
- Stops remote fence installation at the first exact leader-inclusive quorum,
  avoiding unnecessary write barriers and node archives on healthy replicas.
- Persists success or abort before releasing fences and journals releases in
  deterministic order. Remote release is required to be idempotent, so a crash
  between the effect and checkpoint safely resumes without reopening writes at
  an uncertified cut.
- Rejects symlink substitution for plans, manifests, journals, lock files,
  artifact directories, node artifacts, and certificates.
