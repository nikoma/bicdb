# BicDB 1.0.316-beta

This release adds the first callable, industry-agnostic application-serving
path inside the fail-closed BicDB Cell runtime. It remains a preview and does
not admit clinical PHI or other regulated production workloads.

## Cell-native application host

- `CellRuntime` can verify and activate exact signed ABI-v2 application
  packages pinned by application root, name, version, artifact digest, cell
  scope, and schema generation.
- Application release trust is independent of CellManifest activation trust.
  A package signer cannot authorize its own deployment, and a manifest signer
  cannot make an untrusted package valid.
- Release, OIDC identity, and egress policies are exact-byte digest pins in the
  signed CellManifest and are verified before the database opens.
- `CellApplicationHost` deliberately exposes readiness and authenticated HTTP
  serving only. It does not expose the database handle or package lifecycle
  mutation methods.
- Public package routes are rejected, and every declared authentication scheme
  must be OIDC Ed25519 with the issuer and audience pinned by the cell identity
  policy.
- The monotonic active-manifest state is persisted only after package staging,
  activation, and readiness succeed; a failed activation cannot falsely become
  the cell's active release.
- The reduced runtime constructs no pgwire listener, database selector,
  cluster manager, general installer, or cross-cell handle.

## Fail-closed providers and listener

- New deny-only blob and egress providers ensure a cell never receives an
  ambient filesystem or network capability merely to satisfy an application
  host interface.
- Cleartext cell HTTP is loopback-only. Non-loopback serving requires a TLS
  certificate/key pair, and `--check` cannot accidentally start a listener.
- Both `bicdb-cell serve` and `bicdb cell serve` accept the policy/TLS flags.
  `BICDB_RUNTIME_MODE=cell` accepts equivalent `BICDB_CELL_*` environment
  paths while retaining the same typed construction path.

## Validation

- A generic signed conformance application activates inside one cell and
  serves only through its authenticated host.
- Negative tests cover release-key/manifest-key separation, mismatched package
  trust, public routes, identity-policy mismatch, failed activation state,
  artifact identity, wrong volume/key/runtime identity, manifest rollback,
  deny-only providers, and listener/TLS admission.
- The LAN mesh convergence regression now waits for both replicated data and
  the worker's durable completed-session bookkeeping; a 30-run stress check
  covers the former CI-only race.
- The non-admitted profile rejects `phi` and `phi_local` data classes instead
  of merely reporting that admission remains closed after opening.
- The fixture is deliberately generic; BicDB contains no EHR schema or
  healthcare workflow.
- Core transaction conflict detection now carries the exact mutation version
  seen by a point read into a later write. A raised read-your-writes snapshot
  can no longer hide a lower commit that applied after the read and cause a
  lost update; deterministic and concurrent balance-conservation gates cover
  the fix. Blind direct writes retain their established snapshot-isolation
  semantics, preserving stale-writer rejection, concurrent disjoint-row work,
  and back-to-back upserts without reopening the point-read lost-update window.
- A WAL-encoding failure now completes its unused reserved sequence in the
  applied watermark, so one rejected commit cannot permanently hide every
  later successful commit.
- Metadata-consensus failover validation follows the current elected authority
  after a restarted former leader triggers another legitimate election,
  instead of pinning the first replacement forever.
- The quorum-elected metadata controller can now drive a committed relocation
  even when another node owns the source range. That authority is limited to
  the exact consensus topology generation and exact relocation/range state;
  forged state, stale leaders, and ordinary authenticated members remain
  rejected. Empty bootstrap nodes no longer publish their empty schema as
  cluster authority before the source schema is installed and certified.
- Browser/device sync now exposes explicit collection authorization and
  authenticated peer-key pinning through the WASM and JavaScript APIs. Sync
  remains fail-closed for unknown, unprovisioned, protected, or unpinned
  endpoints; the conformance tests no longer depend on unsafe legacy mesh
  defaults.
- Packed full-text positional reads now have a bounded portable fallback for
  WASI, restoring a successful `wasm32-wasip1` build of the browser runtime.

## Migration semantics

Schema-changing releases still carry one migration definition, not one
hand-maintained migration per tenant. Each isolated cell must execute that
transition against its own storage. This preview performs exact local package
activation during cell startup; cohort rollout, durable activation receipts,
lazy dormant-cell convergence, and fleet rollback remain Phase-4 work and are
not claimed by this release.

## Admission remains closed

`clinical_phi_admitted` remains false. Attested cell-scoped KMS release,
complete durable/transient encryption, external anti-rollback state,
independent process/microVM isolation, threshold release authorization, fleet
activation, cell-scoped HA, device/cross-cell protocols, and independent
regulated-workload certification remain required.

See [`cell-application-host-preview.md`](../cell-application-host-preview.md)
for the exact operator contract.
