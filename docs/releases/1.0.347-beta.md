# BicDB 1.0.347-beta

This release hardens paged-store recovery and transaction-status spill reclamation after a production restart exposed two crash-lifecycle defects.

## Changes

- Restore the observed first LSN of a nonempty active WAL during recovery. A reopened store can no longer rotate that file under the name of an existing sealed segment and later fail checkpoint cleanup with a missing-segment error.
- Track status-spill retirement by page ID and physical page generation. A delayed cleanup can no longer free a new owner after the same page ID has been reused.
- Make duplicate and already-staged status-spill cleanup idempotent without weakening the existing durable-descriptor fence.
- Reject repeated page IDs while loading a persisted status-spill chain, including repeated empty pages that value-range validation alone cannot detect.
