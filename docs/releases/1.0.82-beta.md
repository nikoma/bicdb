# BicDB 1.0.82-beta

## Clean-process WAL recovery certification

This release adds `bicdb bench paged-recovery`, a repeatable evidence harness
for the bounded server-paged startup path introduced in 1.0.81-beta.

The benchmark:

- creates only a new database path and refuses to overwrite an existing path;
- independently sizes checkpointed logical row data and the post-checkpoint WAL
  suffix, so total-database and suffix scaling can be distinguished;
- performs recovery in a fresh child process rather than charging fixture-build
  allocator memory to startup;
- samples RSS before, during, and after recovery;
- records open time and the strict engine recovery report;
- verifies selected checkpointed rows and recovered suffix rows;
- requires exactly two WAL scans, exact suffix-byte accounting, and the hard
  one-record scanner ceiling;
- emits a versioned JSON or CSV certification artifact; and
- exits unsuccessfully when operator-declared recovery-time, peak-RSS, or
  RSS-growth limits are exceeded. Declared RSS limits fail closed on platforms
  where RSS cannot be measured.

The default benchmark uses physical durability. `--fsync false` remains
available for algorithmic smoke tests but is explicitly excluded from
production certification.

## Verification

- Library tests build checkpointed and post-checkpoint data, recover it, verify
  both generations, validate the two-pass/record-buffer invariants, and prove a
  zero memory ceiling fails the report.
- CLI integration tests exercise the actual clean child process, JSON evidence,
  limit handling, and refusal to reuse an existing target directory.
- A documented 64 MiB development smoke matrix ran with zero and 64 MiB of
  checkpointed logical data. It validates the harness but is not represented as
  the still-required production-hardware certification matrix.
