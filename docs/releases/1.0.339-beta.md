# BicDB 1.0.339-beta

This release restores PostgreSQL-compatible `NULL` behavior for Carrier
resource filters over sparse rows created by signed SQL.

## PostgreSQL-compatible application behavior

- Treat an omitted nullable field and an explicitly stored JSON `null` as the
  same value when Carrier resource filters model `IS NULL` / `IS NOT NULL`.
- Keep active soft-delete scopes from hiding rows inserted by SQL statements
  that omit the nullable deletion timestamp.
- Apply the same semantics to policy-filtered lists and full-text-search list
  post-filtering.

## Validation

- Reproduced the issue with the WalkNorth EHR `PractitionerProfile`: direct
  lookup returned the row, while the default active list returned zero rows
  and the deleted scope returned the active practitioner.
- Confirmed PostgreSQL 18.4 materializes the omitted nullable column as SQL
  `NULL`, making the row visible in the active scope.
- Added application-runtime regressions for missing, explicit-null, and
  non-null values across both resource filtering paths.
